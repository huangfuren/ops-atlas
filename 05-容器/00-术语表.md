# 00 术语表

> **这一文档回答**：某个词是什么意思、两个长得像的概念差在哪、「只知道现象、不知道该翻哪一册」时往哪走。  
> **怎么用**：三种查法——按名字（下面按册分组）、按英文或缩写（缩写速查）、按现象（症状反查）。  
> **只有一句话**：要原理和命令回对应册；这里只保证你「认得出、分得清、找得到」。

## 000 容器全貌

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 容器 | container | 被namespace和cgroup框起来的**一个进程**，带独立的根文件系统视图 |
| 镜像 | image | 容器的只读模板，分层存储。镜像跑起来才是容器 |
| 容器 vs 虚机 | container vs VM | 虚机虚拟整台机器带内核，容器共享宿主内核只隔离进程——所以秒级启动、密度高 |
| Docker | Docker | 最流行的容器引擎。日常说「docker 跑个容器」的 docker 就是它 |
| containerd | containerd | 从 Docker 拆出来的底层运行时，K8s 通过 CRI 直接用它；Docker 本身也建立在它上面 |
| runc | runc | 真正创建容器进程的那一小步：按 OCI 规范把 namespace 和 cgroup 配好再 exec |
| OCI | Open Container Initiative | 镜像与运行时的开放标准。有 OCI 标志的镜像到处能跑 |
| CRI | Container Runtime Interface | K8s 对容器运行时的统一接口。dockershim 移除后，K8s 直连 containerd |
| Kubernetes（K8s） | Kubernetes | 容器编排系统：一组机器上的容器由它统一调度、自愈、扩缩 |
| 编排 | orchestration | 多机容器的调度、自愈、伸缩、发现的统称。单机用 Docker，多机就要编排 |
| 控制平面 / 数据平面 | control plane / data plane | K8s 里「做决定的组件」（API/scheduler/controller）与「干活的组件」（kubelet/容器） |
| 云上托管 K8s | managed K8s | ACK / EKS / TKE：控制平面云厂商管，你只管节点和负载。版本升级节奏与自建不同 |

## 001 镜像与容器

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 分层 | layer | 镜像由多层只读层叠成，层可被多个镜像共享——拉取快、磁盘省的原因 |
| 写时复制 | copy-on-write, COW | 容器写文件先把层里的文件拷到可写层再改。改得多 I/O 放大就明显 |
| overlay2 | overlay2 | Docker 默认的联合文件系统驱动：把多层目录叠成一个根 |
| 可写层 | writable layer | 容器启动时在最上面挂的薄薄一层，`docker rm` 后就没了——数据进卷的原因 |
| 生命周期 | lifecycle | created → running → paused → stopped → deleted。每一步对应一条 docker 命令 |
| 前台 / 后台 | foreground / detached | `-d` 让容器在后台跑。**容器默认跟前台进程共存亡** |
| 端口发布 | port publishing | `-p 8080:80` 把宿主端口转发到容器端口。映射关系 `docker ps` 可见 |
| 环境变量注入 | environment | `-e KEY=value` 传配置进容器。十二要素应用的标准配置方式 |
| Entrypoint / CMD | — | 容器的启动命令。ENTRYPOINT 定「程序本体」，CMD 给「默认参数」，`docker run` 后面的词覆盖 CMD |
| exec 形式 | exec form | `["nginx","-g","daemon off;"]`——直接 exec，不走 shell，**信号能送达**。PID 1 问题的根源在 shell 形式 |
| PID 1 | — | 容器里的 1 号进程就是启动命令本身。它不转发信号、不收尸，是「stop 卡 10 秒」「僵尸进程」的根源 |
| 重启策略 | restart policy | `no / on-failure / always / unless-stopped`。开机自启靠 `--restart unless-stopped` 或 systemd |

## 002 Dockerfile 与镜像构建

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| Dockerfile | Dockerfile | 构建镜像的配方文件。`docker build` 逐行执行并生成层 |
| FROM | — | 基础镜像。选 alpine 瘦、选 distroless 安全、选 slim 折中 |
| RUN | — | 构建时执行命令并生成一层。**多个命令用 `&&` 连一条写，少一层** |
| COPY / ADD | — | 拷文件进镜像。COPY 语义清晰；ADD 额外会解压、拉 URL，**能用 COPY 就别用 ADD** |
| ENV / ARG | — | ENV 留在镜像里运行时可用；ARG 只在构建期有效 |
| EXPOSE / -p | — | EXPOSE 只是声明文档；真正发布端口靠 `run -p` |
| 构建缓存 | build cache | 每条指令一层，输入没变就复用缓存。**把不常变的指令写前面**是提速的全部秘密 |
| 多阶段构建 | multi-stage build | 第一阶段用大镜像编译，第二阶段只拷产物进干净小镜像。构建工具不进最终镜像 |
| .dockerignore | — | 构建上下文的排除清单。不配它，`.git` 和 node_modules 全部发进构建 |
| latest 标签 | — | 漂移的标签：今天和明天的 `latest` 不是同一个镜像。**生产永远用明确版本 tag** |
| 镜像扫描 | image scanning | 扫镜像里的 CVE。Trivy / Harbor 内置扫描都做这件事 |

## 003 数据卷与持久化

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 卷 | volume | Docker 管理的持久化存储，`/var/lib/docker/volumes/` 下。删容器卷还在 |
| 绑定挂载 | bind mount | 把宿主任意目录直接映射进容器。开发挂代码、配置挂文件都靠它 |
| tmpfs | tmpfs | 挂在内存里的临时卷，容器停就消失。放敏感临时数据 |
| 具名卷 / 匿名卷 | named / anonymous | 有名字的卷可复用可备份；匿名卷随容器删除易堆积垃圾 |
| 只读挂载 | read-only, `:ro` | 容器内只读。配置文件挂载的标准姿势 |
| 备份卷 | volume backup | `docker run --rm -v 卷:/data -v $PWD:/backup alpine tar ...` 一条命令导出 |

## 004 Compose 与日常运维

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| Compose | Docker Compose | 一个 YAML 描述一组容器，`up -d` 一条命令起全套。单机编排的事实标准 |
| service | service | compose 文件里的一个服务定义，对应一个（或一组）容器 |
| `depends_on` | — | 声明启动顺序。**只管启动顺序，不管「就绪」**——数据库没 ready 应用照样先起 |
| 容器日志 | container logs | `docker logs` 看 stdout/stderr。**容器里别自己写文件日志**，打 stdout 才统一 |
| 日志轮转 | log rotation | json-file 驱动的 `max-size` / `max-file`。不配它，容器日志能把磁盘写满 |
| 资源限制 | resource limits | `--memory` / `--cpus`。超内存的部分进程被 OOM kill |
| 磁盘清理 | prune | `docker system prune` 清悬空镜像、停容器、无用网络与卷——**加 `-a` 连没用镜像全删，先看清再敲** |
| 悬空镜像 | dangling image | 没有标签被引用的旧层，`<none>:<none>`，清理的第一目标 |

## 005 K8s 架构与核心对象

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 集群 | cluster | 一组节点由 K8s 统一管理。至少一个控制平面节点 + 若干工作节点 |
| kube-apiserver | — | 集群唯一入口：所有读写（包括 kubectl）都进它。挂了集群变只读都做不了 |
| etcd | etcd | 集群的数据库，存全部对象状态。**备份 etcd = 备份整个集群** |
| kube-scheduler | — | 决定新 Pod 落在哪个节点。它只「绑定」，真正拉起容器的是 kubelet |
| controller-manager | — | 一堆控制器的集合：盯着期望状态，不断把现实掰向期望 |
| kubelet | — | 每个节点上的管家：按 apiserver 的指令拉起/重启本节点容器 |
| Pod | Pod | 最小调度单位：一或多个紧耦合容器共享网络与存储。**直接建裸 Pod 没人管死活** |
| ReplicaSet | ReplicaSet | 保证 Pod 副本数符合期望。一般不直接用，由 Deployment 代管 |
| Deployment | Deployment | 管应用的版本与副本：声明 replicas、镜像、滚动策略。改镜像 = 触发滚动更新 |
| 期望状态 | desired state | YAML 里写的样子。K8s 的全部逻辑就是「现实向期望状态收敛」 |
| 声明式 | declarative | 你说「要三个副本」，不说「执行哪些命令」。与脚本式运维的本质区别 |
| Label / Selector | — | 贴在对象上的键值对。Service 找 Pod、Deployment 管 Pod 全靠 selector 匹配 |
| Namespace | namespace | 集群内的逻辑分组（dev/prod、按团队）。资源配额与 RBAC 的边界 |
| kubectl | kubectl | 命令行客户端。`get/describe/logs/exec/apply/delete` 覆盖 90% 日常 |

## 006 K8s 网络

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| Service | Service | 一组 Pod 的稳定访问入口：IP 和 DNS 名不变，后面 Pod 随便换 |
| ClusterIP | — | 默认类型：集群内部才能访问的虚拟 IP |
| NodePort | — | 在每个节点开一个端口（默认 30000-32767）对外。测试用，生产走 Ingress/LB |
| LoadBalancer | — | 云厂商的 LB 接到 Service 前面。云上对外服务的标准姿势 |
| Endpoints / EndpointSlice | — | Service 背后真实的 Pod IP 列表。**Service 不通先看它是不是空的** |
| kube-proxy | — | 每个节点上把 Service 规则写成 iptables/IPVS 的组件 |
| CoreDNS | CoreDNS | 集群内 DNS：`服务名.命名空间.svc.cluster.local` 解析成 ClusterIP |
| Ingress | Ingress | 七层路由规则：按域名/路径把外部流量转到不同 Service |
| Ingress Controller | — | 真正执行 Ingress 规则的组件（nginx-ingress / Traefik）。**只建 Ingress 没装 Controller 等于没配** |
| CNI | Container Network Interface | 给 Pod 配网络插件的接口。Calico / Flannel / Cilium 都是实现 |

## 007 K8s 存储与配置

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| ConfigMap | ConfigMap | 非敏感配置的注入载体：环境变量或挂成文件。改它要重启（或热加载）才生效 |
| Secret | Secret | 敏感配置，base64 编码（非加密）。RBAC 要管住「谁能读」 |
| emptyDir | emptyDir | 与 Pod 同生共死的临时目录。缓存用，Pod 重建即清空 |
| hostPath | hostPath | 直接挂节点目录。**调度到别的节点数据就不在**，排障用，别当存储用 |
| PV / PVC | PersistentVolume / Claim | 集群里的存储资源与使用申请。Pod 声明 PVC，管理员或 StorageClass 供 PV |
| StorageClass | StorageClass | 存储的「模板」：PVC 一申请，动态创建对应的 PV。云盘/NFS 各配一个类 |
| 回收策略 | reclaimPolicy | PV 释放后 `Retain` 留着还是 `Delete` 删掉。**数据盘必须想清楚这一条** |

## 008 K8s 发布与资源管理

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 滚动更新 | rolling update | 新旧 Pod 交替替换，服务不断。maxSurge / maxUnavailable 控制节奏 |
| 回滚 | rollback | `kubectl rollout undo` 回到上一个 ReplicaSet 版本。**前提是历史没被改崩** |
| 探针 | probe | liveness 挂了重启容器；readiness 没绪摘出 Service；startup 给慢启动留宽限 |
| requests / limits | — | 申请量（调度依据）与上限（用量封顶）。**不设 requests 的 Pod 调度是盲的** |
| QoS 等级 | Quality of Service | Guaranteed / Burstable / BestEffort。节点资源紧张时按这个顺序反向驱逐 |
| HPA | Horizontal Pod Autoscaler | 按指标自动加减副本。常见按 CPU利用率，需装 metrics-server |
| 驱逐 | eviction | 节点资源紧张时按 QoS 优先级清 Pod。BestEffort 最先被赶走 |
| cordon / drain | — | 维护节点：cordon 停止新调度，drain 连已有 Pod 一起迁走 |

## 009 K8s 排障与生产实践

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 事件 | events | `kubectl describe` 末尾和 `get events` 里的时间线。**排障第一现场** |
| CrashLoopBackOff | — | 容器反复崩溃退避重启。`logs --previous` 看上一次死前说了什么 |
| OOMKilled | — | 内存超 limits 被杀，退出码 137。加 limits 或查泄漏 |
| Pending | — | 调度不下去：资源不足 / 亲和性不满足 / PVC 绑不上，`describe` 看原因 |
| ImagePullBackOff | — | 镜像拉不下来：tag 写错 / 私库没配 secret / 网络不通 |
| 排障三板斧 | — | `describe`（事件与状态）→ `logs`（应用输出）→ `exec`（进去看）。覆盖 80% 现场 |
| etcd 备份 | etcd backup | `etcdctl snapshot save` 定期做并演练恢复。**集群级灾难的唯一后悔药** |
| 版本升级 | cluster upgrade | kubeadm 一次升一个小版本：先控制平面再节点，先测试集群再生产 |

## 缩写速查

读报错、看 YAML 时按字母找。

| 缩写 | 全称 | 意思与出处 |
| --- | --- | --- |
| CNI | Container Network Interface | Pod 网络插件接口（006） |
| CRI | Container Runtime Interface | K8s 对容器运行时的接口，对接 containerd（000） |
| CSI | Container Storage Interface | 存储插件接口（007） |
| CRUD | Create / Read / Update / Delete | 增删改查（泛用） |
| HPA | Horizontal Pod Autoscaler | 水平自动扩缩（008） |
| K8s | Kubernetes | 容器编排系统（全册） |
| LB | Load Balancer | 负载均衡（006） |
| OOM | Out Of Memory | 内存耗尽被杀，K8s 里表现为 OOMKilled / 137（008 / 009） |
| OCI | Open Container Initiative | 镜像与运行时开放标准（000） |
| PVC / PV | PersistentVolumeClaim / PersistentVolume | 存储申请 / 存储资源（007） |
| QoS | Quality of Service | Guaranteed / Burstable / BestEffort 三档（008） |
| RBAC | Role-Based Access Control | 基于角色的权限控制（生产实践） |
| SC | StorageClass | 存储类，动态供给 PV 的模板（007） |
| VPA | Vertical Pod Autoscaler | 纵向（改 requests/limits）自动扩缩，与 HPA 相对（008 注记） |

## 最容易混的 16 对

| 容易混 | 一句话差别 | 怎么确认 | 册 |
| --- | --- | --- | --- |
| 镜像 vs 容器 | 只读模板 / 跑起来的进程 | `docker images` vs `docker ps` | 001 |
| CMD vs ENTRYPOINT | 默认参数 / 程序本体 | `docker run img arg` 覆盖的是 CMD | 001 / 002 |
| COPY vs ADD | 纯拷贝 / 还会解压与拉 URL | 能用 COPY 就用 COPY | 002 |
| volume vs bind mount | Docker 管理的卷 / 宿主任意目录 | `docker volume ls` 看得到的是前者 | 003 |
| compose `depends_on` vs 就绪 | 只管启动顺序 / 不管服务可用 | 应用连不上库，多半是没等就绪 | 004 |
| Pod vs Deployment | 裸 Pod 没人管死活 / Deployment 自愈与滚动 | 被 `kubectl delete pod` 后没重建的就是裸 Pod | 005 |
| Deployment vs ReplicaSet | 管版本滚动 / 只管副本数 | `rollout history` 记录在 Deployment 上 | 005 / 008 |
| Service vs Ingress | 四层稳定入口 / 七层路由规则 | 按域名路径分流的是 Ingress | 006 |
| ClusterIP vs NodePort vs LoadBalancer | 仅集群内 / 节点端口 / 云 LB | 对外访问选后两者或 Ingress | 006 |
| ConfigMap vs Secret | 普通配置 / 敏感配置 | 值都是 base64，区别在权限与用途 | 007 |
| emptyDir vs hostPath | Pod 生命周期 / 节点目录 | 调度换节点后还在的是 hostPath | 007 |
| PV vs PVC | 存储资源 / 使用申请 | Pod 只认 PVC | 007 |
| requests vs limits | 调度申请量 / 运行上限 | `describe node` 看 allocation，OOM 看 limits | 008 |
| liveness vs readiness | 失败重启容器 / 失败摘出流量 | 重启次数涨看 liveness，流量进不来看 readiness | 008 |
| 滚动 vs 蓝绿 | 逐步替换一套资源 / 两套环境整切 | 回滚方式不同：undo vs 切回旧版 | 008 / CICD 007 |
| cordon vs drain | 拒绝新调度 / 连存量一起迁走 | 维护节点用 drain | 009 |

## 按症状反查

| 现象 | 大概是 | 去哪 |
| --- | --- | --- |
| 容器起完立刻退出 | 启动命令不是前台进程 / 配置错误秒退 | 001 §1.6 / §1.7 |
| `docker stop` 卡 10 秒才停 | PID 1 不转发信号（shell 形式启动） | 001 §1.7 |
| 容器里改的文件重启就没了 | 写进了可写层，数据没进卷 | 001 / 003 |
| 构建一次十几分钟 | 缓存被前面易变指令打断 / 没配 .dockerignore | 002 |
| 镜像 1GB+ 瘦不下来 | 没多阶段构建 / 用了全量基础镜像 | 002 |
| 磁盘被 Docker 吃满 | 容器日志没轮转 + 悬空镜像堆积 | 004 |
| compose 起了但应用连不上数据库 | depends_on 只管顺序，没等就绪 | 004 |
| Pod 一直 Pending | 资源不足 / 亲和性 / PVC 绑不上 | 009 |
| ImagePullBackOff | tag 错 / 私库 secret 缺 / 加速器不通 | 009 |
| CrashLoopBackOff | 应用崩溃，看 `logs --previous` | 009 |
| Pod 反复重启，exit 137 | OOMKilled，超了 limits | 008 / 009 |
| Service 访问不通 | Endpoints 为空 / label 不匹配 / 探针没绪 | 006 |
| Ingress 域名 404 | 规则路径不匹配 / Controller 没装 | 006 |
| 改了 ConfigMap 应用没变化 | 挂载的文件有同步延迟 / 应用不热加载，要滚动 | 007 |
| 节点 NotReady，Pod 大量驱逐 | kubelet/容器运行时挂了或资源耗尽 | 009 |
| 想维护节点不中断服务 | cordon + drain，确认 PodDisruptionBudget | 009 |
