# 网络运维手册

> **定位**：按运维视角编排的网络文档。从「包能不能到」到「慢在哪」再到「都查不动了怎么拆」，九篇对应九类真实任务。  
> **读者**：会配 IP、但连不通时不知道先看哪一层的运维人员，也用于自查与复习。  
> **口径**：命令以 **Linux `iproute2`**（`ip` / `ss` / `nstat`）为主，不用已废弃的 `ifconfig` / `route`；协议语义与厂商无关，云、容器、虚拟化环境的差异在 007 / 008 单独讲。

> **001 与 002 的分界**：001 管「包到不到」（三层以下），002 管「连接建不建得起来」（传输层）。ping 不通回 001，ping 通但端口不通回 002。  
> **应用侧慢不归网络**：先按 009 的四要素拆（带宽/时延/丢包/抖动），拆不出网络证据就转应用与数据库侧。

## 阅读约定

1. **命令以 iproute2 为准**：`ip` / `ss` / `nstat`，不用已废弃的 `ifconfig` / `route` / `netstat`。
2. **协议语义与厂商无关**：讲 TCP、TLS 按 RFC 语义讲；云厂商控制台操作只在 007 / 008 提差异，不给截图式步骤。
3. **给输出**：能给出命令输出的都给，读者靠输出判断自己对不对。
4. **每一层只给一条命令**：排查按层走，每层一条命令、一个判据，通过才往下（009 §9.1）。
5. **先取数再动手**：改路由、改防火墙之前先抓包、先记录，回滚路径写在改动旁边。
6. **每篇结构统一**：范围与口径 → 正文（每节解决一个小问题）→ 命令与坑 → 排查顺序 / 故障剧本。可以顺序读，也可以只查某一节。
