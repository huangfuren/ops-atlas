# 00 术语表

> **这一文档回答**：某个词是什么意思、两个长得像的概念差在哪、「只知道现象、不知道该翻哪一篇」时往哪走。  
> **怎么用**：三种查法——按名字（下面按篇分组）、按英文或缩写（缩写速查）、按现象（症状反查）。  
> **只有一句话**：要原理和命令回对应篇；这里只保证你「认得出、分得清、找得到」。

## 001 IP、路由与二层

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 五层模型 | layered model | 物理链路、IP、端口到应用的提问顺序。排查时**自下而上逐层过**，不是背名词 |
| IP 地址 | IP address | 主机在网络里的逻辑地址。同网段通信靠 MAC，跨网段靠 IP + 网关 |
| 子网掩码 / CIDR | netmask / CIDR | 判断目标在不在同一网段。`/24` 就是 `255.255.255.0` |
| 网关 | gateway | 目标不在同网段时的下一跳。配错了就是「同网段通、外网不通」 |
| 路由表 | routing table | 「去哪个网段走哪个口」。`ip route` 看的就是它 |
| 直连路由 | connected route | 网卡配了 IP 自动生成的路由，优先级最高，视同本地 |
| 默认路由 | default route | `0.0.0.0/0`，谁都不匹配时走它。没有它就出不了网段 |
| MAC 地址 | MAC address | 网卡的物理地址，二层转发依据。**跨网段后帧的源/目的 MAC 每一跳都重写，IP 不变** |
| ARP | Address Resolution Protocol | IP 到 MAC 的翻译。`ip neigh` 看到的缓存表；同网段不通先查它 |
| VLAN | Virtual LAN | 交换机上隔离广播域。不同 VLAN 二层不通，必须过三层 |
| 广播域 | broadcast domain | ARP 广播能到达的范围。VLAN 的意义就是把大广播域切小 |
| ICMP | Internet Control Message Protocol | ping 用的控制报文。ping 不通只说明 ICMP 不通，不代表服务不通 |

## 002 TCP 与连接状态

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 端口 | port | 同一 IP 上区分服务的编号，`0~65535`。**端口不是连接，四元组才是** |
| 四元组 | 4-tuple | 源 IP、源端口、目的 IP、目的端口。一条 TCP 连接的唯一标识 |
| TCP | Transmission Control Protocol | 可靠、有序、面向连接。运维排障的绝对主角 |
| UDP | User Datagram Protocol | 无连接尽力而为。DNS、QUIC、视频流用它 |
| SYN / ACK / FIN / RST | — | 建连、应答、正常关闭、异常复位。抓包先认这四个标志位 |
| 三次握手 | 3-way handshake | SYN → SYN+ACK → ACK。第二次没回来是网络，第三次没回来多是队列满 |
| 四次挥手 | 4-way teardown | 两个 FIN 两个 ACK。主动关的一方最后进 TIME_WAIT |
| 半连接 / 全连接队列 | SYN / accept queue | 收到 SYN 还没握完的排一队，握完等应用 `accept` 的排一队。打满的表象完全不同（002 §2.8） |
| 十一种状态 | TCP states | `LISTEN` 到 `TIME_WAIT` 的状态机。`ss` 列里每个字母都有含义 |
| TIME_WAIT | — | 主动关闭方停留约 2MSL。**是正常现象**，堆积到端口耗尽才是问题 |
| CLOSE_WAIT | — | 被动关闭方收到 FIN 后等应用调 `close`。**大量堆积就是应用代码的锅** |
| keepalive | TCP keepalive | 空闲连接的保活探测。应用层心跳与它不是一回事 |
| QUIC | QUIC | 基于 UDP 的可靠传输，HTTP/3 的底座，握手 0-RTT |

## 003 DNS 与域名解析

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| DNS | Domain Name System | 域名到 IP 的分布式查询系统。**「能上 QQ 打不开网页」先怀疑它** |
| 递归查询 | recursive query | 客户端问本地 DNS：你给我最终答案。客户端只发一次请求 |
| 迭代查询 | iterative query | 本地 DNS 逐级问根、顶级、权威：你告诉我下一步问谁 |
| 权威 DNS | authoritative server | 存着域名记录正本的服务器。改解析就是改它上面的记录 |
| A / AAAA 记录 | A / AAAA record | 域名指向 IPv4 / IPv6 地址 |
| CNAME | Canonical Name | 域名指向**另一个域名**。接 CDN 就是把 CNAME 指到厂商 |
| MX / TXT / PTR | — | 邮件路由 / 文本验证（SPF 等）/ IP 反查域名 |
| NS 记录 | Name Server record | 这个域名交给哪些 DNS 服务器解析。换 DNS 服务商改的就是它 |
| TTL | Time To Live | 记录允许缓存多少秒。**改解析后「不生效」就是在等旧 TTL 过期** |
| hosts | /etc/hosts | 本机手动解析，优先于 DNS。排障时先确认没被它劫持 |
| CDN | Content Delivery Network | 把内容分发到边缘节点。接入后排查对象变成「边缘节点到源站」两段 |

## 004 HTTP

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| HTTP | HyperText Transfer Protocol | 应用层请求-响应协议。运维看的是报文和行为，不是开发用的框架 |
| 报文结构 | message format | 请求行/状态行、头部、空行、正文。`curl -v` 看到的就是这个 |
| 方法与语义 | methods | GET 取、POST 交、PUT 替、DELETE 删。**GET 带 body、POST 做删除都算违例** |
| 幂等 | idempotent | 同一请求发多次效果相同。GET/PUT/DELETE 幂等，POST 不幂等——重试策略靠它定 |
| 状态码 | status codes | 2xx 成功、3xx 重定向、4xx 客户端错、5xx 服务端错。**502/504 是运维信号弹** |
| 重定向 | 3xx redirect | 301 永久（浏览器会缓存）、302 临时。改错了用户被带进沟里 |
| 长连接 | keep-alive | 一条 TCP 连接跑多个请求，省握手。HTTP/1.1 默认开 |
| 队头阻塞 | head-of-line blocking | 长连接里前一个请求慢，后面的都得等。HTTP/2 多路复用缓解、HTTP/3 彻底解决 |
| 强缓存 | strong cache | 浏览器直接用本地副本，**不发请求**。`Cache-Control` 控制 |
| 协商缓存 | negotiated cache | 问服务器「我这份还能用吗」，没变回 304。`ETag` / `Last-Modified` 控制 |
| 压缩 | compression | gzip/br 减小传输体积。双侧都支持才生效，抓包看 `Content-Encoding` |

## 005 HTTPS 与 TLS 证书

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| TLS | Transport Layer Security | HTTP 之下的加密层。SSL 是它的旧名 |
| 对称 / 非对称加密 | symmetric / asymmetric | 一把钥匙快 / 两把钥匙安全但慢。**TLS 用非对称交换密钥，之后全走对称** |
| 握手 | TLS handshake | 验证书、商量出会话密钥。握手慢=每次建连都贵，所以有会话复用 |
| 证书 | certificate | 绑定「域名 ↔ 公钥」并经 CA 签名的文件。浏览器信任的是签名链不是文件本身 |
| 证书链 | certificate chain | 服务器证书 → 中间 CA → 根 CA。**缺中间证书是最常见的部署翻车** |
| CA | Certificate Authority | 签发证书的机构。系统信任的根证书列表里没有它，浏览器就报警 |
| SAN | Subject Alternative Name | 证书覆盖的域名清单。一张证书多个域名靠它 |
| SNI | Server Name Indication | 握手时告诉服务器要访问哪个域名，同一 IP 托多证书的前提 |
| mTLS | mutual TLS | 双向认证：客户端也出示证书。服务间调用的强认证 |
| TLS 终止 | TLS termination | 在 LB / Nginx 解密，后端走明文。**排障时先确认自己在终止点的哪一侧** |
| 自签名证书 | self-signed | 自己给自己签名。内部服务可用，客户端要手动信任 |

## 006 负载均衡与高可用

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 负载均衡 | load balancing | 把流量分到多台后端。单点是可用性天敌，这是第一道防线 |
| 四层 / 七层 | L4 / L7 | 改写 IP 端口转发，不解应用 / 解析 HTTP 按内容转发。性能与灵活性的取舍 |
| LVS | Linux Virtual Server | 内核态四层 LB。三种转发模式对应三种网络形态 |
| DS / RS | Director / Real Server | LVS 里的调度器 / 后端真实服务器 |
| VIP / RIP | Virtual / Real IP | 对外服务的浮动地址 / 后端机器的真实地址 |
| NAT / DR / TUN 模式 | — | 回包经调度器改源地址 / RS 直接回客户端只进不出 / IP 隧道可跨网段（006 §6.3） |
| 调度算法 | scheduling | 轮询、加权轮询、最小连接、源地址哈希。**后端性能不齐必须加权** |
| Keepalived | Keepalived | VRRP + 健康检查的高可用套件，给 LB 自己做主备 |
| VRRP | Virtual Router Redundancy Protocol | 多台机器虚拟成一个路由器，主挂了备顶上，靠优先级选举 |
| 脑裂 | split-brain | 主备失联后都认为自己是主，VIP 出现两份。靠仲裁线路或 fence 预防 |
| 健康检查 | health check | 定期探测后端，坏的摘除。检查路径要选真实业务路径，别只探 TCP 通 |
| 会话保持 | session persistence | 同一客户端固定打到同一后端。源地址哈希或 cookie 插入，**破坏均匀性** |
| 反向代理 | reverse proxy | 替后端接请求的网关（Nginx/HAProxy）。七层能力：改头、限流、缓存 |

## 007 NAT、防火墙与访问控制

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| NAT | Network Address Translation | 私网地址与公网地址之间的转换 |
| SNAT / DNAT | Source / Destination NAT | 改源地址（内网上网）/ 改目的地址（对外发布映射） |
| MASQUERADE | — | SNAT 的动态版：出口 IP 不固定时用，`-j MASQUERADE` |
| conntrack | connection tracking | 内核记录的连接状态表。**NAT 和状态防火墙的地基，表满了新连接全断** |
| 四表 | filter / nat / mangle / raw | iptables 规则按功能分四张表，filter 与 nat 最常用 |
| 五链 | PREROUTING / INPUT / FORWARD / OUTPUT / POSTROUTING | 包流经的五个检查点。**先入哪链、后入哪链决定了规则顺序** |
| 规则顺序 | rule order | 自上而下第一条命中即生效。加了规则不生效，八成是被前面的规则截胡 |
| 状态检测 | stateful inspection | 按连接状态放行：`ESTABLISHED,RELATED` 一条顶无数条 |
| 安全组 | security group | 云上实例级防火墙，**有状态**：出方向放行的回包自动进 |
| 网络 ACL | Network ACL | 云上子网级防火墙，**无状态**：进和出要各配一遍 |

## 008 容器、云与企业网络

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| veth pair | virtual ethernet pair | 一对虚拟网线，从容器里穿到宿主机。容器网络的「网线」 |
| 网桥 | bridge | 二层交换机。Docker 默认网桥叫 `docker0` |
| 容器 NAT 网络 | container NAT | 容器拿私网 IP，出网靠宿主机 MASQUERADE。**外面主动进不来**，要端口映射 |
| Overlay / Underlay | — | 叠在三层网上的虚拟网 / 底下真实的三层网。跨主机容器流量走 Overlay |
| VXLAN | Virtual eXtensible LAN | 把二层帧包进 UDP 的隧道。**头部开销 50 字节，MTU 要相应调小** |
| CNI | Container Network Interface | K8s 的网络插件接口。Calico / Flannel / Cilium 都是实现 |
| Service（K8s） | kubernetes service | 一组 Pod 的稳定虚拟 IP。访问不通先看 kube-proxy 模式与 Endpoint |
| VPC | Virtual Private Cloud | 云上的私网。子网、路由表、对等连接都在它里面配 |
| VMnet | virtual network | VMware 的虚拟交换机。桥接 = 独立 IP 进局域网；NAT = 借宿主机出门；仅主机 = 与宿主私有网 |
| AD 域 | Active Directory | Windows 的统一账号体系。域控（DC）兼做 DNS，**办公网一半的「网络问题」是域 DNS** |

## 009 排障、抓包与性能

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 分层排查 | layered troubleshooting | 链路 → 地址 → 路由 → 端口 → 应用。顺序本身就是方法（009 §9.1） |
| tcpdump | tcpdump | 命令行抓包。**抓包点选错（抓错网卡/抓在 NAT 前）会得出相反结论** |
| BPF 过滤器 | Berkeley Packet Filter | `tcpdump` 的过滤语法：`host`、`port`、`tcp[tcpflags]`。不过滤全抓等于没抓 |
| 性能四要素 | — | 带宽、时延、丢包、抖动。说「网络慢」必须拆成这四项（009 §9.4） |
| 带宽 / 吞吐 | bandwidth / throughput | 管道多宽 / 实际跑了多少。吞吐低不一定带宽不够 |
| 时延 / RTT | latency / round-trip time | 单程耗时 / 往返耗时。`ping` 和 `ss -tin` 都能看 |
| 丢包与重传 | loss / retransmission | 包在路上没了重发。重传率高，时延和吞吐一起恶化 |
| 抖动 | jitter | 时延忽大忽小。平均值正常但用户抱怨「时快时慢」就是它 |
| MTU | Maximum Transmission Unit | 单包上限，默认 1500。隧道叠加要逐层扣减 |
| PMTUD | Path MTU Discovery | 探测路径最小 MTU。**ICMP 被拦就黑洞：大包不通小包通** |

## 最容易混的 18 对

网络的困惑多半是成对的。这张表只回答「差别在哪、怎么一眼确认」。

| 容易混 | 一句话差别 | 怎么确认 | 篇 |
| --- | --- | --- | --- |
| 交换机 vs 路由器 | 二层按 MAC 转发 / 三层按路由转发 | `ip neigh` vs `ip route` | 001 |
| 同网段 vs 跨网段 | 直接 ARP / 交网关且每跳重写帧 | 抓包看目的 MAC 是对端还是网关 | 001 |
| TCP vs UDP | 可靠有序有连接 / 尽力而为无连接 | `ss` 里 TCP 有状态可查，UDP 几乎是裸的 | 002 |
| 端口 vs 四元组 | 门牌号 / 一条连接的唯一标识 | `ss -tnp` 同端口多连接并存就是靠四元组 | 002 |
| 半连接队列 vs 全连接队列 | SYN 收了没握完 / 握完了等 accept | 攻击表象是无状态堆积 vs `Recv-Q` 涨 | 002 §2.8 |
| TIME_WAIT vs CLOSE_WAIT | 主动关方的正常停留 / 被动方等应用 close | 多在客户端=正常；多在服务端=代码没关连接 | 002 §2.6 |
| 递归 vs 迭代 | 客户端要最终答案 / DNS 之间逐级问 | `dig +trace` 看迭代全程 | 003 |
| CNAME vs A 记录 | 指向另一个域名 / 直接指向 IP | `dig` 输出里 answer 是域名还是地址 | 003 |
| 强缓存 vs 协商缓存 | 本地直接用不发请求 / 问一句 304 | DevTools 里 `(from disk cache)` vs `304` | 004 |
| 301 vs 302 | 永久，浏览器缓存 / 临时，每次都问 | 换回原地址还跳=301 被缓存了 | 004 |
| 502 vs 504 | 上游连不上或回得非法 / 上游超时 | 上游日志里「拒绝连接」vs「无响应」 | 004 / 006 |
| 四层 vs 七层 LB | 只看 IP 端口 / 能看 HTTP 内容 | 能按 URL 转发就是七层 | 006 |
| LVS NAT vs DR | 回包经 DS 改写 / RS 直接回客户端 | RS 上 `tcpdump` 有没有客户端源 IP | 006 §6.3 |
| SNAT vs DNAT | 改源（内网出门）/ 改目的（对外发布） | 抓包看被改的是哪个字段 | 007 |
| 安全组 vs 网络 ACL | 实例级、有状态 / 子网级、无状态 | 出方向要不要单独配回程规则 | 007 §7.7 |
| 桥接 vs NAT（VMnet） | 独立 IP 在局域网 / 借宿主机 IP 出门 | 虚机 IP 与宿主同网段与否 | 008 §8.6 |
| MTU vs MSS | 链路层整包上限 / TCP 载荷上限（MTU−40） | `ip link` vs `ip tcp_metrics`/抓包 MSS 协商 | 009 |
| 时延 vs 带宽 | 单次要多久 / 单位时间运多少 | `ping` vs `iperf3` | 009 §9.4 |

## 按症状反查

值班时只有一个现象、不知道该翻哪一篇，从这里进。

| 现象 | 大概是 | 去哪 |
| --- | --- | --- |
| ping 同网段 IP 不通 | ARP 没学上 / VLAN 不对 / 端口隔离 | 001 §1.9 |
| ping 跨网段不通 | 缺网关 / 缺回程路由 | 001 §1.9 |
| ping 通但端口不通 | 服务没起 / 只听 127.0.0.1 / 防火墙 | 002 §2.10 / 007 §7.8 |
| 时通时断，重启网卡就好 | ARP 冲突或地址冲突 | 001 §1.8 |
| 能上 QQ 打不开网页 | DNS 坏了 | 003 §3.7 |
