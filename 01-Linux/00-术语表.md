# 00 术语表

> **这一文档回答**：某个词是什么意思、两个长得很像的概念差在哪、以及「只知道现象、不知道该翻哪一册」时往哪走。  
> **怎么用**：三种查法——按名字（下面按册分组）、按英文或缩写（缩写速查）、按现象（症状反查）。  
> **只有一句话**：要原理和命令回对应册；这里只保证你「认得出、分得清、找得到」。

---

## 01 系统与启动

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 内核 | kernel | 直接管硬件的那层。它出错叫 panic，不叫崩溃 |
| 发行版 | distribution | 内核 + 包管理 + 默认配置的组合。CentOS 与 Ubuntu 的差别几乎都在这三样 |
| 固件 | firmware（BIOS / UEFI） | 通电后的第一段代码，决定从哪块盘、哪个文件开始引导 |
| GRUB | GRUB | 引导器，把内核和 initramfs 读进内存后移交控制权 |
| initramfs | initial RAM filesystem | 开机时先加载进内存的小根文件系统，作用是去挂真正的根分区 |
| PID 1 / init | init process | 内核拉起的第一个用户态进程。现在的 Linux 上它就是 systemd |
| systemd | systemd | 服务与依赖管理器。它是 1 号进程，所有服务最终都是它的子进程 |
| unit | unit | systemd 管理的最小单位。一个 `.service` 文件就是一份服务定义 |
| target | target | 一组 unit 的集合，等于旧的「运行级别」 |
| 运行级别 | runlevel | CentOS 6 的说法：3 是多用户命令行，5 是图形界面 |
| dmesg | dmesg | 内核环形缓冲区。硬件报错和 OOM 都在这里，重启即清空 |
| sysctl | sysctl | 运行时改内核参数。不写进 `/etc/sysctl.d` 就重启失效 |
| 内核模块 | kernel module | 可动态加载的驱动（`.ko`），不用重编内核就能加硬件支持 |
| EOL | End of Life | 停止维护，不再出安全补丁。CentOS 6 在 2020-11 已经 EOL |

## 02 进程与资源

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 进程 | process | 程序被加载执行一次。有独立地址空间、独立 PID |
| 线程 | thread | 进程内部的执行流，共享地址空间和文件表 |
| 守护进程 | daemon | 脱离终端在后台常驻的进程，习惯以 d 结尾命名 |
| 僵尸进程 | zombie | 已退出但父进程没收尸。杀不掉，只能处理它的父进程 |
| 孤儿进程 | orphan | 父进程先退出，被 PID 1 收养 |
| 信号 | signal | 进程间的通知机制。TERM 是请它退，KILL 是硬杀，HUP 常被实现成重载 |
| 会话 / 控制终端 | session / TTY | 决定退出登录时哪些进程会被 SIGHUP 带走 |
| 文件描述符 | file descriptor, fd | 进程打开的文件编号。0 / 1 / 2 是标准输入、输出、错误 |
| 负载 | load average | 1 / 5 / 15 分钟内在跑和等 IO 的进程数均值，算的是 R + D |
| RSS | Resident Set Size | 进程占的物理内存。共享库会被每个进程各算一遍 |
| PSS | Proportional Set Size | 共享页按比例分摊后的真实占用。多进程共享库时看它 |
| swap | swap | 内存不够时把不活跃的页挪到磁盘上。`si`/`so` 非 0 就是已经在换页了 |
| page cache | page cache | 文件内容的缓存，就是 `free` 里的 `buff/cache`。高是好事 |
| OOM Killer | Out Of Memory killer | 内存耗尽时内核挑一个进程杀掉，按 `oom_score` 挑 |
| cgroup | control group | 把一组进程框起来限制 CPU / 内存 / IO。容器的底层依赖 |
| ulimit / rlimit | resource limit | 单个进程的资源上限（句柄数、进程数、栈大小），和 cgroup 不是一回事 |
| nice 值 | nice value | CPU 调度优先级。`-20` 最优先，`19` 最谦让 |

## 03 用户权限与安全

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| UID / GID | user / group ID | 用户与组的数字身份。`ls -n` 看到的就是它 |
| root | root / superuser | UID 为 0 的用户，不受普通权限检查约束 |
| SUID / SGID | set user / group ID | 执行时借用文件属主 / 属组的身份。`passwd` 靠 SUID 才能改 shadow |
| Sticky bit | sticky bit | 目录里的文件只有属主能删。`/tmp` 就是靠它 |
| umask | user file-creation mask | 新建文件 / 目录时被扣掉的权限位 |
| ACL | Access Control List | 在 rwx 三元组之外，单独给某个用户或组授权 |
| capability | Linux capabilities | 把 root 的一揽子特权拆成细项，可以只给一项而不给全部 |
| sudo | superuser do | 按策略临时借权，比直接发 root 密码可审计 |
| PAM | Pluggable Authentication Modules | 认证插件框架。密码强度、登录次数限制、家目录自动创建都在这 |
| SELinux / AppArmor | SELinux / AppArmor | 强制访问控制：即使 root 也要按策略走。`chmod 777` 不生效多半是它 |
| auditd | audit daemon | 内核级审计，记录谁在什么时候动了哪个文件 |
| 提权 | privilege escalation | 从普通用户拿到 root 的过程。正当运维和攻击用的是同一批口子 |

## 04 存储与文件系统

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 分区表 | MBR / GPT | 记录磁盘怎么分区。MBR 只支持 2TB 和 4 个主分区 |
| 文件系统 | filesystem | 数据在盘上怎么排布。Linux 上主要是 ext4 与 xfs |
| 挂载 | mount | 把分区接到目录树上。`/etc/fstab` 决定开机挂哪些 |
| inode | index node | 文件的元数据（权限、属主、数据块位置）。**inode 满了同样写不进文件** |
| 块设备 | block device | 按块随机读写的设备。磁盘、LVM 卷、RAID 都是 |
| LVM | Logical Volume Manager | 逻辑卷。盘 → PV → VG → LV，可以跨盘扩容 |
| RAID | Redundant Array of Independent Disks | 多盘组合，用冗余换可用性。0 无冗余、1 镜像、5/6 校验、10 镜像加条带 |
| 硬链接 / 软链接 | hard link / symlink | 硬链接是同一 inode 的另一个名字；软链接是存路径的文件 |
| 快照 | snapshot | 某一时刻的文件系统副本，用来做备份窗口或回滚 |
| journal | journal | 文件系统日志。崩溃后靠它把没写完的操作重放或丢弃 |

## 05 网络配置与排障

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 网卡 / 接口 | network interface | 网络收发的出口，`ip a` 列出来的每一项 |
| MAC 地址 | MAC address | 网卡的物理地址。同网段通信靠它，跨网段靠 IP |
| 子网掩码 / CIDR | netmask / CIDR | 判断目标 IP 在不在同网段。`/24` 就是 `255.255.255.0` |
| 网关 | gateway | 目标不在同网段时的下一跳 |
| 路由表 | routing table | 「去哪个网段走哪个口」。`ip route` 看的就是它 |
| DNS | Domain Name System | 域名转 IP。`/etc/resolv.conf` 决定问谁 |
| 端口 | port | 同一 IP 上区分服务的编号。`LISTEN` 表示有人在等连接 |
| 套接字 | socket | 一条连接的抽象。`ss` 列出的是它，不是端口 |
| 环回 | loopback, lo | `127.0.0.1`。只在本机内部走，不经过网卡 |
| MTU | Maximum Transmission Unit | 一个包最大能装多少字节。超了要分片，分片被拦就是「能 ping 通、打不开网页」 |
| NAT | Network Address Translation | 地址转换。把内网地址换成公网地址出门 |
| 防火墙四件套 | netfilter | `iptables` / `firewalld` / `nftables` / `ufw`，底层都是 netfilter |

## 06 软件、服务与任务

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 包 | package（RPM / DEB） | 预编译好的软件包。RPM 与 DEB 是两大格式 |
| 仓库 | repository | 包从哪下载。换源换的就是这个地址 |
| 依赖 | dependency | A 要跑必须先装 B。「依赖地狱」指版本互相要求、谁都不满足 |
| 补丁 | patch | 修安全问题或 bug 的更新。不升大版本也要打 |
| journald / rsyslog | journald / rsyslog | 两套日志服务。前者二进制、用 `journalctl` 查；后者写文本文件 |
| logrotate | logrotate | 按大小或时间切日志并清理。磁盘被打满的第一大原因就是它没配 |
| cron | cron | 定时任务。它拿到的环境变量和 `PATH` 与你登录时不同，这是最大的坑 |
| timer | systemd timer | systemd 版的定时任务。能补跑、有日志，比 cron 好排错 |

## 07 命令行与文本处理

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 标准流 | stdin / stdout / stderr | 每个进程默认带三条流，编号 0 / 1 / 2。`2>` 里的 2 就是它 |
| 重定向 | redirection | 把流改接到文件。`>` 覆盖、`>>` 追加、`2>&1` 把错误并进标准输出 |
| 管道 | pipe | 前一条命令的输出直接变成后一条的输入，走内核内存，不落盘 |
| 通配符 | glob | `*` `?` `[]` 由 **shell 先展开**再把结果交给命令，不是命令自己认 |
| 正则 | regular expression | 文本匹配模式，`grep`/`sed`/`awk` 用。和通配符不是一套语法 |
| 字段分隔符 | FS / IFS | `awk` 的 `FS`（默认空白）、`read` 的 `IFS`。怎么切片由它定 |
| 命令替换 | command substitution | `$( )` 或反引号，把命令输出当字符串用 |
| 进程替换 | process substitution | `<( )`，把命令输出伪装成一个文件路径给别的命令读 |
| 参数展开 | parameter expansion | `${var:-默认}`、`${var%.*}` 这类。**不加引号会被分词** |
| here document | here document (`<<`) | 把一段多行文本直接喂给命令的标准输入，`cat <<EOF` 是典型 |

## 08 Shell 脚本

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| shebang | shebang (`#!`) | 脚本第一行，告诉内核用哪个解释器。`bash x.sh` 时它只是注释 |
| 退出码 | exit code | 0 是成功，1–255 是失败原因。cron、CI、监控**只看它** |
| 子 shell | subshell | 管道右边、`$( )`、`( )` 里开出的副本，里面改的变量外面看不到 |
| `trap` | trap | 捕获信号或退出事件执行清理。`kill -9` 捕获不到 |
| 锁文件 | lock file | 防止两个实例同时跑。`flock` 靠它加锁，进程退出自动释放 |
| 幂等 | idempotent | 跑一次和跑十次结果一样。中断后能直接重跑的脚本才叫幂等 |
| 静态检查 | static analysis | 不运行就查代码问题。`shellcheck` 就是干这个的 |

## 09 性能分析与排障

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| USE 方法 | Utilization / Saturation / Errors | 每个资源都问三句：忙不忙、排不排队、有没有报错 |
| 利用率 | utilization | 资源在时间上忙的比例。**高不等于饱和**，还得看队列 |
| 饱和度 | saturation | 排队长度。利用率 100% 可能仍然健康，饱和度涨才是真堵 |
| 吞吐量 | throughput | 单位时间干完多少活（IOPS、MB/s、req/s） |
| 延迟 | latency | 单次操作要等多久。`iostat` 的 `await` 就是它 |
| 抖动 | jitter | 延迟忽高忽低。平均值正常但长尾很惨时看它 |
| 缺页 | page fault | 访问的页不在内存里，要内核补。分 minor 和 major 两种 |
| 主缺页 | major fault | 需要读盘才能补齐的缺页。它高就是内存压力或首次访问 |
| 脏页 | dirty page | 改了还没写回磁盘的页。积压到阈值会把写入进程卡住 |
| 回写 | writeback | 内核把脏页刷盘的动作。`kworker` 常停在这上面 |
| 软中断 | softirq | 内核推迟处理的中断下半部。收包暴涨时它先高 |
| PSI | Pressure Stall Information | 内核直接统计「任务被资源卡了多久」，比 load 准，4.20+ |
| steal time | `%st` | 虚机的时间被宿主机拿走的部分。**guest 里查不出任何原因** |
| 队列深度 | queue depth | 同时压给设备的请求数。报 IOPS 必须连它一起说才有意义 |
| 火焰图 | flame graph | 把采样堆栈画成宽度＝耗时占比的图，用来找热点 |

## 10 数据备份与共享

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| rsync | remote sync | 增量同步，只传有差异的部分 |
| 热备 / 冷备 | hot / cold standby | 备机能随时接管 / 要先停机再加载 |
| 3-2-1 | 3-2-1 rule | 三份副本、两种介质、一份异地。备份策略的最低标准 |
| RTO / RPO | Recovery Time / Point Objective | 出事多久能恢复 / 能容忍丢多少数据 |
| 恢复演练 | restore drill | 真的从备份恢复一次。没演练过的备份不能算备份 |
| 硬链接快照 | hardlink snapshot | 未变化的文件指向上一份的同一个 inode，看着每份都是全量，实际只占一份空间 |
| 写时复制 | copy-on-write, COW | 改数据前先把旧块搬到快照区。快照又快又省空间就是靠它 |
| `root_squash` | root squash | NFS 把客户端 root 压成匿名用户。默认开启，也是「共享写不进」的头号原因 |
| 一致性备份 | consistent backup | 备的是某一瞬间的状态，而不是「边写边拷」拼出来的结果 |

## 缩写速查

读报错、看英文文档时按字母找。

| 缩写 | 全称 | 意思与出处 |
| --- | --- | --- |
| ACL | Access Control List | 访问控制列表，rwx 之外的细粒度授权（03） |
| CIDR | Classless Inter-Domain Routing | 无类域间路由，`/24` 这种写法就是它（05） |
| DAC | Discretionary Access Control | 自主访问控制：属主说了算。`chmod` 属于这一层（03） |
| FD | File Descriptor | 文件描述符，进程打开文件的编号（02） |
| FHS | Filesystem Hierarchy Standard | 目录树规范，`/etc` `/var` `/run` 的职责出自它（01） |
| GPT | GUID Partition Table | 新分区表，支持 2TB 以上、最多 128 个分区（04） |
| IOPS | Input/Output Operations Per Second | 每秒能完成多少次读写操作。**报它必须连块大小一起说**（04 / 09） |
| LVM | Logical Volume Manager | 逻辑卷管理，盘 → PV → VG → LV（04） |
| **MAC** | ① MAC address ② Mandatory Access Control | **两个完全不同的意思**：①是网卡物理地址（05），②是强制访问控制（03）。看上下文，SELinux 语境里是② |
| MBR | Master Boot Record | 老分区表，2TB 与 4 个主分区的上限来自它（04） |
| MTU | Maximum Transmission Unit | 单包最大字节数，默认 1500（05） |
| NAT | Network Address Translation | 地址转换（05） |
| NUMA | Non-Uniform Memory Access | 多路机器上内存按 CPU 分组，跨节点访问更慢（09 讲 `%st` 时提到） |
| OOM | Out Of Memory | 内存耗尽，被内核挑中杀掉的那个进程就是 OOM kill（02） |
| PAM | Pluggable Authentication Modules | 认证插件框架，`sshd` 的密码校验实际在这里（03） |
| PID / PPID | Process ID / Parent PID | 进程号 / 父进程号（02） |
| PSI | Pressure Stall Information | 内核统计的资源压力，比 load 更能说明「到底卡在哪」（09） |
| PSS | Proportional Set Size | 共享页按比例分摊后的内存占用（02） |
| PV / VG / LV | Physical Volume / Volume Group / Logical Volume | LVM 的三层：物理卷 → 卷组 → 逻辑卷（04） |
| RAID | Redundant Array of Independent Disks | 磁盘阵列（04） |
| RPM | RPM Package Manager | 既是包格式也是包管理器名（06） |
| RSS | Resident Set Size | 进程驻留的物理内存（02） |
| SELinux | Security-Enhanced Linux | 红帽系的强制访问控制（03） |
| SUID / SGID | Set User ID / Set Group ID | 借身份执行的两个特殊权限位（03） |
| TTY | Teletype | 终端设备。`ps` 里 TTY 是 `?` 表示已脱离终端（02） |
| UEFI | Unified Extensible Firmware Interface | 新式固件，替代 BIOS（01） |
| UID / GID | User ID / Group ID | 用户号 / 组号。UID 0 就是 root（03） |
| VSZ | Virtual Set Size | 虚拟地址空间大小，含已申请未使用的，参考价值低（02） |

## 最容易混的 20 对

Linux 的困惑多半是成对的。这张表只回答「差别在哪、怎么一眼确认」。

| 容易混 | 一句话差别 | 怎么确认 | 册 |
| --- | --- | --- | --- |
| 孤儿 vs 僵尸 | 活着没人管 / 死了没人埋 | `ps -o stat,ppid` 看到 `Z` 就是僵尸 | 02 |
| 冻结 vs 杀死 | `STOP` 还能 `CONT` 回来 / `KILL` 不可逆 | 冻结后状态变 `T`，`kill -CONT` 恢复 | 02 |
| RSS vs PSS | 重复算共享库 / 按比例分摊 | `/proc/<pid>/smaps_rollup` 里的 `Pss` | 02 |
| cgroup vs ulimit | 一组进程的总量 / 单进程的上限 | `systemd-cgtop` vs `/proc/<pid>/limits` | 02 |
| 负载 vs CPU 使用率 | 负载算 R + D，`D` 不占 CPU | `vmstat 1` 的 `r` / `b` 两列 | 02 |
| 内存不足 vs 内存泄漏 | 需求超过容量 / 申请了不释放 | 曲线是阶梯上升还是单调不回落 | 02 |
| 缓冲 vs 缓存 | buffer 为「攒一批再写」，cache 为「读过还可能再读」 | `free` 里合成一列 `buff/cache`，看总量即可 | 02 |
| 利用率 vs 饱和度 | 忙的时间占比 / 排队的长度 | `iostat` 的 `%util` vs 同一行的 `aqu-sz` | 09 |
| 次缺页 vs 主缺页 | 内存里挪一下就有 / 必须读盘 | `sar -B` 的 `fault/s`（含 minor）vs `majflt/s` | 09 |
| `su` vs `su -` | 不换环境 / 加载目标用户的完整环境 | `echo $PATH`、`pwd` 两边比 | 03 |
| SUID vs capability | 整个身份切成 root / 只给一项特权 | `ls -l` 看 `s` 位 vs `getcap` | 03 |
| `chcon` vs `semanage fcontext` | 临时改标签 / 永久规则 | 跑一次 `restorecon` 看还在不在 | 03 |
| target vs runlevel | 同一概念的新旧名字 | `systemctl get-default` | 01 |
| journald vs rsyslog | 二进制集中 / 文本分散 | `journalctl` vs `ls /var/log` | 06 |
| 权限不足 vs 只读挂载 | 位没给够 / 文件系统整个是 `ro` | `namei -l` vs `mount \| grep ' ro,'` | 03 / 04 |
| 软链接 vs 硬链接 | 存路径的文件 / 同一 inode 的另一个名字 | `ls -li` 看两个 inode 是否相同 | 04 |
| `df` vs `du` | 文件系统视角 / 文件累加视角 | 对不上时查 deleted 文件（002 §2.7） | 04 |
| `set -e` vs `trap ERR` | 出错就停 / 出错时告诉你停在哪 | `trap 'echo "$LINENO"' ERR` 配 `set -E` | 08 |
| `[ ]` vs `[[ ]]` | 外部程序，会分词 / 语法结构，不分词 | `v="a b"; [ $v = x ]` 报错，`[[ $v == x ]]` 不报 | 08 |
| `flock` vs PID 锁文件 | 内核管锁，进程退自动释放 / 自己判断，PID 会复用 | 锁「永远不释放」就是用了 PID 锁 | 08 |

| 现象 | 大概是 | 去哪 |

| `free` 快见底了，是不是要炸 | 正常，`buff/cache` 可回收，看 `available` | 002 §2.8 |

| 端口不通 | 防火墙 / 只听在 127.0.0.1 / 路由 | 05 |
| 能 ping 通但打不开网页 | MTU 分片被拦 / DNS / 代理 | 05 |
