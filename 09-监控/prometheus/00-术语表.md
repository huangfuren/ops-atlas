# Prometheus 术语表

> **这一文档回答**：监控领域某个词是什么意思、两个混用词的分界。  
> **怎么用**：按名字（按册分组）、按缩写（缩写速查）、按现象（症状反查）。  
> **只有一句话**：要原理和命令回对应册；这里只保证你「认得出、分得清、找得到」。

---

## 001 原理与架构

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| Prometheus | — | 拉模式时序数据库与监控系统 |
| TSDB | Time Series Database | 时序数据库：按时间戳+标签索引的KV存储 |
| 拉模式 | pull model | Prometheus 定期 HTTP GET 目标的 /metrics——与推模式（StatsD）相对 |
| exporter | — | 把非 Prometheus 格式的指标暴露为 /metrics 的适配器 |
| target | — | 被监控的一个端点（IP:port/metrics） |
| job | — | 一组同类型 target 的集合 |
| instance | — | 一个 target 的具体实例标识 |
| service discovery | 服务发现 | 自动发现要监控的 target：file/consul/kubernetes |
| Pushgateway | — | 短命任务的指标中转站—— Prometheus 拉不到它，它推给 Prometheus |
| 多副本 | HA pair | 两个 Prometheus 抓同一组目标——数据重复但可用性高 |

## 002 数据与查询

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 时间序列 | time series | 标签名组+指标名唯一确定的一条带时间戳的值序列 |
| metric name | 指标名 | `http_requests_total`——描述测量的是什么 |
| label | 标签 | 键值对维度：`method="GET"`——区分同指标的不同维度 |
| sample | 样本 | 某时刻的具体值（float64 + 毫秒时间戳） |
| PromQL | Prometheus Query Language | 查询语言：选择器+运算+函数 |
| instant vector | 瞬时向量 | 每条序列在某一时刻的最新值 |
| range vector | 范围向量 | 某段时间内的多个样本：`[5m]` |
| counter | 计数器 | 只增不减——用 `rate()` 取速率而非直接看值 |
| gauge | 仪表盘 | 可增可减——直接取当前值 |
| histogram | 直方图 | 分桶计数——`histogram_quantile()` 算分位数 |
| summary | 摘要 | 客户端预算分位数——**多实例不能聚合** |
| rate / irate | — | counter 的增长率：irate 灵敏（最后两个点），rate 平滑 |
| histogram_quantile | — | 从 histogram 算 P99——**预估不是精确值** |

## 003 配置与部署

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| prometheus.yml | — | 主配置文件：global/rule_files/scrape_configs |
| scrape_interval | — | 抓取间隔（默认 1m，常改 15s–30s） |
| scrape_timeout | — | 单次抓取超时（必须 < scrape_interval） |
| relabel | — | 抓取前改写标签：过滤、重命名、映射 |
| metric_relabel_configs | — | 抓取后改写样本标签——最后一道闸 |
| honor_labels | — | 是否保留目标自带的 job/instance 标签 |
| recording rule | 记录规则 | 预计算表达式存为新指标——降查询压力 |
| alerting rule | 告警规则 | 表达式超阈值则触发告警 |
| federation | 联邦 | 上级 Prometheus 抓下级的聚合指标——层级监控 |

## 004 存储告警排错

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| head block | — | 内存中的近期数据（默认 2h），查询的主战场 |
| block | block | 落盘的不可变数据块（每 2h 压缩一次） |
| WAL | Write-Ahead Log | 崩溃恢复日志——重启后从 checkpoint 回放 |
| tombstone | — | 删除标记——数据不立即消失，retention 清理时才释放 |
| Alertmanager | — | 告警的分组/抑制/路由/通知组件——**与 Prometheus 分离** |
| group_wait / group_interval | — | 同组告警等首批集齐再发 / 后续告警间隔 |
| inhibition | 抑制 | 根因告警触发时压制连带告警（如节点挂了→该节点所有 Pod 告警静默） |
| silence | 静默 | 指定时间/标签范围不发送通知——计划内维护用 |
| remote_write | — | 把样本实时推给远端存储（Thanos Receive/Mimir） |

## 05–08 扩展

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| Grafana | — | 可视化与仪表盘平台——数据源可接 Prometheus/Loki/Tempo |
| data source | 数据源 | Grafana 里配置的查询后端连接 |
| panel | 面板 | 仪表盘上的单个图表/表格/统计 |
| variable | 变量 | 仪表盘的下拉参数（如 `$service`）——一份模板服务多场景 |
| node_exporter | — | 主机指标采集器：CPU/内存/磁盘/网络 |
| blackbox_exporter | — | 黑盒探测：HTTP/TCP/ICMP/ DNS 拨测 |
| Thanos | Thanos | Prometheus 的水平扩展与长期存储方案：Sidecar + Query + Store |
| Mimir | Grafana Mimir | Prometheus 的水平扩展替代（原 Cortex） |
| VictoriaMetrics | — | 高性能时序数据库，兼容 Prometheus 查询 |
| 多窗口多燃烧率 | multi-window multi-burn-rate | SLO 告警的标准写法：快慢双窗口同时超才触发 |

## 最容易混的 12 对

| 容易混 | 一句话差别 | 怎么确认 | 册 |
| --- | --- | --- | --- |
| gauge vs counter | 可增可减 / 只增不减 | 进程重启归零的是 counter | 02 |
| rate vs irate | 时间段平均增速 / 最后两个样本的瞬时增速 | irate 更灵敏但毛刺大 | 02 |
| histogram vs summary | 服务端可聚合 / 客户端预算分位 | 多实例需要 P99 → histogram | 02 |
| instant vs range vector | 一个点 / 一段时间的点 | `metric` vs `metric[5m]` | 02 |
| recording vs alerting rule | 预计算存指标 / 超阈值发告警 | recording 结果可查，alerting 只在触发时可见 | 03 |
| relabel vs metric_relabel | 抓前改 target 标签 / 抓后改样本标签 | 作用对象不同：target vs sample | 03 |
| Prometheus vs Alertmanager | 存数据+评估规则 / 管通知路由 | Alertmanager 不存指标 | 04 |
| group_wait vs group_interval | 首条等集合 / 后续条间隔 | 首条通知慢是 group_wait 的锅 | 04 |
| 抑制 vs 静默 | 条件压制 / 时间范围内全静音 | 抑制看标签关系，静默看时间 | 04 |
| head vs block | 内存近期 / 落盘不可变 | 重启后 head 从 WAL 恢复 | 04 |
| 联邦 vs 远程写 | 上级拉下级聚合 / 实时推到远端 | 全局视图用联邦，长期存储用远程写 | 004 §4.5 |
| Thanos vs VictoriaMetrics | Prometheus 原生扩展 / 独立高性能时序库 | 都解决长期存储与水平扩展 | 08 |

## 按症状反查

| 现象 | 大概是 | 去哪 |
| --- | --- | --- |
| target 显示 DOWN | 端口不通 / 路径错 / 防火墙 | 001 §1.3 / 003 §3.1 |
| 指标有数据但图形空白 | 时间窗 / refresh / data view | 003（Grafana）§3.1 |
| ES/存储突然不能写 | 磁盘 95% 只读锁（ES 场景） | 见「日志」006 |
| Prometheus OOM | 基数爆炸 / 查询过重 | 008 §8.x |
| 告警不触发 | 表达式错 / for 时间未满足 / Alertmanager 路由 | 006 §6.x |
| 告警风暴 | 缺分组 / 缺抑制 / 阈值太敏感 | 006 §6.x |
| 通知延迟很久 | group_wait + group_interval 串联 | 004 §4.4 |
| Grafana 面板无数据 | 数据源配置 / 时间范围 / 变量值 | 005 §5.x |
| P99 图形有锯齿 | histogram bucket 太少 / 采样间隔太长 | 002 §2.2 |
| Prometheus 重启后老数据丢 | WAL 损坏 / 保留期过短 | 004 §4.1 |
| 节点挂了但 Prometheus 还在抓 | SD 未更新 / stale 标记未生效 | 003 §3.5 |
| rate() 结果为 0 或负 | counter 重置（服务重启）——用 rate 而非手工差值 | 002 §2.2 |
