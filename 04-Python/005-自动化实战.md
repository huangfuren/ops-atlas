## 5.1 批量三条路：Ansible / paramiko / requests API

"对一批机器做点什么"有三条路，选型边界：

| 路线 | 适合 | 本库 |
|---|---|---|
| **Ansible** | 批量**变更**（改配置/装包/重启）——编排、幂等、审计全套 | 「CICD」004/005 |
| **paramiko** | 单机编程式取数/操作（需要结果参与判断） | 003 §3.6 |
| **requests API** | 目标有 API 时的正路（云主机、容器平台、监控） | 003 §3.5 |

判断口诀：**改状态找 Ansible；取数据看有没有 API；两条都没有才 paramiko**。Python 巡检脚本的定位是"**只读不改**"——巡检发现问题后，修复动作交给 Ansible playbook 或人工，脚本自己不越权（审计与授权边界，004 §4.4 的安全带）。

## 5.2 IM 告警 webhook：钉钉/企微/飞书

三大 IM 的机器人都是"POST 一个 JSON"：

```python
import requests

def notify_dingtalk(text: str) -> None:
    requests.post(
        WEBHOOK_URL,                       # 从环境变量取（001 §1.6 凭据纪律）
        json={"msgtype": "text", "text": {"content": text}},
        timeout=(3, 10),
    ).raise_for_status()

notify_dingtalk("⚠️ 磁盘巡检：web-1 使用率 95%（阈值 90%）")
```

两条告警纪律（与「监控」004 的告警分级对齐）：**限频**——同一问题在告警窗口内只发一次（内存里记"上次发送时间"，或交给监控去发而脚本只落库）；**消息自包含**——收件人不需要追问"哪台机器、多严重、谁该看"。

## 5.3 调用 Ansible：subprocess 跑 playbook

Python 与 Ansible 的组合姿势：**Python 做上游判断，Ansible 做下游执行**：

```python
import subprocess

def run_playbook(playbook: str, limit: str) -> int:
    cmd = [
        "ansible-playbook", playbook,
        "-i", "inventory/prod",
        "--limit", limit,
    ]
    return subprocess.run(cmd, check=True, timeout=1800).returncode

if disk_report["critical"]:
    run_playbook("playbooks/cleanup.yaml", limit=",".join(disk_report["critical"]))
```

要点：`check=True` 让 playbook 失败即异常；`--limit` 精确圈定目标机（Ansible 的批量边界）；**执行日志留存**（Ansible 自身的输出进日志文件——「CICD」009 的审计链）。若发现脚本里写满了"先 SSH 看状态、再 ssh 改文件"——那是把 Ansible 的活用 paramiko 重写了一遍（003 §3.6 的越界信号）。

## 5.4 巡检脚本的幂等纪律

巡检/取数类脚本的天然优势是**只读**——天然幂等。仍要守住四条：

1. **不产生副作用**：只读系统状态；要"顺手修复"就显式加 `--fix` 开关（默认只报）；
2. **输出可解析**：人读一行摘要 + 机读一份 JSON/CSV（004）——下游能消费；
3. **失败可重跑**：中断/重跑不产生重复告警（5.2 的限频即去重）；
4. **凭据与路径自足**：绝对路径 + venv 解释器（002 §2.6），cron 与手工行为一致。

## 5.5 完整例子：磁盘巡检 + 告警 + 报表

把 002（subprocess/shutil）、003（API 可选）、004（报表）串成一个真实脚本骨架：

```python
#!/usr/bin/env python3
"""磁盘巡检：采集 → 判阈 → 告警 → 报表。只读，幂等。"""
import argparse, csv, shutil, sys
from pathlib import Path

def collect(hosts: list[str], threshold: int) -> list[dict]:
    rows = []
    for host in hosts:                     # 多机场景：改用 Ansible 采集（5.3）
        usage = shutil.disk_usage(f"/data/{host}").percent
        rows.append({"host": host, "used": usage,
                     "critical": usage >= threshold})
    return rows

def main() -> int:
    parser = argparse.ArgumentParser(description="磁盘巡检")
    parser.add_argument("hosts", nargs="+")
    parser.add_argument("-t", "--threshold", type=int, default=90)
    args = parser.parse_args()

    rows = collect(args.hosts, args.threshold)
    critical = [r for r in rows if r["critical"]]

    with open("/opt/reports/disk.csv", "w", newline="", encoding="utf-8-sig") as f:
        w = csv.DictWriter(f, fieldnames=["host", "used", "critical"])
        w.writeheader(); w.writerows(rows)

    if critical:
        notify_dingtalk("⚠️ 磁盘告警：" +
                        ", ".join(f"{r['host']} {r['used']}%" for r in critical))
        return 2                           # cron/流水线据此判断
    print("全部正常")
    return 0

if __name__ == "__main__":
    sys.exit(main())
```

结构复盘：**collect（002 系统交互）→ 判阈 → csv（004 报表）→ webhook（本册 5.2）→ 退出码（001 §1.3）**——每段都可独立测试（006），整个脚本约 40 行。

## 5.6 六个坑

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 巡检脚本顺手修复 | 越权变更无审计 | 默认只读，`--fix` 显式（5.4） |
| 2 | 告警无限频 | 风暴把自己打挂 | 窗口内去重（5.2） |
| 3 | webhook 凭据硬编码 | 泄漏进 Git | 环境变量（001 §1.6） |
| 4 | 多机循环用 paramiko | 重新发明 Ansible | 变更走 Ansible（5.1） |
| 5 | 告警消息不自包含 | 收件人再追问 | 主机+数值+阈值写全 |
| 6 | 脚本超时无外保 | 挂死占住 cron 槽 | 外层 subprocess timeout（003 §3.7） |

第 4 条展开一个判别练习：需求是"检查 50 台机器的 nginx 版本并汇总"——取数（只读）且需要汇总逻辑 → Python 合理；需求是"50 台机器升级 nginx"——状态变更 → Ansible playbook（Python 至多当调度者）。**读用 Python、改用 Ansible**，六字分界。
