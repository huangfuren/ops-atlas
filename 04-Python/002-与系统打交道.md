## 2.1 subprocess：run、check=True 与命令注入防线

Python 里跑外部命令只有一个入口：`subprocess.run`。

```python
import subprocess

# ✅ 标准姿势：参数列表 + check + 捕获输出
result = subprocess.run(
    ["df", "-h", "/data"],
    capture_output=True, text=True, check=True, timeout=30,
)
print(result.stdout)

# ✅ 带管道的复杂命令：多条 run 串联，别开 shell
df = subprocess.run(["df", "-h"], capture_output=True, text=True, check=True).stdout
data_line = subprocess.run(["grep", "/data"], input=df, capture_output=True, text=True).stdout
```

三条防线，缺一不可：

1. **`check=True`**：退出码非 0 即抛 `CalledProcessError`——不加它，命令失败你的脚本照样往下跑（静默失败，001 §1.4 的病）；
2. **`shell=False`（默认）**：参数用**列表**，变量不经过 shell 解释——命令注入的防线。反例：`subprocess.run(f"ping {user_input}", shell=True)`——用户输入 `x; rm -rf /` 就是灾难；确需 shell 特性（管道/通配）时优先用两条 run 串联（如上例）；
3. **`timeout=30`**：外部命令可能挂死——超时抛 `TimeoutExpired`。

`text=True` 让输出直接是字符串（否则是 bytes）——忘加它是 `b'...'` 前缀之谜的来源。

## 2.2 pathlib 与 shutil：路径与文件树的现代写法

路径操作一律 `pathlib`（面向对象，跨平台分隔符）：

```python
from pathlib import Path
import shutil

log_dir = Path("/var/log/myapp")
for f in sorted(log_dir.glob("*.log")):        # 遍历当前层
    print(f.name, f.stat().st_size)

for f in log_dir.rglob("*.log"):               # 递归子目录
    if f.stat().st_mtime < cutoff:
        f.unlink()                              # ⚠️ 删除前确认范围

shutil.copy2("app.conf", backup_dir / "app.conf.bak")   # 连元数据一起拷
shutil.rmtree("/tmp/work", ignore_errors=True)           # ⚠️ 删整棵树
```

三条纪律：**删操作先用 print 列出目标再执行**（等价于 --check 演练，「CICD」004 的幂等纪律）；**字符串拼路径（`"/var/log" + "/" + name`）换成 `Path("/") / "var" / "log"`**；`shutil.rmtree` 与 `unlink` 永远确认路径不含变量拼写错误——Python 里没有回收站。

## 2.3 文本与编码：re 与 UTF-8

日志与配置文件解析的正则三件套：

```python
import re

# 分组捕获：日志行 → 字段（与「日志」005 §5.2 的字段公约对齐）
PAT = re.compile(
    r"^(?P<ip>\S+) .+ \[(?P<time>[^\]]+)\] \"(?P<method>\w+) (?P<uri>\S+)[^\"]*\" (?P<status>\d{3})"
)
m = PAT.match(line)
if m:
    print(m["ip"], m["status"])          # 命名分组直接取

# 常用：findall 取全部、sub 替换
ips = PAT.findall(text)
masked = re.sub(r"(sk-)\w+(.{4})", r"\1***\2", text)   # token 打码
```

编码纪律：**读写文件显式 `encoding="utf-8"`**——Windows 上默认编码是 GBK（本地化变体），不写 encoding 的脚本跨平台必乱码：

```python
text = Path("app.log").read_text(encoding="utf-8")
```

## 2.5 系统信息：os/platform 与 psutil 注记

- **标准库**：`os.cpu_count()`、`os.getloadavg()`、`platform.system()/release()`、`shutil.disk_usage("/")`（总/用/余）——轻量巡检够用；
- **psutil（第三方）**：进程清单、内存明细、网络连接——**需要跨平台细粒度系统数据时才引**，`psutil.disk_usage` 与 `disk_partitions` 是磁盘巡检（005 §5.5）的主力。

标准库能解决就不引 psutil——依赖最小化（000 §0.3）。

## 2.6 定时任务配合：脚本接 cron/timer 的规范

脚本被 cron/systemd timer 调度时的四条规范（「Linux」006 的坑在 Python 侧的落地）：

1. **路径全绝对**：cron 的 PATH 极简、工作目录是家目录——`open("data.csv")` 必翻车，用 `Path(__file__).parent / "data.csv"`；
2. **退出码表达结果**：cron 看退出码发告警（001 §1.3）；"成功也发通知"用显式 webhook（005 §5.2）；
3. **输出重定向给日志**：stdout/stderr 接 logging 或由 timer 的 `StandardOutput=` 收（「Linux」006）；
4. **环境自足**：venv 用绝对解释器路径（001 §1.2），不依赖激活状态；凭据从环境变量/受保护文件读。

四条的本质一句话：**定时任务的世界里没有你的交互环境**。

## 2.7 六个坑

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | `check=True` 忘加 | 命令失败脚本照跑 | run 三件套：check/capture/text |
| 2 | `shell=True` 拼用户输入 | 命令注入 | 参数列表（2.1） |
| 3 | 没设 timeout | 外部命令挂死拖垮脚本 | run(timeout=30) |
| 4 | 不写 encoding | Windows 下中文乱码 | 显式 utf-8（2.3） |
| 5 | 相对路径进 cron | 找不到文件，静默失败 | 绝对路径（2.6） |
| 6 | readall 处理大文件 | 内存打爆 | 逐行流式（004 §4.5） |

第 2 条展开一个真实形态：`subprocess.run(f"ssh {host} {cmd}", shell=True)` 是运维脚本最常见的注入点——`host` 来自配置文件还好，来自 API/参数时，`host = "x; shutdown"` 就被执行。修法不是"校验输入"，而是**结构上不用 shell**：`run(["ssh", host, cmd])`——参数列表里没有解释器，注入无从发生。
