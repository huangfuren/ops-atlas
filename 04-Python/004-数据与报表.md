## 4.1 日志解析实战：正则分组提取字段

结构化日志普及前的过渡期，运维仍要从文本日志提取字段——命名分组是主力（「日志」005 §5.2 的字段公约就是为这一步准备的）：

```python
import re
from pathlib import Path

PAT = re.compile(
    r'^(?P<ip>\S+) \S+ \S+ \[(?P<time>[^\]]+)\] '
    r'"(?P<method>\S+) (?P<uri>\S+)[^"]*" '
    r'(?P<status>\d{3}) (?P<bytes>\d+)'
)

rows = []
for line in Path("access.log").read_text(encoding="utf-8").splitlines():
    if m := PAT.match(line):                    # 海象符：匹配成功才处理
        rows.append(m.groupdict())              # {'ip':…, 'status':…}
```

两条纪律：**正则写命名分组 `(?P<name>…)`**——`m["status"]` 比 `m.group(4)` 可读；**解析失败的行要有去处**（`else: unparsed += 1`）——静默丢弃解析失败的行，报表就系统性地失真（「CICD」009 静默失败的变体）。

## 4.2 聚合统计：Counter 与分组

```python
from collections import Counter

status = Counter(r["status"] for r in rows)      # {'200': 9812, '502': 23, …}
top_uri  = Counter(r["uri"] for r in rows).most_common(10)   # TOP 10 URI
top_ip   = Counter(r["ip"] for r in rows).most_common(5)

# 分组求和：按状态码分组的流量
from collections import defaultdict
bytes_by_status = defaultdict(int)
for r in rows:
    bytes_by_status[r["status"]] += int(r["bytes"])
```

`Counter` 一行顶 Shell 的 `awk+sort+uniq -c` 一串管道；`most_common(n)` 直接给 TOP 榜。这套聚合与「日志」003 §3.4 的 Kibana 聚合是同一件事的两个形态——**Kibana 里做得到的不用 Python 重复做**，Python 的价值在"Kibana 查询表达不了的复杂逻辑"（跨行关联、业务规则过滤）。

## 4.3 csv 报表：巡检与统计的交付格式

```python
import csv

with open("report.csv", "w", newline="", encoding="utf-8-sig") as f:
    w = csv.writer(f)
    w.writerow(["状态码", "请求数", "占比"])
    total = sum(status.values())
    for code, n in status.most_common():
        w.writerow([code, n, f"{n / total:.1%}"])
```

要点回顾（002 §2.4）：`newline=""` 防空行、`utf-8-sig` 防 Excel 乱码。报表的设计纪律：**第一行是列头、每行可独立读懂、比例带百分号**——收报表的人（往往是上级）不该需要说明书。

## 4.4 大文件流式：逐行与生成器

日志动辄几十 GB，`read()` 一次读全会打爆内存。两种流式姿势：

```python
# ① 逐行：文件对象天然是迭代器
with open("huge.log", encoding="utf-8") as f:
    for line in f:                    # 每次只在内存放一行
        process(line)

# ② 生成器：解析逻辑与统计逻辑解耦
def parse(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            if m := PAT.match(line):
                yield m.groupdict()    # 惰性产出，不攒内存

count = Counter(r["status"] for r in parse("huge.log"))   # 消费端照常写
```

生成器的价值：**解析函数与统计函数互不感知**——同一个 `parse()` 可以喂 Counter、喂 csv、喂任何下游。内存恒定一条行的大小。

## 4.5 交付渠道：文件、Excel、IM

报表的最后一公里，按收件人选渠道：

| 渠道 | 做法 | 场景 |
|---|---|---|
| CSV 文件 | 4.3 的写法，放共享目录/发邮件附件 | 正式报表、要二次加工 |
| Excel | openpyxl（第三方）：多 sheet、格式 | 面向非技术干系人 |
| IM 消息 | 摘要文本 + 明细附件（005 §5.2 webhook） | 值班速览 |
| 直接入库 | 写回 ES/数据库（003 的 API 反向） | 要长期查询 |

pandas 的边界注记：**表格需要复杂计算（透视、多表关联）时上 pandas**；简单计数与求和，标准库更轻——为一个 TOP 榜引 200MB 依赖不值（000 §0.3 依赖最小化）。

## 4.6 六个坑

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | `read()` 读大文件 | 内存打爆 | 逐行流式（4.4） |
| 2 | 解析失败行静默跳过 | 报表系统性失真 | 计数并输出 unparsed |
| 3 | 正则太贪婪 | 提取字段串位 | 用 `[^\]]+` 排除界符而非 `.+` |
| 4 | csv 忘 newline 与 sig | Excel 空行/乱码 | `newline=""` + `utf-8-sig`（002 §2.4） |
| 5 | 除零算占比 | 遇空文件崩 | 分母判零 |
| 6 | 报表无时间戳与来源 | 隔周无法对账 | 表头写明统计范围与数据源 |

第 3 条展开：贪婪匹配是最常见的正则事故——`"(?P<uri>.+)"` 遇到一行里有两个引号时会吃到行尾。修正口诀：**能排除（`[^\]]+`）就不贪婪（`.+`）**，写完用一行"最刁钻"的真实日志验证分组结果，再上量。
