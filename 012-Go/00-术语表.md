# Go 术语表

> **这一文档回答**：某个词是什么意思、两个长得像的概念差在哪。  
> **怎么用**：按名字（下面按册分组）、按缩写（缩写速查）、按现象（症状反查）。  
> **只有一句话**：要原理和代码回对应册；这里只保证你「认得出、分得清、找得到」。

## 000 环境配置

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| Go SDK | Go Software Development Kit | 编译器 + 标准库 + `go` 命令。装一个文件即全套 |
| module | module | Go 的依赖管理单元：`go.mod` 声明模块名与依赖。替代旧 GOPATH |
| GOPROXY | — | 模块代理地址，国内用 `goproxy.cn,direct` |
| workspace | Go workspace | 多模块共存的开发模式（`go.work`），替代软链 |

## 001 语言全貌

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 静态编译 | statically compiled | 编译出单个二进制，不依赖运行时——容器镜像可以只有可执行文件 |
| CSP | Communicating Sequential Processes | Go 的并发模型：goroutine + channel 通信共享内存 |
| 三色标记 | tricolor marking | GC 的并发标记算法——STW 极短（微秒级） |

## 002 入门

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 切片 | slice | 动态数组的视图：指向底层数组的指针 + 长度 + 容量。**传参共享底层数据** |
| map | map | 哈希表，键值对。**无序**，并发读写需加锁 |
| struct | struct | 结构体：字段的组合，Go 的"类"（方法挂上面） |
| interface | interface | 方法签名集合——**隐式实现**，不需要 `implements` 关键字 |
| defer | defer | 函数返回前执行（LIFO）。用于资源清理，**panic 时也会执行** |
| 指针 | pointer | `*T` 与 `&`——Go 没有指针运算，安全 |
| 错误包装 | error wrapping | `fmt.Errorf("...: %w", err)` 保留原始错误链，上层用 `errors.Is/As` 解包 |
| goroutine | goroutine | Go 的协程：`go f()` 一行即起，初始栈 2KB，由运行时调度 |
| WaitGroup | sync.WaitGroup | 等 N 个 goroutine 完成的计数器。Add 在 go 前、Done 用 defer |
| 包 | package | Go 的代码组织单位，同目录同名。`main` 包的 main 函数是入口 |

## 003 进阶

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 方法集 | method set | 类型上能调用的方法集合。值接收者 vs 指针接收者的分界 |
| 接口内部结构 | interface internals | 接口值 = (动态类型, 动态值) 二元组——**塞 nil 指针 ≠ nil 接口** |
| 逃逸分析 | escape analysis | 编译器决定变量分配在栈还是堆。`go build -gcflags=-m` 查看 |
| 三色标记 | tricolor abstraction | GC 并发标记的抽象模型——写屏障保证并发正确性 |
| GOGC | GOGC | GC 触发频率参数（默认 100 = 堆增长 100% 时触发） |
| GOMEMLIMIT | — | Go 1.19+ 的软内存上限——容器场景防 OOM 的关键参数 |
| 值接收者 vs 指针接收者 | value vs pointer receiver | 值接收者复制副本（含 Mutex 就是灾难）；指针接收者修改原值 |
| context | context.Context | 跨调用链传递取消信号与超时的标准机制。**第一个参数惯例** |
| errgroup | errgroup.Group | WaitGroup + 错误收集：一个失败全取消（`golang.org/x/sync`） |
| slog | structured logging | Go 1.21+ 的结构化日志库——JSON 输出，键值对必须偶数 |
| channel 方向 | channel direction | `chan<-` 只发送、`<-chan` 只接收——类型系统保证不误用 |
| select | select | 多 channel 就绪时随机选一个——非阻塞（default）与超时用法 |

## 004 高阶

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| GMP | G(goroutine) M(thread) P(processor) | Go 运行时调度模型：P 是逻辑处理器，持有一组 G 的队列 |
| work stealing | — | 空闲 P 从其它 P 的队列尾偷 goroutine——负载均衡的机制 |
| 数据竞争 | data race | 多 goroutine 无同步地读写同一内存——`go test -race` 检测 |
| pprof | pprof | Go 内置性能剖析：CPU / heap / goroutine / mutex / block 五种 |
| 写屏障 | write barrier | GC 并发标记期间捕获指针写入的钩子——代价极小 |
| 逃逸到堆 | escape to heap | 编译器确定变量生命周期超出栈帧——分配到堆、GC 管理 |
| 泛型约束 | type constraint | `[T comparable]` 限定类型参数的能力边界 |
| unsafe | unsafe 包 | 绕过类型系统的逃逸舱口——**指针运算、绕过只读**，非必要不用 |
| 可观测 SDK | — | prometheus/client_golang（指标）+ OTel SDK（链路）+ slog（日志） |

## 缩写速查

| 缩写 | 全称 | 意思与出处 |
| --- | --- | --- |
| GMP | G / M / P | goroutine / machine(OS 线程) / processor(逻辑处理器)（004） |
| GOGC | Go Garbage Collection target | GC 触发的堆增长百分比（003/004） |
| LSP | Language Server Protocol | gopls 用的编辑器通信协议（000） |
| CGO | C Go bindings | Go 调 C 代码的桥——CGO_ENABLED=0 可编译纯静态二进制（002） |

## 最容易混的 12 对

| 容易混 | 一句话差别 | 怎么确认 | 册 |
| --- | --- | --- | --- |
| `:=` vs `=` | 短声明（新变量）/ 赋值（已有变量） | 循环体内用 `:=` 会遮蔽外层 err | 002 |
| 切片 vs 数组 | 动态视图（引用底层）/ 固定长度（值拷贝） | `len` 可变的是切片 | 002 |
| make vs new | 初始化切片/map/channel / 返回指针 | make 只用于三种内置类型 | 002 |
| 值接收者 vs 指针接收者 | 复制副本 / 可修改原值 | 含 Mutex/大 struct 用指针 | 003 |
| nil 指针 vs nil 接口 | 指针为空 / 接口二元组全空 | 塞 nil 指针进接口 ≠ nil 接口 | 003 |
| goroutine vs OS 线程 | 用户态 2KB 栈 / 内核态 MB 级栈 | `GOMAXPROCS` 管 P 不管 goroutine 数 | 004 |
| buffered vs unbuffered channel | 有容量可异步 / 发送即阻塞等接收 | `make(chan T, n)` 的 n | 003 |
| GOGC vs GOMEMLIMIT | GC 触发频率 / 内存软上限 | 容器里 GOMEMLIMIT 优先 | 004 |
| errors.Is vs errors.As | 判断是不是某个值 / 提取某个类型 | Is 用哨兵、As 用自定义类型 | 002/003 |
| go run vs go build | 编译并运行（临时二进制）/ 编译产出 | 部署用 build，开发用 run | 000 |
| context.WithCancel vs WithTimeout | 手动取消 / 到时自动取消 | WithTimeout 内部包了 WithCancel | 003 |
| pprof CPU vs heap | 谁在烧 CPU / 谁在占内存 | profile vs heap 两个 endpoint | 004 |

## 按症状反查

| 现象 | 大概是 | 去哪 |
| --- | --- | --- |
| `err != nil` 但值是 nil | 接口里塞了 nil 指针 | 003 §1 |
| Mutex 锁不住 | 值接收者复制了 Mutex | 003 §1（用指针接收者） |
| goroutine 数量一直涨 | HTTP 没设超时 / channel 阻塞 | 004 §13.1 |
| 容器 OOM 但堆没那么大 | GOMEMLIMIT 未设或 MaxIdleConnsPerHost 未调 | 004 §11 |
| p99 延迟高但 CPU 低 | 连接池太小 / TLS 握手频繁 | 004 §13.2 |
| `go vet` 报 copylocks | 值接收者复制了含锁的 struct | 改为指针接收者 |
| 测试数据竞争 `-race` 报告 | 多 goroutine 无同步读写 | 加锁或 channel |
| main 退出 goroutine 全没了 | 没有 WaitGroup / 没等信号 | 002 §11 |
| 静态二进制跑不了 CGO 依赖 | CGO_ENABLED=0 缺少纯 Go 实现 | 换纯 Go 库或启用 CGO |
| 容器里 CPU 高但 NumCPU 正常 | Go 1.24 前读宿主机核数 | 设 GOMAXPROCS 或升级 Go |
