# 碎片文档 —— 日常碎片信息收件箱（留存式）

> **定位**：随手记的想法、聊天要点、剪藏片段、待整理素材——**要留存的日常记录**都放这里。  
> **发布状态**：本目录已推送 GitHub 公开仓（2026-11-06 作者定），**写入即公开**，脱敏要求见下方第 3 条。  
> **与 tmp/ 的分界**：tmp 是随时可清空的草稿/下载件/中间产物；**碎片文档不清空**，是留存的原料库。  
> **与 _issues/ 的分界**：_issues 是待办与缺口登记（一条一文件、要关闭）；碎片是素材与记录，无需关闭。

## 规则

1. **命名**：`YYYYMMDD-主题.md`（同日多份加 `HHMMSS`）。快照类，**只增不改**（011 一）——补进展用追加。
2. **写法**：碎片允许零格式——一行结论、一段聊天粘贴、一条命令输出都行；原文的价值在"不通顺"里。想整理时交给 AI，**AI 只归位排版、不改写事实**（011 六）。
3. **脱敏（公开仓红线）**：本目录已推送公开仓，**写入即公开**——真实 IP / 主机名 / 网段 / 账号 / 口令 / 内部系统名一律替换为虚构值（011 脱敏铁律）；禁止把未脱敏原料直接落在这里。确需留存原始敏感片段时，放本地 `tmp/` 或 `.agents/` 层。
4. **归档**：定期（或需要时）提炼——教材价值进 `体系文档/`（走 003 SOP）、台账事实按 011 体例、待办进 `_issues/`；**提炼后碎片原文保留**，不删。
5. **不入统计**：本目录不计入根 README 任何数字，也不进体系文档目录树。
6. **AI 义务**：作者说"记一条碎片 / 整理一下今天的碎片"时，按上述规则落位；整理产出先给作者过目再定去向。
