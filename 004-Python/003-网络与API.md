## 3.1 requests 基础与超时（必设）

```python
import requests

resp = requests.get(
    "https://api.internal/v1/hosts",
    params={"env": "prod"},
    headers={"Authorization": f"Bearer {token}"},
    timeout=(3, 27),                 # ⚠️ 必设：(建连, 读响应)
)
resp.raise_for_status()              # 4xx/5xx 抛异常（同 subprocess check=True）
data = resp.json()
```

**超时是本节唯一的"必须"**：requests 默认**永不超时**——上游卡住时你的脚本就挂死（cron 里挂一整夜是经典事故）。二元组含义：`(3, 27)` = 建连最多 3 秒、读响应间隔最多 27 秒。`raise_for_status()` 把 HTTP 错误变成异常——与 001 §1.4 的异常纪律衔接。

## 3.2 Session 与认证

多次请求同一服务时用 `Session`（复用 TCP 连接 + 统一携带认证）：

```python
with requests.Session() as s:
    s.headers["Authorization"] = f"Bearer {token}"
    s.headers["Content-Type"] = "application/json"

    hosts = s.get(f"{base}/v1/hosts", timeout=(3, 27)).json()
    for h in hosts:
        s.post(f"{base}/v1/hosts/{h['id']}/check", json={"force": False}, timeout=(3, 27))
```

认证三种常见形态：**Bearer token**（上例，从环境变量取凭据——001 §1.6 纪律）、**Basic**（`s.auth = (user, pwd)`）、**自签证书内网**（`s.verify="/path/ca.pem"`——内网 CA 的正确信任姿势，而不是 `verify=False` 关校验）。

## 3.3 重试与退避

对接一切"偶尔抽风"的上游（内网 LB 后的服务、云 API）都要重试——标准做法是挂 urllib3 的 Retry 策略：

```python
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

retry = Retry(
    total=3,                              # 最多重试 3 次
    backoff_factor=1,                     # 间隔 1s → 2s → 4s
    status_forcelist=[500, 502, 503, 504], # 这些状态码才重试
    allowed_methods=["GET"],              # ⚠️ 只重试幂等方法
)
s.mount("https://", HTTPAdapter(max_retries=retry))
```

两条纪律：**只自动重试幂等方法**（GET）——POST 下单类请求盲重试 = 重复下单；**重试解决偶发，不解决持续故障**——持续 502 是下游的事（006 §6.4 的分段取证思维）。

## 3.4 实战：Prometheus HTTP API

调自家监控 API 是运维 Python 最高频的场景（「监控」002 的查询语义在这里复用）：

```python
import requests

def query_range(expr: str, start: str, end: str, step: str = "60s"):
    r = requests.get(
        "https://prometheus.internal/api/v1/query_range",
        params={"query": expr, "start": start, "end": end, "step": step},
        timeout=(3, 27),
    )
    r.raise_for_status()
    body = r.json()
    if body["status"] != "success":
        raise RuntimeError(f"query 失败：{body.get('error')}")
    return body["data"]["result"]

# 最近 1 小时各实例的 CPU 使用率
series = query_range('100 - avg by (instance)(rate(node_cpu_seconds_total{mode="idle"}[5m]))*100',
                     start="now-1h", end="now")
for s in series:
    print(s["metric"]["instance"], s["values"][-1][1])
```

通用模板三段式：**请求（带超时）→ 校验 `status == "success"` → 提取 `data.result`**——大多数监控/云 API 的返回结构都是这个形状，换 URL 换参数即可复用。

## 3.5 分页与限流：对接云与内部服务

**分页**：云 API 列表接口都要翻页，循环吃到空页为止：

```python
page, all_items = 1, []
while True:
    body = s.get(f"{base}/v1/hosts", params={"page": page}, timeout=(3, 27)).json()
    all_items.extend(body["items"])
    if page >= body["total_pages"]:
        break
    page += 1
```

**限流**：被 429 拒绝时按响应头退避（`Retry-After` 秒数），并在循环里加节流（每页 `time.sleep(0.2)`）——**对接云 API 的脚本默认把自己当"礼貌客户端"**。批量写入类操作同理分批，别一口气打满下游。

## 3.6 SSH 自动化：paramiko 与它的边界

paramiko 能用 Python 直接跑远程命令——但**边界先立住**：批量配置变更与多机编排，Ansible 是首选（「CICD」004/005）；paramiko 的合理场景是**单机、需编程逻辑的远程取数**（读一个文件、调一个远程接口拿结果继续判断）：

```python
import paramiko

client = paramiko.SSHClient()
client.set_missing_host_key_policy(paramiko.AutoAddPolicy())   # 内网可信环境
client.connect("web-1", username="ops", key_filename="~/.ssh/id_ed25519")
_, stdout, _ = client.exec_command("cat /etc/myapp/version", timeout=10)
print(stdout.read().decode().strip())
client.close()
```

凭据同 001 §1.6：密钥文件 + 受保护的路径，密码不进代码。**如果发现自己用 paramiko 写出了"对 50 台机器循环执行"**——停下，那是 Ansible 的活（005 §5.1 的三条路对照）。

## 3.7 六个坑

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | requests 不设 timeout | 脚本永久挂死 | timeout=(3, 27) 必设（3.1） |
| 2 | 不检查状态码 | 拿着 500 的 body 当数据 | raise_for_status() |
| 3 | 盲重试非幂等请求 | 重复下单/重复告警 | allowed_methods 限 GET（3.3） |
| 4 | verify=False 绕证书 | 加密通道形同虚设 | 挂内网 CA（3.2） |
| 5 | 分页漏页/死循环 | 数据不全或跑不完 | 以 total_pages/游标为准（3.5） |
| 6 | paramiko 写成批量框架 | 重新发明 Ansible 的轮子 | 单机场景用，批量走 Ansible（3.6） |

第 1 条展开：**没设超时的 requests 是"不会报错的 bug"**——它不抛异常、不写日志，只是永远等下去；cron 里挂死后表现为"今天的巡检没跑"，往往隔天才被发现。防御组合：每次 `requests` 调用带 timeout + 脚本整体再包一层外部超时（002 §2.1 的 `subprocess.run(timeout=)`，005 §5.5 的巡检器就是这么包巡检脚本的）。
