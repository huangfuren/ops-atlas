# Python 运维实战手册

> **定位**：面向运维场景的 Python 实战文档——不讲语言大全，讲"运维为什么用它、怎么用到能上线"。000 讲生态位与工具链，001–004 按能力分册（脚本基础 → 系统交互 → 网络API → 数据报表），005–006 收在自动化实战与工程化。  
> **读者**：会 Shell 与 Ansible（本库「CICD」004/005 水平）的运维人员，第一次系统学 Python。  
> **口径**：**Python 3.10+**（示例在 3.12 验证）；依赖用 **venv + pip**（uv 作新工具注记）；格式与静态检查用 **ruff**；**标准库优先**，第三方只引运维刚需（requests / paramiko / psutil）。  
> **更新**：2026-11-01  
> **术语表**：单独成册 → [00 术语表](00-术语表.md)。47 个术语 · 7 个缩写 · 12 对易混 · 12 条症状反查。

> **与「CICD」004/005 的分界**：批量配置变更的首选永远是 Ansible——Python 做它做不了的胶水（API 调用、数据加工、复杂判断），以及调用 Ansible 本身（005 §5.3）。  
> **与「Go」板块的分界**：常驻服务、高并发工具用 Go；Python 主打**生态粘合**——Ansible/ELK/云 SDK 全是 Python 生态，胶水脚本 20–500 行是它的舒适区。  
> **与「日志」005 的衔接**：运维脚本自己的日志也走 logging + 级别纪律——脚本输出进集中日志后同样可查。  
> **与「Linux」006 的衔接**：脚本接 cron/timer 的规范（退出码、日志、幂等）在那里立过，002 §2.6 是 Python 视角的落地。

## 阅读约定

1. **标准库优先**：能 `import json` 解决的不引第三方；每个第三方依赖都写明"为什么非它不可"。
2. **给输出**：命令与代码给预期输出/行为，读者靠输出判断自己对不对。
3. **凭据不进代码**：环境变量 / 凭据文件（与「CICD」002 §2.7、「日志」脱敏同源纪律）。
4. **脚本可重跑**：幂等是安全带（「SRE」004 §4.4 同源）——写完自测"连跑两遍结果一致"。
5. **每册结构统一**：目录 → 正文 → N 个坑 → 检查清单。可以顺序读，也可以只查某一节。
