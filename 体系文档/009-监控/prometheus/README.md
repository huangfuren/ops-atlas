# Prometheus 手册

> **定位**：以运维视角组织的一套 Prometheus 笔记，按「原理 → 取数 → 配置 → 运维」四条任务线分册，既能顺读入门，也能单篇查用。  
> **读者**：具备基础 Linux / HTTP 概念、第一次系统学 Prometheus 的运维人员。  
> **口径**：正文以 **2.53 为基线**，3.x 的行为差异集中在 [002 §2.15 迁移要点](002-数据与查询.md)，其他位置的 3.x 变化以 **3.x** 标出。具体版本能力以 `promtool --version` 与本机 `--help` 输出为准。  
> **更新**：2026-11-01

## 术语表

首次出现即使用，遇到不熟的词回这里查。

| 术语 | 含义 | 常见误解 |
| --- | --- | --- |
| **指标（metric）** | 被测量的东西的名字，如 `http_requests_total` | 以为指标=数值，其实指标只是名字 |
| **标签（label）** | 指标上的 key/value，用于区分维度，如 `code="200"` | 以为可以随便加，实际基数会爆 |
| **样本（sample）** | 一个 `(timestamp, value)` 点 | 以为存的是"每秒请求数"，其实多数是累计值 |
| **时间线 / series** | 指标名 + 全部 label 的唯一组合，构成一串样本 | 与"指标"混用。一个指标通常有几十上百条 series |
| **基数（cardinality）** | 活跃 series 的数量 | 以为跟指标个数有关，其实跟 label 取值组合数有关 |
| **抓取（scrape）** | Prometheus 主动 GET 目标 `/metrics` 并解析入库的动作 | 以为是一次性请求，实际是周期性重复 |
| **目标（target）** | 一个可被抓取的端点，即 `instance` | 与 job 混用 |
| **作业（job）** | 一组同类目标的逻辑分组，来自 `job_name` | 以为 job 是"任务实例" |
| **Exporter** | 把某种系统状态翻译成 `/metrics` 文本的进程 | 以为它是监控系统的一部分，其实只是数据源 |
| **TSDB** | Prometheus 自带的时序数据库 | 以为可以像 MySQL 那样随意改数据 |
| **WAL** | 预写日志，崩溃后靠它恢复最近数据 | 以为是备份，其实只保最近约 2 小时 |
| **Block** | 每 2 小时落盘的不可变数据块 | 以为可以单独删某几条数据 |
| **staleness** | 目标消失后指标被标记为"陈旧"的机制，约 5 分钟后不再返回 | 以为抓不到就等于没数据，实际会先"卡住"一会儿 |
| **lookback delta** | 瞬时查询向前回看的窗口，默认 5m | 以为是保留期，其实是"多久算过期" |

> **术语表**：单独成册 → [00 术语表](00-术语表.md)。51 个术语 · 6 个缩写 · 12 对易混 · 12 条症状反查。

## 已知限制

- **native histogram 只讲清了原理与开关**（002 §2.2、§2.15），**没有给埋点侧示例**——各语言 SDK 的启用方式不同，需要按 SDK 文档补。
- 告警演练（003 §3.11）**只给 webhook 一种接收端**。企业微信 / 钉钉机器人需要中间转换层，文中说明了原因但没有给完整转发实现。
- 早期"不含看板与规模化"的限制已由 005~008 分册补齐；K8s 场景由 009 补齐；Alertmanager 的集群部署与静默细节分散在 004 与 006，未单独立册。
