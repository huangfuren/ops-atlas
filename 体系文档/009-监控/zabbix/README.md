# Zabbix 手册

> **一句话**：传统 IT 与网络设备监控的主力工具——Zabbix 6.0 LTS 的部署、模板、告警、分布式与 API 自动化。  
> **读者**：管着物理机、虚拟机、交换机和混合云主机的运维；已有 Prometheus 但缺网络设备与 Windows 监控的团队。  
> **口径**：Zabbix 6.0 LTS（server / agent2 / proxy）；数据库 MySQL 8.0 或 PostgreSQL 13+；命令以 RHEL 8 系为例，Debian/Ubuntu 差异在节内注记。  
> **更新**：2026-11-06  
> **术语表**：单独成册 → [00 术语表](00-术语表.md)。71 个术语 · 8 个缩写 · 12 对易混 · 12 条症状反查。

## 体系总览

Zabbix 解决的是「非容器世界的统一监控」：SNMP 交换机、Windows 服务器、IPMI 硬件、JMX Java 应用，一套服务端全接。六册一条线，**一册只回答一个问题**。

| [001 架构与部署](001-架构与部署.md) | 装起来、跑通第一台主机 | 组件与端口 · 数据库初始化 · 前端时区 · agent2 主被动 · 首次纳管 |

| [003 触发器与告警动作](003-触发器与告警动作.md) | 什么情况该报、报给谁、怎么不刷屏 | 表达式函数 · 恢复表达式 · 依赖 · 动作与升级 · 媒体类型 · 维护窗口 |

> **与 Prometheus 的关系**：不是二选一。动态容器环境用 `prometheus/` 九册，传统 IT 与网络设备用本目录，两者可通过 exporter 或统一告警入口汇合（见 000「选型对照」）。

## 阅读约定

1. **每册结构统一**：目录 → 正文（每节开头一句承接上文）→ 坑表 → 检查清单 → 尾链。
2. **命令按版本给**：6.0 LTS 的路径与参数为准；7.0 的差异（如 API 令牌、部分前端路径）在节内注记，不混写。
3. **危险操作标后果**：删主机、清历史、改数据库都带 ⚠️ 与回滚路径。
4. **文字引用不带目录前缀**：写「监控」000，不写「009-监控」000。
