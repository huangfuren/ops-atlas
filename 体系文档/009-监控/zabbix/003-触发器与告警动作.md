## 1. 触发器表达式

上一册把数据采上来了；本节决定「什么样的数值算故障」。

### 1.1 基本语法与常用函数

一个触发器就是一条布尔表达式，成立即进入 PROBLEM：

```plain
min(/web-01/system.cpu.load[percpu,avg1],5m)>5
```

| 部分 | 含义 |
|---|---|
| `min` | 聚合函数，对窗口内取值 |
| `/web-01/system.cpu.load[percpu,avg1]` | 主机名 / 监控项 key |
| `5m` | 时间窗口 |
| `>5` | 比较阈值 |

常用函数按用途分：

| 用途 | 函数 | 说明 |
|---|---|---|
| 瞬时值 | `last()` | 最新一个值，最容易抖动 |
| 窗口极值 | `min()` `max()` | 窗口内最小/最大，抗抖动 |
| 窗口均值 | `avg()` | 适合负载、使用率 |
| 计数 | `count()` | 窗口内满足条件的次数 |
| 求和 | `sum()` | 流量、错误数累计 |
| 变化 | `change()` `abschange()` | 与上一个值的差 |
| 无数据 | `nodata()` | 窗口内没有新数据 |
| 时间 | `time()` `dayofweek()` | 只在特定时段生效 |
| 趋势 | `trendavg()` `trendmax()` | 按小时趋势算，适合长期基线 |

**阈值要带窗口**：`last(...)>90` 会被一次毛刺打醒；`avg(...,5m)>90` 才是「持续高」。CPU、内存、磁盘这类慢变量用 5~15 分钟窗口，端口 down、进程消失这类事件用 `last()`。

### 1.2 恢复表达式

默认「表达式不再成立」就算恢复。但有些场景需要单独定义，例如「CPU 高于 90 告警、低于 70 才恢复」，避免在阈值附近反复跳：

```plain
问题：avg(/web-01/system.cpu.util,5m)>90
恢复：avg(/web-01/system.cpu.util,5m)<70
```

不配恢复表达式的后果是**问题永远不关闭**——尤其是 `nodata` 或 `count` 类表达式，一旦成立可能再也不会自动变回不成立，告警列表越积越长。

### 1.3 未知状态与 nodata

采集断了，触发器拿不到新值，状态会变成「未知」（前端灰色），**不是正常**。默认情况下未知不产生告警，所以必须显式加一条：

```plain
nodata(/web-01/agent.ping,5m)=1
```

这条表达式覆盖的是「agent 失联」「网络断了」「监控项被禁用」三类情况。建议每个主机的核心 item 都配一条，否则最容易出现的漏报就是「监控自己挂了没人知道」。

## 2. 依赖、分级与抑制

上一节解决单条规则；本节解决「一次故障刷出几十条告警」。

### 2.1 触发器依赖

同一台主机上，网络断了会导致 CPU、内存、磁盘所有 item 都取不到，如果每条都配了 nodata，一次断网就是几十条告警。

依赖的语义是：**上游触发器处于 PROBLEM 时，下游触发器不生成事件**（仍求值、仍记录状态，只是不通知）。

```plain
上游：agent.ping 无数据（主机失联）
下游：CPU 高、磁盘满、进程数异常……
配置：下游依赖上游
```

依赖只能配在**同一主机**的触发器之间，跨主机要用「主机组 + 动作条件」或标签抑制。

### 2.2 严重级别与分级原则

| 级别 | 含义 | 响应 |
|---|---|---|
| Disaster | 业务全断 | 立即电话 |
| High | 核心功能受损 | 15 分钟内 |
| Average | 冗余失效、容量告警 | 1 小时内 |
| Warning | 趋势异常、需关注 | 当天 |
| Information | 变更、启停 | 不通知，只记录 |
| Not classified | 未分级 | 不允许长期存在 |

分级不是为了好看，是为了**路由**：Disaster/High 走电话 + 值班群，Average 走工单，Warning 进日报。全部设成 High 等于没有分级。

## 3. 告警动作与升级

上一节让告警不重复；本节让告警找到对的人。

### 3.1 动作的三段结构

`Alerts → Actions → Trigger actions`，一个动作由三部分组成：

| 段 | 配什么 | 例子 |
|---|---|---|
| Conditions | 什么事件进来 | 严重级别 ≥ Average、主机组 = 核心业务 |
| Operations | 进来后做什么 | 发消息给值班组，30 分钟后升级给主管 |
| Recovery operations | 恢复时做什么 | 发「已恢复」消息 |
| Update operations | 确认/留言时做什么 | 同步到工单系统 |

条件支持主机、主机组、触发器、标签、严重级别。**标签（tag）比主机组更灵活**：给主机打 `service=payment`，动作按标签路由，组织调整时不用改规则。

### 3.2 升级链

| 参数 | 作用 | 常见配法 |
|---|---|---|
| Default operation step duration | 每步间隔 | 30m |
| Steps | 从第几步到第几步 | 1~3 |
| Step 0 | 立即执行 | 发值班组 |
| Step 1~2 | 未确认未恢复时 | 发主管、发经理 |
| 恢复/更新操作 | 状态变化时 | 通知同组 |

没配 `Default operation step duration` 时，升级步骤不会按时推进——这是「配了升级但从来不发」的第一原因。

### 3.3 媒体类型

| 类型 | 适用 | 注意 |
|---|---|---|
| Email | 常规通知 | 要配 SMTP、发件人、TLS |
| Webhook | 钉钉/企微/Slack/工单 | 6.0 用 JavaScript 脚本，需测超时与证书 |
| Script | 自定义脚本 | 在 server 上执行，注意权限 |
| SMS | 电话告警 | 需网关，成本高 |

**只配动作不够**：用户必须挂媒体（User → Media），媒体类型必须启用，动作的 `Send to` 才能投递。三处任一缺失，表现都是「动作日志显示已发送，人没收到」。

## 4. 告警治理

上一节把告警发出去；本节让它长期可用，而不是三个月后全员屏蔽。

### 4.1 维护窗口

`Data collection → Maintenance` 按主机或主机组建窗口：

| 类型 | 行为 | 用途 |
|---|---|---|
| With data collection | 照常采集，不告警 | 滚动升级、重启演练 |
| Without data collection | 停采，不告警 | 设备下架、长期停机 |

选错类型会出现两种极端：维护期完全没数据（事后无法复盘），或维护期照常告警（窗口形同虚设）。

### 4.2 误报治理的五个动作

1. **加窗口**：单点阈值改 5 分钟均值。
2. **配恢复**：避免阈值附近反复跳。
3. **配依赖**：断网时只报根因。
4. **调阈值**：用近 30 天数据看 P95，不要拍脑袋。
5. **降级或转记录**：Information 级不通知，只进日报。

### 4.3 告警健康度的三个指标

| 指标 | 算法 | 健康区间 |
|---|---|---|
| 日均告警量 | 事件数 / 天 | 与团队规模匹配，突增要查 |
| 确认率 | 已确认 / 总告警 | 低于 50% 说明大量噪声 |
| 误报率 | 无效告警 / 总告警 | 高于 20% 必须治理 |

这三个数每周看一次，比事后抱怨「告警太多」有用。

## 5. 坑表

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | 告警反复跳 | 用 `last()` 单点判定 | 改 `avg/min` + 时间窗口 |
| 2 | 问题永远不恢复 | 未配恢复表达式，或表达式一旦成立不再变假 | 显式配恢复条件 |
| 3 | 采集断了但没有告警 | 未配 `nodata()`，未知状态不通知 | 核心 item 全部补 nodata |
| 4 | 一次断网刷几十条 | 未配触发器依赖 | 下游依赖 `agent.ping` |
| 5 | 依赖配反，真故障被吞 | 上游/下游搞反 | 依赖方向：根因在上，症状在下 |
| 6 | 动作配了但没人收到 | 用户未挂媒体 / 媒体类型未启用 / 条件不匹配 | 三处逐一核对，看动作日志 |
| 7 | 升级链从不触发 | 未配 step duration 或 Steps 范围错 | 设 30m + Steps 1~3 |
| 8 | 维护期数据缺失 | 选了 Without data collection | 升级演练选 With data collection |
| 9 | Webhook 偶发失败 | 脚本超时、证书、目标限流 | 加超时与重试，记录返回码 |
| 10 | 远程命令不执行 | agent 未开 `EnableRemoteCommands` | 慎用远程命令，优先走工单/自动化平台 |

## 6. 检查清单

| # | 问题 | 判据 |
|---|---|---|
| 1 | 关键触发器都带时间窗口吗？ | CPU/内存/磁盘不用裸 `last()` |
| 2 | 每条触发器都有恢复路径吗？ | 手工造一次故障，确认能自动恢复 |
| 3 | 核心 item 配了 nodata 吗？ | 停 agent 5 分钟，能收到失联告警 |
| 4 | 依赖方向对吗？ | 拔网线只收到一条根因告警 |
| 5 | 动作条件用标签还是主机组？ | 组织变动不需要改规则 |
| 6 | 升级链做过演练吗？ | 造一条不确认的告警，按时收到第二级通知 |
