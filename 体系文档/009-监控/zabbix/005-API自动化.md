## 1. API 基础与认证

前面四册都在讲「怎么配」；本节开始讲「怎么让机器替你配」。

### 1.1 一个端点、一种协议

所有请求都发到同一个地址：

```plain
http://<zabbix-server>/api_jsonrpc.php
Content-Type: application/json-rpc
```

请求体是 JSON-RPC 2.0，四个字段：

```json
{"jsonrpc":"2.0","method":"apiinfo.version","params":{},"id":1}
```

`apiinfo.version` 不需要认证，是验证连通性的第一条命令。

### 1.2 6.0 与 7.0 的认证差异

| | 6.0 LTS | 7.0 LTS |
|---|---|---|
| 登录 | `user.login` 换 sessionid | 同左，或直接用 API token |
| 后续请求 | 顶层 `"auth": "<sessionid>"` | 请求头 `Authorization: Bearer <token>` |
| 过期 | 空闲约 15 分钟失效 | 令牌可设长期 |

写脚本时把认证方式抽成一层，升级 7.0 只改这一处，不要让每个方法都带 `auth`。

### 1.3 最小权限

不要用 `Admin` 跑自动化。6.0 支持用户角色（User roles），给自动化账号一个只含 `Hosts → Read/Write`、`Problems → Read` 的角色即可。密码或令牌放环境变量，不进代码库。

## 2. 按任务选方法

上一节打通了认证；本节按「你要做什么」列方法，不背 API 全表。

### 2.1 查询类

| 任务 | 方法 | 关键参数 |
|---|---|---|
| 查主机 | `host.get` | `filter:{host:[...]}`、`selectInterfaces`、`selectParentTemplates` |
| 查监控项 | `item.get` | `hostids`、`search:{key:...}`、`output` |
| 查触发器 | `trigger.get` | `hostids`、`min_severity`、`selectHosts` |
| 查当前问题 | `problem.get` | `recent:true`、`severities`、`selectAcknowledges` |
| 查历史值 | `history.get` | `history`（值类型）、`time_from`、`time_till`、`limit` |
| 查模板 | `template.get` | `filter:{host:[...]}` |
| 查代理 | `proxy.get` / `proxygroup.get` | `output:extend` |

`history.get` 的 `history` 参数必须与监控项的值类型一致：`0` 浮点、`1` 字符、`3` 无符号整数、`4` 文本。类型填错返回空数组，不报错——这是最常见的「查不到数据」原因。

### 2.2 写入类

| 任务 | 方法 | 必填 |
|---|---|---|
| 建主机 | `host.create` | `host`、`groups`、`interfaces`、`templates` |
| 改主机 | `host.update` | `hostid` + 要改的字段 |
| 删主机 | `host.delete` | `hostids`（⚠️ 连带删除历史，先备份） |
| 建维护窗口 | `maintenance.create` | `name`、`active_since/till`、`hostids`、`timeperiods` |
| 批量确认问题 | `event.acknowledge` | `eventids`、`action`、`message` |

`host.create` 的 `interfaces` 至少要有一个，否则报 `No interfaces defined`；主动模式的主机也要给一个接口对象，IP 可为空。

## 3. Python 封装与实战

上一节知道了方法名；本节写一个能复用的最小客户端。

### 3.1 一个类包住认证与错误

```python
import json, os, requests

class Zabbix:
    def __init__(self, url, user, password):
        self.url = url.rstrip("/") + "/api_jsonrpc.php"
        self.s = requests.Session()
        self.s.headers.update({"Content-Type": "application/json-rpc"})
        self.id = 0
        self.auth = None
        self.login(user, password)

    def call(self, method, params=None):
        self.id += 1
        payload = {"jsonrpc": "2.0", "method": method,
                   "params": params or {}, "id": self.id}
        if self.auth:
            payload["auth"] = self.auth
        r = self.s.post(self.url, data=json.dumps(payload), timeout=30)
        r.raise_for_status()
        data = r.json()
        if "error" in data:
            raise RuntimeError(f"{data['error']['code']}: {data['error']['data']}")
        return data["result"]

    def login(self, user, password):
        self.auth = self.call("user.login", {"username": user, "password": password})

    def logout(self):
        self.call("user.logout", {})
        self.auth = None
```

```python
z = Zabbix("https://monitor.example.com", os.environ["ZBX_USER"], os.environ["ZBX_PASS"])
print(z.call("apiinfo.version"))
```

### 3.2 幂等纳管：先查后建

脚本要能重复执行，不能第二次跑就报 `Host already exists`：

```python
def ensure_host(z, host, ip, group_id, template_id):
    found = z.call("host.get", {"filter": {"host": [host]}, "output": ["hostid"]})
    if found:
        z.call("host.update", {"hostid": found[0]["hostid"], "templates": [{"templateid": template_id}]})
        return found[0]["hostid"], "updated"
    res = z.call("host.create", {
        "host": host,
        "groups": [{"groupid": group_id}],
        "interfaces": [{"type": 1, "main": 1, "useip": 1, "ip": ip, "dns": "", "port": "10050"}],
        "templates": [{"templateid": template_id}],
    })
    return res["hostids"][0], "created"
```

批量时把多个主机对象放进一个数组传给 `host.create`，失败会**整批回滚**——所以要么先校验全部数据，要么一台一个事务。

### 3.3 导出当前问题做日报

```python
problems = z.call("problem.get", {
    "output": ["eventid", "name", "severity", "clock"],
    "recent": True,
    "sortfield": ["eventid"], "sortorder": "DESC", "limit": 200,
})
for p in problems:
    print(p["severity"], p["name"])
```

`recent: true` 返回「最近发生过、可能已恢复」的问题；只要当前未恢复的，去掉该参数并加 `acknowledged` 等过滤。

## 4. 对接 CMDB 与流水线

上一节有了可复用客户端；本节看它放进什么流程。

### 4.1 CMDB 每日同步

```plain
CMDB 导出（主机名/IP/负责人/业务线）
  → 逐条 ensure_host（先查后建）
  → 按业务线打 tag、分配到主机组
  → 已下线主机改 disabled，不直接删（保留历史）
```

关键原则：**同步只增改不删**。直接 `host.delete` 会连带删历史与事件，事后无法追溯；下架先禁用，观察一个保留期再清理。

### 4.2 发布时自动开维护窗口

```python
z.call("maintenance.create", {
    "name": f"release-{app}-{ts}",
    "active_since": start, "active_till": end,
    "hostids": host_ids,
    "timeperiods": [{"timeperiod_type": 0, "start_date": start, "period": 1800}],
})
```

配合 CI/CD 的发布阶段：开始前建窗口，结束后删除窗口（`maintenance.delete`）。窗口类型选「With data collection」，发布期间的数据仍要保留。

### 4.3 安全与稳定性

| 风险 | 做法 |
|---|---|
| 凭据泄漏 | 环境变量/密钥管理，不写进仓库 |
| 明文传输 | API 走 HTTPS，禁用 HTTP |
| 权限过大 | 专用角色，只给需要的实体 |
| 调用过量 | 加 `limit`、分页、失败重试退避 |
| 误删 | 删除类操作先 dry-run 打印清单，人工确认 |

## 5. 坑表

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | `Session terminated, re-login` | 未带 `auth` 或空闲超时 | 每次调用检查 auth，失效自动重登 |
| 2 | `Invalid params` | 6.0 用 `username`，老脚本用 `user` | 按版本文档改参数名 |
| 3 | 7.0 上报 `auth` 无效 | 7.0 改 Bearer 令牌 | 升级时改认证层，不动业务代码 |
| 4 | `No interfaces defined` | `host.create` 缺 interfaces | 主动模式也给一个接口对象，IP 可空 |
| 5 | 批量建主机一半失败 | 一条数据不合法导致整批回滚 | 先全量校验，或逐台提交 |
| 6 | `history.get` 返回空 | `history` 值类型与 item 不匹配 | 先查 `item.get` 的 `value_type` |
| 7 | 大查询超时或内存暴涨 | 未加 `limit`、一次取全量 | 分页 + 时间窗，必要时用趋势表 |
| 8 | `host.delete` 后历史没了 | 删除连带清理 | 下架改 disabled，保留期内不删 |
| 9 | 脚本并发跑锁表 | 多个实例同时写 | 加文件锁/队列，串行执行 |
| 10 | Webhook 与 API 混淆 | 前者是告警投递，后者是管理接口 | 告警走媒体类型，管理走 JSON-RPC |

## 6. 检查清单

| # | 问题 | 判据 |
|---|---|---|
| 1 | 认证方式抽成一层了吗？ | 升级 7.0 只改一处 |
| 2 | 自动化账号是最小权限吗？ | 不是 Admin，角色只含必需实体 |
| 3 | 脚本可重复执行吗？ | 连跑两次结果一致，不报已存在 |
| 4 | 删除类操作有 dry-run 吗？ | 先打印清单再执行 |
| 5 | 大查询有限制吗？ | 都带 `limit` 与时间窗 |
| 6 | 凭据不在代码里吗？ | 仓库搜不到密码与令牌 |
