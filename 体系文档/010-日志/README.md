> **与「监控」的分界**：监控管指标与告警（发现异常），本册管日志（解释异常）——告警响了来日志里取证。链路追踪（第三支柱）在 001 §0.1 只立概念，深入见「链路」板块 111~124。  
> **与「容器」114 的衔接**：容器日志打 stdout 的纪律在那里立了，本册 111 的 DaemonSet 采集是它的下游。  
> **与「Linux」122 的衔接**：journald/rsyslog/logrotate 管"本机日志"，本册管"跨机器集中"——本机纪律是集中的前提。

## 阅读约定

1. **主线 EFK、对照 Loki**：概念讲一遍，两条路线写法并排给；只用轻量路线的读者可跳读 112/113。
2. **给输出**：命令与查询都给预期结果形态，读者靠输出判断自己对不对。
3. **密钥不进配置仓库**：ES 的账号、API key 走凭据管理（同「CICD」112 §2.7 的纪律）。
4. **危险操作先说后果**：删索引、改 ILM、关闭副本，一律先写会丢什么。
5. **成本是设计参数**：每一册都把"这会让日志量/存储怎么变"写在决策旁边。
6. **每册结构统一**：目录 → 正文（每节开头一句承接上文）→ N 个坑 → 检查清单。可以顺序读，也可以只查某一节。
