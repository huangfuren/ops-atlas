# 日志体系手册

> **定位**：可观测性第二支柱的集中日志文档。000 讲三支柱与两条路线，001–004 按组件分册（采集 → 存储 → 查询 → 轻量对照），005–006 收在规范与排障——每一册对应一类真实任务。  
> **读者**：会 Linux 日志基础（「Linux」006 册的 journald/rsyslog/logrotate）、容器应用日志打 stdout（「容器」004）的运维人员，第一次搭集中日志。  
> **口径**：主线 **Filebeat 8.x → Elasticsearch 8.x → Kibana 8.x**；轻量对照路线 **Loki 3.x + Promtail/Alloy + Grafana**；K8s 采集以 DaemonSet 形态为准（与「容器」009 衔接）。  
> **更新**：2026-11-01  
> **术语表**：单独成册 → [00 术语表](00-术语表.md)。64 个术语 · 10 个缩写 · 14 对易混 · 14 条症状反查。

从「日志为什么值得集中」到「排障与成本治理」，三块七册。**一册只回答一个问题，一个问题只在一册里答。**

> **与「监控」的分界**：监控管指标与告警（发现异常），本册管日志（解释异常）——告警响了来日志里取证。链路追踪（第三支柱）在 000 §0.1 只立概念，深入建议单独成文。  
> **与「容器」004 的衔接**：容器日志打 stdout 的纪律在那里立了，本册 001 的 DaemonSet 采集是它的下游。  
> **与「Linux」006 的衔接**：journald/rsyslog/logrotate 管"本机日志"，本册管"跨机器集中"——本机纪律是集中的前提。

## 阅读约定

1. **主线 EFK、对照 Loki**：概念讲一遍，两条路线写法并排给；只用轻量路线的读者可跳读 002/003。
2. **给输出**：命令与查询都给预期结果形态，读者靠输出判断自己对不对。
3. **密钥不进配置仓库**：ES 的账号、API key 走凭据管理（同「CICD」002 §2.7 的纪律）。
4. **危险操作先说后果**：删索引、改 ILM、关闭副本，一律先写会丢什么。
5. **成本是设计参数**：每一册都把"这会让日志量/存储怎么变"写在决策旁边。
6. **每册结构统一**：目录 → 正文（每节开头一句承接上文）→ N 个坑 → 检查清单。可以顺序读，也可以只查某一节。
