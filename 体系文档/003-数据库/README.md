> **定位**：以 MySQL 为主线、按运维职责编排的数据库文档。000 是板块地图，010 讲选型与换库，001–008 讲怎么管好一个 MySQL，009 讲换了库差别在哪——每一篇对应一类真实任务。

## 阅读约定

1. **主线是 MySQL 8.0**：001–008 全部以 MySQL 为例；PG / Redis / MongoDB 的运维差异集中在 009，通用能力的平移关系见 000 §0.14。
2. **运维视角**：不教业务开发写 SQL，只保证你看懂慢 SQL、执行安全变更、出事知道看哪。
3. **给输出**：能给出命令输出的都给，读者靠输出判断自己对不对。
4. **危险操作先说后果**：`DROP` / `TRUNCATE`、不带 `WHERE` 的 `UPDATE`、生产开 general log，一律先写后果再写标准姿势。
5. **改动必有回滚**：参数与配置修改给前后验证命令，并写明改错了怎么退。
6. **每篇结构统一**：目录 → 正文（每节开头一句承接上文）→ N 个坑 → 检查清单。可以顺序读，也可以只查某一节。
