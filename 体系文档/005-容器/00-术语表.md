## 000 容器全貌

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 容器 | container | 被namespace和cgroup框起来的**一个进程**，带独立的根文件系统视图 |
| 镜像 | image | 容器的只读模板，分层存储。镜像跑起来才是容器 |
| 容器 vs 虚机 | container vs VM | 虚机虚拟整台机器带内核，容器共享宿主内核只隔离进程——所以秒级启动、密度高 |
| Docker | Docker | 最流行的容器引擎。日常说「docker 跑个容器」的 docker 就是它 |
| containerd | containerd | 从 Docker 拆出来的底层运行时，K8s 通过 CRI 直接用它；Docker 本身也建立在它上面 |
| runc | runc | 真正创建容器进程的那一小步：按 OCI 规范把 namespace 和 cgroup 配好再 exec |
| OCI | Open Container Initiative | 镜像与运行时的开放标准。有 OCI 标志的镜像到处能跑 |
| CRI | Container Runtime Interface | K8s 对容器运行时的统一接口。dockershim 移除后，K8s 直连 containerd |
| Kubernetes（K8s） | Kubernetes | 容器编排系统：一组机器上的容器由它统一调度、自愈、扩缩 |
| 编排 | orchestration | 多机容器的调度、自愈、伸缩、发现的统称。单机用 Docker，多机就要编排 |
| 控制平面 / 数据平面 | control plane / data plane | K8s 里「做决定的组件」（API/scheduler/controller）与「干活的组件」（kubelet/容器） |
| 云上托管 K8s | managed K8s | ACK / EKS / TKE：控制平面云厂商管，你只管节点和负载。版本升级节奏与自建不同 |

## 缩写速查

读报错、看 YAML 时按字母找。

| 缩写 | 全称 | 意思与出处 |
| --- | --- | --- |
| CNI | Container Network Interface | Pod 网络插件接口（006） |
| CRI | Container Runtime Interface | K8s 对容器运行时的接口，对接 containerd（000） |
| CSI | Container Storage Interface | 存储插件接口（007） |
| CRUD | Create / Read / Update / Delete | 增删改查（泛用） |
| HPA | Horizontal Pod Autoscaler | 水平自动扩缩（008） |
| K8s | Kubernetes | 容器编排系统（全册） |
| LB | Load Balancer | 负载均衡（006） |
| OOM | Out Of Memory | 内存耗尽被杀，K8s 里表现为 OOMKilled / 137（008 / 009） |
| OCI | Open Container Initiative | 镜像与运行时开放标准（000） |
| PVC / PV | PersistentVolumeClaim / PersistentVolume | 存储申请 / 存储资源（007） |
| QoS | Quality of Service | Guaranteed / Burstable / BestEffort 三档（008） |
| RBAC | Role-Based Access Control | 基于角色的权限控制（生产实践） |
| SC | StorageClass | 存储类，动态供给 PV 的模板（007） |
| VPA | Vertical Pod Autoscaler | 纵向（改 requests/limits）自动扩缩，与 HPA 相对（008 注记） |

## 最容易混的 16 对

| 容易混 | 一句话差别 | 怎么确认 | 册 |
| --- | --- | --- | --- |
| 镜像 vs 容器 | 只读模板 / 跑起来的进程 | `docker images` vs `docker ps` | 001 |
| CMD vs ENTRYPOINT | 默认参数 / 程序本体 | `docker run img arg` 覆盖的是 CMD | 001 / 002 |
| COPY vs ADD | 纯拷贝 / 还会解压与拉 URL | 能用 COPY 就用 COPY | 002 |
| volume vs bind mount | Docker 管理的卷 / 宿主任意目录 | `docker volume ls` 看得到的是前者 | 003 |
| compose `depends_on` vs 就绪 | 只管启动顺序 / 不管服务可用 | 应用连不上库，多半是没等就绪 | 004 |
| Pod vs Deployment | 裸 Pod 没人管死活 / Deployment 自愈与滚动 | 被 `kubectl delete pod` 后没重建的就是裸 Pod | 005 |
| Deployment vs ReplicaSet | 管版本滚动 / 只管副本数 | `rollout history` 记录在 Deployment 上 | 005 / 008 |
| Service vs Ingress | 四层稳定入口 / 七层路由规则 | 按域名路径分流的是 Ingress | 006 |
| ClusterIP vs NodePort vs LoadBalancer | 仅集群内 / 节点端口 / 云 LB | 对外访问选后两者或 Ingress | 006 |
| ConfigMap vs Secret | 普通配置 / 敏感配置 | 值都是 base64，区别在权限与用途 | 007 |
| emptyDir vs hostPath | Pod 生命周期 / 节点目录 | 调度换节点后还在的是 hostPath | 007 |
| PV vs PVC | 存储资源 / 使用申请 | Pod 只认 PVC | 007 |
| requests vs limits | 调度申请量 / 运行上限 | `describe node` 看 allocation，OOM 看 limits | 008 |
| liveness vs readiness | 失败重启容器 / 失败摘出流量 | 重启次数涨看 liveness，流量进不来看 readiness | 008 |
| 滚动 vs 蓝绿 | 逐步替换一套资源 / 两套环境整切 | 回滚方式不同：undo vs 切回旧版 | 008 / CICD 007 |
| cordon vs drain | 拒绝新调度 / 连存量一起迁走 | 维护节点用 drain | 009 |

## 按症状反查

| 现象 | 大概是 | 去哪 |
| --- | --- | --- |
| 容器起完立刻退出 | 启动命令不是前台进程 / 配置错误秒退 | 001 §1.6 / §1.7 |
| `docker stop` 卡 10 秒才停 | PID 1 不转发信号（shell 形式启动） | 001 §1.7 |
| 容器里改的文件重启就没了 | 写进了可写层，数据没进卷 | 001 / 003 |
| 构建一次十几分钟 | 缓存被前面易变指令打断 / 没配 .dockerignore | 002 |
| 镜像 1GB+ 瘦不下来 | 没多阶段构建 / 用了全量基础镜像 | 002 |
| 磁盘被 Docker 吃满 | 容器日志没轮转 + 悬空镜像堆积 | 004 |
| compose 起了但应用连不上数据库 | depends_on 只管顺序，没等就绪 | 004 |
| Pod 一直 Pending | 资源不足 / 亲和性 / PVC 绑不上 | 009 |
| ImagePullBackOff | tag 错 / 私库 secret 缺 / 加速器不通 | 009 |
| CrashLoopBackOff | 应用崩溃，看 `logs --previous` | 009 |
| Pod 反复重启，exit 137 | OOMKilled，超了 limits | 008 / 009 |
| Service 访问不通 | Endpoints 为空 / label 不匹配 / 探针没绪 | 006 |
| Ingress 域名 404 | 规则路径不匹配 / Controller 没装 | 006 |
| 改了 ConfigMap 应用没变化 | 挂载的文件有同步延迟 / 应用不热加载，要滚动 | 007 |
| 节点 NotReady，Pod 大量驱逐 | kubelet/容器运行时挂了或资源耗尽 | 009 |
| 想维护节点不中断服务 | cordon + drain，确认 PodDisruptionBudget | 009 |
