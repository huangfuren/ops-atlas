# 容器与编排手册

> **一句话**：从 Docker 单机到 Kubernetes 集群的容器运维体系——板块级管领域地图，`docker/` 管单机容器，`k8s/` 管集群编排。  
> **读者**：会 Linux 基本操作、手动装过服务的运维人员，第一次系统学容器与 K8s。  
> **口径**：**Docker CE 24+ / containerd 运行时 / overlay2**；**Kubernetes 1.28+**，以 kubeadm 自建集群为主线，云上托管（ACK / EKS / TKE）差异只在相关处注记；命令以 `docker` 与 `kubectl` 为准，不依赖图形界面。  
> **更新**：2026-11-08  
> **术语表**：三份分工——板块级 [00 术语表](00-术语表.md)（领域词与跨册导航）；Docker 专有词 [docker/00](docker/00-术语表.md)；K8s 专有词 [k8s/00](k8s/00-术语表.md)。

## 体系总览

板块分三层：**板块级**管领域地图与概念，`docker/` 管单机容器（镜像、构建、数据、编排、网络底层、运行时），`k8s/` 管集群编排（架构、网络、存储、发布、排障、安全、安装、Helm）。**一册只回答一个问题，一个问题只在一册里答。**

|---|---|---|

> **与「网络」008 的分界**：008 从协议视角讲「包在容器网络里怎么走」，本板块讲「怎么配、怎么管、怎么排障」。  
> **与「CICD」的分界**：CI 产出镜像、CD 把镜像部署到集群——构建与流水线在 CICD 册，运行与编排在本板块；镜像仓库（Harbor）也在 CICD 006。  
> **与「Linux」002 的衔接**：cgroup、namespace、进程信号是容器的一切底层，读 docker/001 前建议先过 02 册 §2。

## 阅读约定

1. **先 Docker 后 Kubernetes**：`docker/` 线是单机地基，`k8s/` 线上集群；跳过 Docker 直接学 K8s，排障时会缺一整层直觉。
2. **给输出**：命令都给预期输出，读者靠输出判断自己对不对。
3. **YAML 给完整可运行片段**：不写 `...省略...`，每个清单都能 `kubectl apply` 复现。
4. **危险操作先说后果**：`docker system prune`、强制删除 PV、etcd 操作，一律先写会丢什么。
5. **改动必有回滚**：K8s 的变更有 `rollout undo`，Docker 的变更靠 Compose 文件进 Git——回滚路径写在每个操作旁边。
6. **每册结构统一**：目录 → 正文 → N 个坑 → 排错路径 → 检查清单 → 尾链。可以顺序读，也可以只查某一节。
