板块分三层：**总览区**（001 全貌 + 002 方法论 + 003 全景图）管地图与方法，`110-Docker/` 管单机容器（镜像、构建、数据、编排、网络底层、运行时），`120-K8s核心/` + `130-K8s进阶与交付/` 管集群编排（架构、网络、存储、发布、排障 + 调度、Ingress、安全、安装、Helm）。**一册只回答一个问题，一个问题只在一册里答。**

> **与「网络」125 的分界**：125 从协议视角讲「包在容器网络里怎么走」，本板块讲「怎么配、怎么管、怎么排障」。  
> **与「CICD」的分界**：CI 产出镜像、CD 把镜像部署到集群——构建与流水线在 CICD 册，运行与编排在本板块；镜像仓库（Harbor）也在 CICD 123。  
> **与「Linux」112 的衔接**：cgroup、namespace、进程信号是容器的一切底层，读 111 前建议先过 Linux 112 §2。

## 阅读约定

1. **先 Docker 后 Kubernetes**：`110-Docker/` 线是单机地基，`120/130` 线上集群；跳过 Docker 直接学 K8s，排障时会缺一整层直觉。
2. **给输出**：命令都给预期输出，读者靠输出判断自己对不对。
3. **YAML 给完整可运行片段**：不写 `...省略...`，每个清单都能 `kubectl apply` 复现。
4. **危险操作先说后果**：`docker system prune`、强制删除 PV、etcd 操作，一律先写会丢什么。
5. **改动必有回滚**：K8s 的变更有 `rollout undo`，Docker 的变更靠 Compose 文件进 Git——回滚路径写在每个操作旁边。
6. **每册结构统一**：目录 → 正文 → N 个坑 → 排错路径 → 检查清单 → 尾链。可以顺序读，也可以只查某一节。
