# 容器与编排手册

> **定位**：从 Docker 单机到 Kubernetes 集群的容器运维文档。000 讲生态全景，001–004 讲把一台机器上的容器管好，005–009 讲把一组机器上的容器管好——每一册对应一类真实任务。  
> **读者**：会 Linux 基本操作、手动装过服务的运维人员，第一次系统学容器与 K8s。  
> **口径**：**Docker CE 24+ / containerd 运行时 / overlay2**；**Kubernetes 1.28+**，以 kubeadm 自建集群为主线，云上托管（ACK / EKS / TKE）差异只在相关处注记；命令以 `docker` 与 `kubectl` 为准，不依赖图形界面。  
> **更新**：2026-10-31  
> **术语表**：单独成册 → [00 术语表](00-术语表.md)。96 个术语 · 14 个缩写 · 16 对易混 · 16 条症状反查。

## 阅读约定

1. **先 Docker 后 Kubernetes**：000–004 是单机地基，005 起才上集群；跳过 001–004 直接学 K8s，排障时会缺一整层直觉。
2. **给输出**：命令都给预期输出，读者靠输出判断自己对不对。
3. **YAML 给完整可运行片段**：不写 `...省略...`，每个清单都能 `kubectl apply` 复现。
4. **危险操作先说后果**：`docker system prune`、强制删除 PV、etcd 操作，一律先写会丢什么。
5. **改动必有回滚**：K8s 的变更有 `rollout undo`，Docker 的变更靠 Compose 文件进 Git——回滚路径写在每个操作旁边。
6. **每册结构统一**：目录 → 正文（每节开头一句承接上文）→ N 个坑 → 排错路径 → 检查清单。可以顺序读，也可以只查某一节。
