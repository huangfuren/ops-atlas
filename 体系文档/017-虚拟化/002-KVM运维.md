## 1. 架构：KVM/QEMU/libvirt

| 组件 | 角色 |
|---|---|
| **KVM** | 内核模块——把 Linux 内核变成 hypervisor，负责 CPU/内存虚拟化加速 |
| **QEMU** | 用户态进程——设备模拟（磁盘/网卡/显卡），每个 VM 一个 qemu 进程 |
| **libvirt** | 管理层——统一 API 守护进程 libvirtd，virsh/virt-manager 都走它 |
| **virtio** | 半虚拟化驱动——VM 看到的"专为虚拟化设计"的设备，性能远高于全模拟 |

关系一句话：**QEMU 模拟硬件，KVM 加速执行，libvirt 统一管理，virtio 提速**——四件套齐了才是生产级 KVM。

## 2. 虚拟机管理：virsh

每个 VM 是一份 **libvirt XML**（`virsh dumpxml vm` 可见）：定义 CPU/内存/磁盘/网卡/设备。常用命令：

```bash
virsh list --all                      # 全部虚拟机
virsh start / shutdown / destroy vm   # 启动 / 优雅关机 / ⚠️ 强制断电
virsh autostart vm                    # 宿主机重启后自启
virsh dumpxml vm > vm.xml             # 导出定义（备份用）
virsh edit vm                         # 编辑 XML（语法自动校验）
virsh console vm                      # 串口控制台（无网络时的救命通道）
virsh vcpuinfo vm                     # vCPU 映射
```

**纪律**：XML 是虚拟机的"定义文件"——变更走 `virsh edit`（或配置管理生成），改完 `virsh dumpxml` 备份归档。

## 3. 网络：NAT 与网桥

| 模式 | 机制 | 场景 |
|---|---|---|
| **NAT（默认 virbr0）** | VM 借宿主机地址转换出网，外部进不来 | 测试机 |
| **网桥（bridge）** | VM 直接连入物理网段，获得与宿主同网段的独立 IP | **生产标准**——VM 像一台真机器 |

网桥生产配置（宿主机网卡 eno1 变成桥成员）：

```bash
# nmcli 方式
nmcli con add type bridge ifname br0 con-name br0
nmcli con add type bridge-slave ifname eno1 master br0
nmcli con up br0
```

VM XML 里接口类型改为 `<interface type='bridge'><source bridge='br0'/>`。排障顺序：宿主机 `brctl`/`ip link` 看桥与成员 → VM 内看网卡 → 防火墙。

## 4. 存储：磁盘格式与存储池

| 格式 | 特点 | 场景 |
|---|---|---|
| **qcow2** | 写时复制、支持内部快照、压缩 | 默认选择 |
| **raw** | 裸格式，性能最好、无特性 | 高 IO 需求 + 外部备份方案 |
| LVM 卷 | 逻辑卷做 VM 磁盘 | 性能与快照分离管理 |
| Ceph RBD | 分布式块存储 | 集群化虚拟化平台（衔接「云平台」004 思想） |

存储池（storage pool）统一管理磁盘位置；磁盘格式转换：`qemu-img convert -O qcow2 old.raw new.qcow2`（顺带压缩）。

**快照**：`virsh snapshot-create-as vm snap1`（内部快照，qcow2 内）——⚠️ 大规模生产用**外部快照**或存储层快照；内部快照回滚 `virsh snapshot-revert`。**快照不是备份**（001 同口径）：qcow2 链依赖母盘，备份用 `virt-backup` 等独立副本方案。

## 5. 迁移与性能

**热迁移（live migration）**：运行中的 VM 搬到另一台宿主机——

```bash
virsh migrate --live vm qemu+ssh://dst-host/system
# 前提：共享存储（或 --copy-storage-all）+ 两端 libvirt 版本/CPU 兼容（可用 EVC 思路的 cpu model 基线）
```

性能三件套：

| 手段 | 做什么 |
|---|---|
| **virtio** | 磁盘（virtio-blk/SCSI）与网卡（virtio-net）全部用半虚拟化驱动 |
| **CPU 亲和** | 大 VM 的 vCPU pin 到指定物理核，避免调度抖动；NUMA 对齐（`numactl`/XML numa 节点） |
| **大页** | 巨型页（hugepages）减少 TLB miss——数据库类大内存 VM 收益明显 |

## 6. 坑表

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 用全模拟设备（e1000/IDE） | 性能只有 virtio 的几分之一 | 磁盘/网卡一律 virtio |
| 2 | 快照链过长 | 磁盘暴涨、性能劣化、回滚牵一发动全身 | 定期合并（blockpull）或快照≤必要时长 |
| 3 | virsh destroy 当关机用 | 相当于拔电源，文件系统损坏 | shutdown；destroy 只用于无响应救援 |
| 4 | 磁盘镜像放系统盘目录 | 根分区打满拖垮宿主机 | 独立存储池/数据盘 |
| 5 | 无 CPU 基线直接热迁移 | 目标机指令集不同导致 VM 崩溃 | 集群统一 cpu model 基线（host-passthrough 慎用） |
| 6 | 宿主机 OOM 杀掉 qemu 进程 | VM 直接"断电" | 宿主机内存超分要克制 + qemu 进程保护 |
