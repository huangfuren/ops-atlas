# 00 术语表

> **这一文档回答**：Java 应用运维的词是什么意思、两个混用词的分界、「只知道现象不知道翻哪册」往哪走。  
> **怎么用**：按名字（按主题分组）、按缩写（缩写速查）、按现象（症状反查）。  
> **只有一句话**：要代码级原理回开发文档；这里只保证你「认得出、分得清、找得到」。

## 01 形态与运行时

| 术语 | 英文 | 一句话 |
|---|---|---|
| JVM | Java Virtual Machine | 执行字节码的虚拟机——"一次编译到处运行"的载体 |
| JDK | Java Development Kit | 开发包：JVM + 编译器 + 工具（运维排障命令都在 JDK 里） |
| JRE | Java Runtime Environment | 运行环境：JVM + 核心类库，无编译器——只跑不编的机器装这个就够 |
| 字节码 | bytecode | .class 文件：编译产物，JVM 的"机器语言" |
| fat jar | — | 内嵌依赖与容器的单个可执行 jar（Spring Boot 常见）——`java -jar` 直接跑 |
| war | Web Archive | 部署到 Tomcat 的 Web 应用包——放进 webapps 目录 |
| 内嵌容器 | embedded container | Spring Boot 自带 Tomcat——应用自己就是服务，不用外置 Tomcat |

## 02 JVM 内存与 GC

| 术语 | 英文 | 一句话 |
|---|---|---|
| 堆 | heap | 对象存放的主区域，`-Xmx/-Xms` 控制大小——OOM 主战场 |
| 元空间 | Metaspace | 类元数据区（8.x 取代永久代）——`MaxMetaspaceSize` 控制 |
| 线程栈 | thread stack | 每线程私有（默认 1MB），方法调用帧——`-Xss` 控制 |
| 直接内存 | direct memory | NIO 堆外内存——不受 `-Xmx` 管，但受 `MaxDirectMemorySize` 管 |
| GC | Garbage Collection | 垃圾回收：自动回收不再引用的堆对象 |
| STW | Stop The World | GC 期间暂停所有应用线程——延迟抖动的来源 |
| Minor/Major/Full GC | — | 年轻代回收 / 老年代回收 / 全堆回收——频率与时长逐级上升 |
| G1 | Garbage First | 分区域增量回收的 GC 器——JDK 9+ 默认 |
| ZGC | Z Garbage Collector | 低停顿 GC（亚毫秒）——大堆低延迟场景 |

## 03 排障与工具

| 术语 | 英文 | 一句话 |
|---|---|---|
| jps | JVM Process Status | 列出本机 Java 进程与 PID——排障第一步 |
| jstat | JVM Statistics Tool | GC 实时统计：各代容量/次数/耗时 |
| jmap | JVM Memory Map | 堆直方图与 **heap dump**（⚠️ 会 STW，生产慎用全量） |
| jstack | JVM Stack Trace | 线程栈快照——CPU 高/死锁/卡顿定位 |
| jcmd | JVM Command | 1.7+ 统一诊断入口（替代多数 jmap/jstack 用法） |
| heap dump | 堆转储 | 堆内存的完整快照文件——MAT/VisualVM 离线分析 |
| thread dump | 线程转储 | 所有线程的栈快照——看"卡在哪一行" |
| Arthas | — | 阿里开源的在线诊断工具：不改重启动态查看（运维利器） |
| Micrometer | — | 应用指标门面——对接 Prometheus 的标准方式 |
| OOM | Out Of Memory | 内存耗尽错误——按报错区域分四种（001 §4） |

## 缩写速查

| 缩写 | 全称 | 意思与出处 |
|---|---|---|
| JVM | Java Virtual Machine | 执行字节码的虚拟机（全册） |
| JDK | Java Development Kit | 开发工具包，含排障命令（001） |
| JRE | Java Runtime Environment | 仅运行环境（001） |
| GC | Garbage Collection | 垃圾回收（001） |
| OOM | Out Of Memory | 内存耗尽（001 §4） |
| JMX | Java Management Extensions | Java 管理接口——JMX exporter 的数据源（「监控」007） |
| WAR | Web Application Archive | Tomcat 应用包（002） |
| STW | Stop The World | GC 暂停（001） |

## 最容易混的 10 对

| 容易混 | 一句话差别 | 去哪 |
|---|---|---|
| JDK vs JRE vs JVM | 开发全套 / 仅运行 / 执行引擎——三层嵌套 | 000 §1 |
| 堆 vs 栈 | 对象共享区 / 线程私有调用帧 | 001 §1 |
| 元空间 vs 永久代 | 8.x 用堆外本地内存 / 8.x 前在堆内——**报错名不同处理不同** | 001 §2 |
| fat jar vs war | 自带容器 `java -jar` / 部到 Tomcat 的 webapps | 002 §1 |
| Full GC vs Minor GC | 全堆回收（长停顿）/ 年轻代回收（短快） | 001 §3 |
| OOM vs 内存泄漏 | 一次性不够 / 慢性堆积——泄漏是 OOM 的前奏 | 001 §4 |
| heap dump vs thread dump | 内存快照（查谁占内存）/ 线程快照（查卡在哪） | 001 §5 |
| jmap vs jstack | 抓内存 / 抓线程 | 001 §5 |
| 内嵌 Tomcat vs 外置 Tomcat | Spring Boot 自带 / 传统 war 部署 | 002 §1 |
| -Xmx vs -Xms | 堆上限 / 堆初始——生产两者设同值避免抖动 | 001 §2 |

## 按症状反查

| 现象 | 大概率病根 | 去哪 |
|---|---|---|
| `OutOfMemoryError: Java heap space` | 堆不够或泄漏 | 001 §4 |
| `OutOfMemoryError: Metaspace` | 类加载泛滥或元空间没配 | 001 §2 |
| 容器里 Java 进程被杀，退出码 137 | 容器 limit < JVM 实际占用（含堆外） | 001 §5 |
| CPU 100% 但业务流量正常 | GC 频繁或死循环——jstat/jstack 定位 | 001 §3 |
| 接口偶发超时无规律 | GC STW 抖动——看 GC 日志 | 001 §3 |
| 线程数暴涨到几千 | 线程池泄漏或未配上限 | 002 §2 |
| war 部署后报类冲突 | 依赖 jar 版本冲突（类加载） | 002 §3 |
| Tomcat 起不来：端口占用 | 8080 被占 | 002 §4 |
| 慢但无 GC 问题 | 数据库/下游慢——thread dump 看线程在等谁 | 001 §5 |
| 重启后过几天又 OOM | 内存泄漏，dump 对比排查 | 001 §4 |
