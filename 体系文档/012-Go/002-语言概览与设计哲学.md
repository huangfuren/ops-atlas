## 1. Go 是什么

**Go 是 Google 开发的编译型语言，编译产物是一个独立可执行文件，拷到任何同架构机器上就能跑，不需要装任何运行时。**

| 点 | 后果 |
|---|---|
| 编译型 | 运行快，错误在编译期暴露 |
| 独立二进制 | 部署简单到极致，没有依赖地狱 |
| 不需要运行时 | 不用装 JDK / Python / Node，不怕版本冲突 |

出身：2007 年 Google 立项、2009 年开源，作者是 Robert Griesemer、Rob Pike 和 **Ken Thompson**（Unix 与 C 的发明人之一、图灵奖得主）——设计目标明确（解决工程问题），这解释了它为什么"没有奇怪的东西"。

你运维的东西大概率一半是 Go 写的：

```bash
kubectl get pods          # kubectl 是 Go
docker ps                 # Docker 是 Go
prometheus --config.file  # Prometheus 是 Go
```

## 2. 五个核心特性

### 2.1 编译成单个静态二进制

```bash
go build -o app.exe .    # 15MB 的 exe，包含代码 + 标准库 + 第三方库 + 运行时
```

部署同样的 HTTP 服务：Go 是 `scp app && ./app`；Python 要装解释器建虚拟环境装依赖；Java 要 JDK 调参打 jar；Node 要 node_modules 几千个文件。**这是 Go 在运维场景最大的优势**：给别人一个文件就能跑。交叉编译见 001 §7.4。

### 2.2 并发是语言内置的

```go
go doSomething()      // 一行起并发，开销约 2KB 栈
```

| 语言 | 起并发 | 代价 |
|---|---|---|
| **Go** | `go f()` | 2KB 栈，创建约 200ns |
| Java | `new Thread` | 1MB 栈，创建约 10μs |
| Python | threading | 有 GIL，多线程不能并行跑 CPU 任务 |

场景：批量探测 5000 个 IP 的 443 端口——Go 十行天然并发，Python 要写 asyncio，Shell 只有 `xargs -P`。

### 2.3 有垃圾回收，但停顿极短

| 语言 | 典型 GC 停顿 |
|---|---|
| **Go** | < 1ms（多数场景 < 100μs） |
| Java（G1） | 10–200ms |
| C++ | 无 GC，手动管内存 |

原理是并发三色标记 + 写屏障（013）。**写运维工具不用操心内存管理，GC 也不会造成监控数据抖动。**

### 2.4 静态类型，但语法极简

```go
names := []string{"a", "b"}               // 对比 Java 的 List<String> = new ArrayList<>()
for _, name := range names { fmt.Println(name) }
```

关键字 25 个（Java 50+，C++ 90+），规范几十页——读别人的代码不用先学风格，新人一周能提交可用代码。

### 2.5 工具链统一，不用选型

| 需求 | 其它语言 | Go |
|---|---|---|
| 依赖管理 | pip / npm / maven… | `go mod`（唯一） |
| 代码格式 | black / prettier… | `gofmt`（唯一，无参数） |
| 测试 / 静态检查 / 性能分析 / 文档 | 各装各的 | `go test` / `go vet` / `pprof` / `go doc`（全内置） |

**没有选择，就没有争论。**

## 3. 四条设计哲学

理解这四条，能解释 Go 里所有"看起来奇怪"的设计。

**3.1 少即是多**——刻意不提供的东西：类与继承（用结构体+组合+接口）、异常（错误是返回值）、三元运算符、方法重载。理由：**特性越多，团队代码风格差异越大**；用"少"换来"所有人写出来都差不多"。

**3.2 显式优于隐式**——类型转换必须写出来、错误必须处理（`err` 就在眼前），多打几个字换来看代码不用猜。

**3.3 组合优于继承**——没有继承，用嵌入：

```go
type Service struct {
    Logger              // 嵌入，Log 方法被"提升"
    Name string
}
s.Log("启动")            // 直接调用
```

没有"父类改了子类崩"，代价是要多写点代码——有意取舍。

**3.4 错误是值，不是异常**——

| | try/catch | 返回值 |
|---|---|---|
| 会漏掉吗 | 容易忘写 catch | `err` 就在眼前 |
| 控制流 | 跳转看不出来源 | 线性，一眼看到失败点 |

代价是满屏 `if err != nil`——**这是 Go 被吐槽最多、也最实用的设计**。

## 4. 和其它语言比

| 维度 | Go | Python | Java | C++ | Node.js |
|---|---|---|---|---|---|
| **部署** | 单文件 | 解释器+依赖 | JVM+jar | 动态库 | node_modules |
| **并发模型** | goroutine 原生 | GIL 受限 | 线程偏重 | 手写 | 单线程+回调 |
| **内存占用** | 低 | 中 | 高 | 低 | 中 |
| **运行性能** | 高（C++ 的 70-80%） | 低 | 高 | 最高 | 中 |

一句话定位：**Go** 写服务、CLI 工具、运维系统（部署简单+并发强）；Python 数据分析与脚本；Java 大型企业存量；Rust 极致性能无 GC 但学习曲线陡 5 倍。

具体对比（读 10 万行日志统计 IP Top 10）：Shell 3 行 2s 无部署；Python 15 行 1.5s 要装环境；**Go 50 行 0.3s 一个 exe**——规模一大，Go 的性价比就出来了。

## 5. 运维为什么用 Go

**5.1 你在用的东西都是 Go 写的**：Kubernetes、Docker、etcd、Prometheus、Terraform、Harbor、kubectl/helm——CNCF 项目绝大多数是 Go。理由实际：这些工具要分发到成千上万台机器、单机跑、低资源高并发，正是 Go 的设计目标。**想读源码、写 exporter、提 PR，绕不开 Go。**

**5.2 自研工具的五个典型场景**：

| 场景 | 现在的做法 | Go 之后 |
|---|---|---|
| 资产/端口扫描 | nmap + 手工整理 Excel | 并发探测 + 输出 CSV + 存库 |
| 配置巡检 | 逐台 ssh 比对 | 并发拉取 + 规则校验 + 报告 |
| 日志处理 | awk/sed 管道，复杂就崩 | 流式解析 + 结构化输出 |
| 发布工具 | 一堆 shell 脚本 | 带参数校验、回滚的单文件 |
| K8s Operator | 手工 kubectl | Controller 自动维持状态 |

**5.3 为什么不是 Python/Shell**：Python 三硬伤——部署（目标机要装环境，内网离线是噩梦）、GIL（千级并发卡住）、慢（1GB 日志几分钟 vs Go 几秒；跑一次 3 秒就能进 CI 每小时跑）。Shell 超 100 行失控：无数据结构、无测试、管道中间失败不可捕。**分界线：临时排查用 Shell，要反复跑的用 Python，要分发要并发的用 Go。**

**5.4 收益账**：每周 40 分钟的 LB 核查，写个 Go 工具花 1 天、之后每次 30 秒——**第 3 周回本**，还能进 CI、给别人用。投入一次，长期复利。

## 6. Go 不擅长什么

| 场景 | 为什么 | 该用什么 |
|---|---|---|
| GUI 桌面程序 | 生态差 | C# / Electron |
| 数据科学 / ML | 没有 numpy/pandas 等价物 | Python |
| 一次性脚本 | 写 20 行也要 `go mod init` | Python / Shell |
| 极致性能 | 比 C++/Rust 慢 20-30% | Rust / C++ |
| 复杂泛型逻辑 | 表达力弱于 Rust/Scala | Rust / Scala |

**判断标准：一次性的、探索性的、要丰富库的用 Python；长期跑、要分发、要高并发的用 Go。**

## 7. 看一段代码

40 行的运维小工具：读日志，统计各状态码次数。Go 的主要语法全在上面：

```go
package main                                    // ① 可执行程序必须是 main 包

import (                                        // ② 导入
	"bufio"
	"fmt"
	"os"
	"strings"
)

type Stats struct {                             // ③ 结构体
	Total  int
	Codes  map[string]int
}

func (s *Stats) Add(line string) {              // ④ 指针接收者方法
	if !strings.Contains(line, "status=") {
		return
	}
	parts := strings.Split(line, "status=")
	if len(parts) < 2 {
		return
	}
	fields := strings.Fields(parts[1])
	if len(fields) == 0 {                       // ⑤ 边界检查，否则 [0] 会 panic
		return
	}
	s.Total++
	s.Codes[fields[0]]++
}

func main() {
	f, err := os.Open("access.log")             // ⑥ 错误是返回值
	if err != nil {
		fmt.Fprintln(os.Stderr, "打开文件失败:", err)
		os.Exit(1)                              // ⑦ 退出码
	}
	defer f.Close()                             // ⑧ 函数返回时执行

	s := &Stats{Codes: make(map[string]int)}    // ⑨ 取地址 + 初始化 map

	scanner := bufio.NewScanner(f)              // ⑩ 流式读取
	for scanner.Scan() {                        // ⑪ 唯一的循环关键字
		s.Add(scanner.Text())
	}
	if err := scanner.Err(); err != nil {       // ⑫ 语句写在 if 里
		fmt.Fprintln(os.Stderr, "读取失败:", err)
		os.Exit(1)
	}

	fmt.Printf("总计 %d 条\n", s.Total)          // ⑬ 格式化输出
	for code, n := range s.Codes {              // ⑭ 遍历 map（顺序随机）
		fmt.Printf("  %s: %d\n", code, n)
	}
}
```

**这段代码里没有的东西**（对比 Java/Python）：没有类、try/catch、`while`、`this`、继承、注解、配置文件、虚拟环境。40 行已是一个能用的工具，编译出来 2MB，扔到任何机器都能跑。

## 8. 常见误解

| 误解 | 事实 |
|---|---|
| "Go 是 Google 内部用的，生态不行" | CNCF 项目绝大多数是 Go |
| "没有泛型，写不了复杂逻辑" | 1.18 起有泛型覆盖 90% 场景，哲学是能不用就不用 |
| "性能不如 C++ 没意义" | 达到 C++ 的 70-80%，开发效率高 3 倍、部署近零成本 |
| "`if err != nil` 太啰嗦" | 有意设计——线性代码比 20 层堆栈好定位 |
| "只能写微服务" | CLI、代理、数据库、编译器、操作系统（gVisor）都有 |
| "学 Go 要先学 C" | 不需要，指针概念很浅 |

## 9. 生态版图

**标准库**能干什么见 [006 §1 常用标准库](006-标准库与并发第一课.md)——HTTP/JSON/TLS/并发/测试/pprof 全内置，写带 TLS 的服务不需要第三方包。

运维常用第三方库：

| 用途 | 库 |
|---|---|
| Prometheus 埋点 | `prometheus/client_golang` |
| 结构化日志 | 新项目直接用 `slog`（1.21+） |
| CLI 框架 | `cobra`（kubectl 同款）+ `viper` |
| K8s 客户端 | `k8s.io/client-go` |
| SSH | `golang.org/x/crypto/ssh` |
| 并发工具 | `golang.org/x/sync`（errgroup） |
| YAML | `gopkg.in/yaml.v3` |

值得读的源码：`node_exporter`（**最佳起点**——代码量小、与监控直接相关，读完就会写 exporter）、`spf13/cobra`（CLI 组织）、`etcd-io/etcd`（分布式一致性）。

**一句话总结**：**Go 把"写起来像 Python"和"跑起来像 C"做出了可用的平衡，并用单文件部署解决了运维最痛的一环**——这就是云原生工具几乎都选它的原因。
