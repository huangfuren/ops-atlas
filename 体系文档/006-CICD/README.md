# CI/CD 与自动化手册

> **定位**：从「手敲命令发布」到「提交即上线」的自动化运维文档。000 讲工具链全景，001–007 按组件分册，008 把它们串成一条完整流水线——每一册对应一类真实任务。  
> **读者**：会写 Shell 脚本（「Linux」008 册水平）、部署过服务的运维人员，第一次系统搭 CI/CD。  
> **口径**：**Jenkins LTS（声明式 Pipeline）为主线，GitLab CI 对照**；Ansible 2.15+（core 语法）；Git 以命令行为准；制品库 Harbor（镜像）与 Nexus（通用制品）。  
> **更新**：2026-10-31  
> **术语表**：单独成册 → [00 术语表](00-术语表.md)。79 个术语 · 8 个缩写 · 14 对易混 · 16 条症状反查。

## 阅读约定

1. **Jenkins 为主线、GitLab CI 对照**：概念只讲一遍，两家写法并排给；只维护 GitLab 生态的读者可跳读 002 §2.9。
2. **每条流水线可复现**：Jenkinsfile / .gitlab-ci.yml / playbook 给完整文件，不写省略号。
3. **凭据永远不进 Git**：所有示例用 Credentials/Vault 引用，明文密钥一律标 ⚠️。
4. **危险操作先说后果**：`git reset --hard`、强制推送、Ansible 对生产执行，先写会丢什么。
5. **改动必有回滚**：每个发布方案配回滚步骤，回滚演练是 007 的必修节。
6. **每册结构统一**：目录 → 正文（每节开头一句承接上文）→ N 个坑 → 排错路径 → 检查清单。
