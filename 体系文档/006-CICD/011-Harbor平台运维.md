## 11.1 与 006 册的分界：用的人与管的人

006 册讲**用 Harbor 的流水线视角**：项目怎么建、robot 账号怎么发、tag 怎么起、制品怎么晋级。本册讲**管 Harbor 的平台视角**：这个 docker-compose 撑起来的服务，数据怎么备、主备怎么复制、证书怎么续、磁盘怎么回收、入口怎么换——平台挂了或要迁移时，全靠这一册。

## 11.2 架构与两块命根数据

docker-compose 单机形态，容器分工：

| 容器 | 职责 |
|---|---|
| proxy（nginx） | 统一入口：portal 页面与 registry API 都从它走，证书挂这层 |
| core | 平台核心服务（API/RBAC/token 签发） |
| registry | 镜像 blob 存储 |
| jobservice | 异步任务执行：复制、回收、扫描调度 |
| trivy | 镜像漏洞扫描（006 §6.8 的门禁数据源） |

**数据两块命根**，备份必须两样齐：

1. **registry 存储**：镜像层数据，随镜像量增长（几百 GB 量级很常见）——丢了 = 全部镜像重新构建；
2. **元数据库**：项目、用户、robot、复制策略、扫描记录——丢了 = 平台"失忆"，镜像 blob 变成无主孤儿。

配置在 `harbor.yml`，改动后必须跑 `prepare` 重新生成容器配置再重启 compose——直接改生成的文件会被下次 prepare 冲掉。

## 11.3 主备复制

主备形态的分工：**主库可写**（CI 往这推），**备库只读兜底**（主库故障时至少能拉）。同步靠**复制规则**（jobservice 异步执行，按项目/仓库名匹配）——它保证的是"最终一致"，不是实时：刚推的镜像在备库可能要等复制任务跑完。切流（把用户从主指到备）是**入口层的事**（改 DNS/反代，见 11.6），数据面复制自己会追平——两层别混为一谈。复制失败的排查入口在 jobservice 日志与任务的失败列表，不在 registry。

## 11.4 证书独立线与批次拉平

Harbor 自带 proxy 容器终结 TLS，证书放在**自己的 ssl 目录**（如 `/opt/harbor/ssl/<域>/`）——**它与 LB 层的证书不是同一份配置**：哪怕内容是同一张证书，续签时也是**分头部署**的两条线。实战教训（真实事件泛化）：某次整批证书续签按"平台清单"分头做，LB 层换完了、Harbor 自己的目录漏了——到期当天用户才炸。**换证要按"证书批次"横向拉平，不能按平台/清单分头做**：拿到新证书包后，grep 全网"谁引用了旧批次"，一查到底成对执行（主备两台都必须换）。

## 11.5 清理与 GC：回收不是删 tag

磁盘水位的治理链：**tag retention 策略**（保留策略在 006 §6.7——留最近 N 个版本/多少天）→ 策略只解除引用，**磁盘空间要等 GC 回收**。GC 的两个纪律：

- **GC 把未引用的 blob 物理删掉**，期间 registry 需要只读窗口——推送中的镜像可能损坏，**挑低峰 + 停推窗口执行**；
- 删了 tag 看磁盘没变化是正常的——**引用解除与空间回收是两步**，别反复点删除。

## 11.6 换门：入口前移与反代接入五坑

"换门"= Harbor 本体不动，把对外 HTTPS 入口从本体前移到统一网关（网关终结 TLS 后回源）。**回源协议是第一大坑**：

| # | 坑 | 机制 | 正确做法 |
|---|---|---|---|
| 1 | 回源走 80 | Harbor proxy 对 80 的请求回 **308 跳转（Location 带显式 ：443）** → 网关回源 80 会陷入无限重定向环，docker 客户端直接断 | **网关必须 HTTPS 回源到本体 443**；先 `openssl s_client -tls1_2` 验握手兼容 |
| 2 | 大镜像推送失败 | 反代默认缓冲与超时按网页设计 | `client_max_body_size 0`（覆盖 http 级上限）+ `proxy_request_buffering off`（大 blob 直通）+ `proxy_read_timeout 300s` + `proxy_http_version 1.1` |
| 3 | 页面跳转/token 异常 | Harbor 不知道"客户端走的是 https" | 反代回源补 `X-Forwarded-Proto https`；harbor.yml 的 `external_url` 不动则 token realm 不变，已签 token 继续有效 |
| 4 | 网关侧 `proxy_ssl_verify on` 报 verify error | 老系统的 CA 包可能缺新根（如 ISRG Root X1） | 内网可信回源可 `proxy_ssl_verify off`，或先补装根证书——**写进变更记录，别静默** |
| 5 | 只迁了读没迁推拉验证 | "能打开网页"≠"能 docker push/pull" | 终验必须 docker 实测：小镜像 push + pull + 大镜像 push，hosts 绑新入口先测再切 DNS |

换门的完整顺序：网关 conf 就位 → 五坑逐项验（hosts 绑网关实测）→ DNS 切（003-003 的 TTL 纪律）→ 观察 Harbor 访问日志确认流量到网关。

## 11.7 搬家：本体迁移

本体迁移（换宿主机/换机房）= **两块命根数据 + compose 配置**一起走：

1. 停写入窗口（低峰，或先切流量到备库承载拉取）；
2. 备份并搬运 registry 存储目录与元数据库（`/opt/harbor` 下的数据卷整体打包——注意磁盘余量，几百 GB 别挤爆中转盘）；
3. 新机装同版本 docker-compose + Harbor，`harbor.yml` 核对（尤其 `external_url`——**它决定 token realm，变了已签发的 token 全部失效**，CI 凭据要同步换）；
4. `prepare` → `docker-compose up -d` → 验证（登录/拉取/复制任务恢复）→ DNS 切。

## 11.8 坑表

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 备份只备 registry 或只备数据库 | blob 失忆或元数据失忆，都是残废 | 两块命根一起备（11.2） |
| 2 | 改生成配置不跑 prepare | 下次 prepare 冲掉手改 | 改 harbor.yml → prepare → 重启（11.2） |
| 3 | 复制是实时的，切流无脑跟 | 刚推的镜像备库还没有，拉取 404 | 复制最终一致；切流前看复制任务队列（11.3） |
| 4 | 换证只换 LB 层 | Harbor 自带目录漏签，到期当天炸 | 证书批次横向拉平，grep 旧批次一查到底（11.4） |
| 5 | 删 tag 后等磁盘瘦身 | 空间不变，以为策略没生效 | 引用解除与 GC 回收是两步，低峰跑 GC（11.5） |
| 6 | 网关回源走 80 | 308 带 ：443 无限重定向环，docker 直断 | HTTPS 回源 443，先验 TLS1.2 握手（11.6） |
| 7 | 反代用默认参数接 registry | 大镜像推送 413/超时/断连 | 大 blob 四参数一套齐（11.6） |
| 8 | 搬家只搬数据不改 external_url | token realm 变，CI 全线认证失败 | external_url 纳入迁移核对清单（11.7） |
