# SRE 方法论手册

> **定位**：把散落在各板块的「故障剧本」「排错路径」「检查清单」收拢成可靠性方法论的薄册。SRE 不是工具栈，是一组**可度量的承诺与运转机制**——SLO、错误预算、待命、复盘、琐事治理。  
> **读者**：已具备技术主干的运维/DevOps 人员（本库其余板块的水平），第一次系统接触 SRE 方法。  
> **口径**：方法论通用，不绑定工具；实例引用本库各册（监控 004 的告警链路、日志 006 的故障剧本、CICD 007 的发布策略），数据源一律指向「监控」册。  
> **更新**：2026-11-06  
> **术语表**：单独成册 → [00 术语表](00-术语表.md)。32 个术语 · 7 个缩写 · 12 对易混 · 12 条症状反查。

> **与「监控」的衔接**：SLO 的数据源全部是指标（SLI 的度量即监控查询）——没有「监控」册的指标体系，SLO 是空谈。  
> **与本库「故障剧本」的关系**：Linux 009、数据库 008、日志 006、接入层 007 的剧本是**战术**（某一类故障怎么修），本册是**战略**（机制上让故障少、响应快、不二犯）。  
> **与「CICD」007 的衔接**：错误预算烧尽 → 收紧发布节奏，是 SRE 与交付体系的经典握手。

## 阅读约定

1. **薄册不是浅册**：每册砍掉了工具细节，但机制定义必须完整——读完能落地的是机制，不是名词。
2. **一切引用本库**：涉及具体技术动作（配置告警、写剧本、做演练）时，指回对应板块，不重复展开。
3. **诚实优先**：SLO 定多少、toil 占比多少，先如实度量再谈改进——假装可靠比不可靠更危险。
4. **每册结构统一**：目录 → 正文 → 坑表 → 检查清单。
