## 2.1 harness 选型：用现成的，自研只做技能层

agent harness（运行时：会话管理、工具调用、上下文组织）**直接用官方开源方案**（如 DeepSeek 的 DSH：`npx @deepseek-ai/dsh web`，Node 22.19+/24），不自研编排。理由：编排层是各家快速迭代的主战场，自研即背负永久维护；而真正沉淀价值的是**技能与规约层**——它们是纯文本，随 git 仓库走，换运行时无损迁移。工程量分配：harness 零，技能与规约全投入。

## 2.2 技能单一事实源与相对软链接

**核心原则：只有 `.agents/skills/` 一个事实源**（社区标准目录名，多数工具原生识别），随 git 入库分发。各工具要求的读取路径（`.dsh/skills`、`.cursor/`、`.claude/` 等）只建**相对路径软链接**：

```bash
mkdir -p .xxx
ln -s ../../.agents/skills .xxx/skills   # 相对路径！仓库搬家不失效
ls .xxx/skills/                           # 验证能列出事实源内容
git check-ignore .xxx && echo ignored     # 确认工具目录不入库
```

四条推论：内容改动**只发生在事实源**（软链接即时生效，无需多处同步）；工具目录里除软链接外什么都不该有；部分工具要求逐 skill 链接就逐个链（内容仍只有一份）；**就近优先（nearest-wins）**——子项目专用技能放子目录 `_skills/`，优先于全局缺省，两套各管一域。

## 2.3 init 前置检查包：三步编排与退出码语义

每次开工的"体检"做成**技能包**而不是口头清单——编排器 `check-all` 串行跑三步，**任一步非 0 立即终止**：

| 步 | 检什么 | 失败码 | AI 动作 |
|---|---|---|---|
| ① check-os-node | 运行环境（node 版本/依赖） | 1 | 停下，提示安装后重跑 |
| ② check-env-vars | 环境变量体检 | 3 | **停下，打印当前系统的可复制配置命令**，等"设好了"再重跑 |
| ③ check-connect | 数据库/服务连通性 | 1 | 停下，提示检查网络与凭据 |

三个设计要点：**退出码语义化**（AI 按 code 分支动作，不猜）；**检查只回 true/false 与缺失变量名**（绝不回显值——004 册凭据红线）；**编排器输出末行固定一句就绪语**，但 AI 不得把它当回合结束语——紧接输出使用场景后停住。

## 2.4 领域技能包：references 五件套

一个领域技能（如"AI 操作某数据库"）的标准内容结构——SKILL.md 瘦身做入口（<200 行），细节全部进 `references/`：

| 文件 | 管什么 |
|---|---|
| 01-红线与禁令 | 最高约束，优先级高于临场指令；触犯即终止并报告 |
| 02-连接与环境变量 | 凭据来源、变量清单、配置方法 |
| 03-工作流与话术 | 标准动作序列与触发话术 |
| 04-账号与命名规范 | 对象命名、权限边界 |
| 05-可观测产出 | 该领域的标准产出物（大盘/报表/日志查询） |

SKILL.md 常驻的内容只有：触发词、红线摘要、命令入口、退出码表、指向 references 的索引。**规约内嵌**：红线引用用户原话与日期做立法依据——规约有出处，才不会被后人随手改。

## 2.5 技能编写规范：frontmatter 硬约束

Agent Skills 开放标准的硬约束：

- 一目录一 `SKILL.md`；**`name` ≤64 字符、仅 `a-z0-9-`、必须等于父目录名**；
- `description` 含 **what + when**，关键触发词前置（工具超预算截断时先保描述）；
- 子目录可选 `scripts/`（可执行）、`references/`（详情）、`assets/`（模板）；
- **存量迁移**：老技能缺 frontmatter、name 不符的一律按标准改写——工具的自动发现依赖它。

## 2.6 交互模式：使用卡片与下一步话术

两个低成本高收益的交互模式：

- **使用卡片**：技能被调用时先输出一张固定卡片（能力范围、前置要求、用户可复制的话术 2~3 条），然后**直接执行第一步只读动作**，不等回复；
- **下一步话术**：每轮动作结束给"下一步你可以说："2~3 条可复制话术，引用本轮真实的批次号/数字——把"然后呢"从用户的负担变成 AI 的产出。

## 2.7 坑表

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 自研编排层 | 永久维护负担，跟不上上游 | harness 用现成的，投入技能层（2.1） |
| 2 | 技能复制到各工具目录 | 改一处漏四处，版本分叉 | 单一事实源 + 相对软链接（2.2） |
| 3 | 软链接用绝对路径 | 换机器/换克隆位置全断 | 相对路径（2.2） |
| 4 | SKILL.md 塞满细节 | 常驻上下文爆炸，触发词被稀释 | 瘦身做入口，细节进 references（2.4） |
| 5 | name 与目录名不一致 | 工具拒绝加载/静默不识别 | frontmatter 硬约束（2.5） |
| 6 | 前置检查靠口头问 | 漏一步就是脏数据/断连 | check-all 编排包 + 退出码语义（2.3） |
