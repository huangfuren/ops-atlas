## 3.1 MCP 与 Skill 的分工：怎么连与怎么处理

MCP 是**工具连接协议**：把数据库、平台 API、文件系统封装成标准化的 tools / resources，任何支持协议的 AI 都能调用——一次封装，处处可用。Skill 是**处理方法**：拿到数据后按什么 SOP 处理、什么顺序、什么红线。分工一句话：**MCP 负责"怎么连"，Skill 负责"怎么处理"**——故障诊断 = MCP 连上监控/日志/数据库 + Skill 沉淀的排查 SOP（「SRE」002 的响应纪律是后者的母本）。

选型：单机自用直接 stdio 进程；团队共享走 HTTP 网关集中部署；能力是否真实存在，以**规约仓库的能力索引**为唯一权威（先查再用，不猜）。

## 3.2 三种接入形态

| 形态 | 典型场景 | 设计要点 |
|---|---|---|
| **只读查询 MCP** | AI 查库取数（MySQL 只读账号） | 库侧限只读账号；AI 只发 SELECT；表结构现查 `information_schema` 不固化 |
| **审查规则 MCP** | SQL 上线前审查、配置审查 | 规则库独立成 standards 文件——审查口径可版本化（006 册制品思维的平移） |
| **平台探测 MCP** | IP 探活、大盘数据、资产盘点 | 发包类必须带授权确认（004 册）；产出物成对交付（005 册） |

## 3.3 受管调用四步：来源锁死与增量同步

调内部网关类能力的标准时序，**一步一脚本**：

1. **同步规约**：拉取上游规约与能力索引（Etag 增量比对，变了才下载）——规约更新了还按旧规则调，是受管调用的第一大事故源；
2. **受管判断**：这次操作要不要走受管通道（三问：动数据吗、有红线吗、有索引吗）；
3. **查能力索引**：按关键词确认能力真实存在，拿到路径与 `service_id`——**索引没有的能力不存在**，不猜不通融；
4. **标准调用时序**：试打 → 自签临时凭证 → 重发。

两条安全设计：**来源锁死**——规约 URL 硬编码只认官方仓库 main 分支，脚本启动自检 URL 被篡改即拒绝执行；**缓存只是加速**——"流程繁琐"不是跳过同步的理由。

## 3.4 凭据与身份：AI 不碰值

- **凭据通道**：全部走系统环境变量；AI 只执行检查脚本拿 **true/false 与缺失变量名**——环境变量值、rc 文件、`env` 输出、截图、"贴配置来核对"一律禁止；
- **缺配置的处置**：不猜、不代设、不索要——**停下来打印当前系统的可复制配置命令**，等使用者确认；
- **身份五件套**（用户名/显示名/唯一身份码/团队身份 ID/一人一串永不改的 UUID）：让每次 AI 调用**可归属到人**——审计与追责的地基。

## 3.5 失败分流：两张表与三态上报

调用失败按**入口**分两张表处置（动作可能相反，不能混用）：

| 码 | 临时凭证入口（网关） | 永久凭证入口（身份服务） |
|---|---|---|
| 401 | 没带凭证 → 走自签流程重发 | 凭证缺失/账号禁用 → **停止上报**，不自签顶替 |
| 403 | 凭证过期/跨入口 → 重签一次，仍拒即停 | 操作被拒 → **停止如实上报**，不换入口绕过 |
| 429 | 限流 → 停止，不循环重试 | 同左 |
| 400/422 | 参数非法（多为 shell 吞引号）→ 文件传参 | 字段不合法 → 按接入说明修正，不猜字段 |
| 404 | 能力未启用 → 回索引核对，仍无则报缺口 | 资源不存在 → 核对 ID，不猜 |
| 5xx/超时 | 只读可有限重试，写请求先核对结果 | 报失败位置 |

三条共同纪律：**三态上报**——只报"成功 / 失败 / 受阻"，受理不等于成功；**带追踪标识**（`X-Request-Id`）；**禁止三绕**——换入口、换凭证、直连后端绕过，以及把"缺凭证"变成"向人要密码"。

## 3.6 坑表

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 规约不同步就调用 | 按旧红线调新接口，静默越权 | 先同步（Etag 增量），再调用（3.3） |
| 2 | 能力"应该存在"直接调 | 404 或打到未登记能力 | 查能力索引，索引说了算（3.3） |
| 3 | AI 读环境变量值"核对配置" | 凭据进了上下文即泄露 | true/false 通道，值永不进对话（3.4） |
| 4 | 失败就换入口/直连后端 | 绕过审计，归因断裂 | 按表分流 + 三态上报（3.5） |
| 5 | 429 循环重试 | 限流雪上加霜 | 停止并报标识（3.5） |
| 6 | 表结构凭记忆写 SQL | 字段名猜错，查询报错或脏读 | 现查 information_schema（3.2） |
