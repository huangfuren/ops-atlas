# AI 运维手册

> **一句话**：把 AI 从"聊天工具"变成**可规约、可审计、可复制的运维生产力**——规约层管行为，harness 层管骨架，MCP 层管连接，安全层管授权，交付层管产品化。  
> **读者**：已经开始用 AI 干运维活（写文档、查数据、跑脚本），想把"每次现讲规矩"升级成"规矩长在仓库里"的运维。  
> **口径**：不绑定模型厂商；工具协作层以社区标准 **AGENTS.md + `.agents/`** 为准；Skill 采用 Agent Skills 开放标准（frontmatter + 目录约定）。  
> **更新**：2026-11-08  
> **术语表**：单独成册 → [00 术语表](00-术语表.md)。

## 体系总览

从"AI 干活不可控"到"AI 干活像同事"，五册一条线：**先立规约（怎么管行为），再搭骨架（技能怎么挂），再接工具（数据怎么来），再收安全（危险动作怎么授权），最后产品化（能力怎么交付给团队）**。

> **与「SRE」的分界**：SRE 管"人 + 系统的生产纪律"（SLO/待命/复盘），本板块管"AI 这个新同事的用工纪律"——AI 的行为规约最终汇入 SRE 的复盘与 toil 治理。  
> **与「数据库」「安全运维」的分界**：AI 连库的安全红线在 004，被连对象的加固本身归各自板块。  
> **与「CICD」011 的分界**：镜像仓库是交付链设施；AI 能力仓库是"规约+技能+文档"的 git 仓——形态同源，内容不同。

## 阅读约定

1. **规约可执行**：每条规约都落到"AI 能照做的判定句"，不写"要负责""要谨慎"这类空话。
2. **模式优先于版本**：AI 工具演进快，本板块写模式（单一事实源、授权三件套、失败分流），具体工具版本只在口径行出现。
3. **零凭据原则**：全部示例不含真实凭据——凭据走环境变量，AI 不碰值（004）。
4. **每册结构统一**：目录 → 正文 → 坑表 → 检查清单。
