## 1. 网络隔离：bind 与 protected-mode

三道闸，缺一不可：

| 闸 | 配置 | 说明 |
|---|---|---|
| ① 只监听内网 | `bind 10.0.0.5 127.0.0.1` | **绝不 bind 0.0.0.0**——历史未授权事件全部源于公网暴露 |
| ② 保护模式 | `protected-mode yes`（默认） | 未设密码时拒绝非本机连接 |
| ③ 防火墙 | 安全组/iptables 只放行应用网段 | 数据库网段策略统一（见「接入层」/「网络」007） |

## 2. 危险命令治理：rename 与禁用

对运维高危命令做处置，两种方式：

```conf
# 方式一（老做法）：rename 成空串"禁用"
rename-command KEYS ""
rename-command FLUSHALL ""

# 方式二（7.x 推荐）：ACL 类别禁用，rename-command 已不推荐
```

`rename-command` 的代价：官方文档/工具可能失效，且改名只是"藏起来"。ACL 体系（§3）可以按用户精细禁用，是正解；`FLUSHALL/FLUSHDB` 无论哪种方式都应在生产禁用或重命名为长随机串。

## 3. ACL：用户级权限

6.0 起内置 ACL，替代全局 requirepass：

```conf
# redis.conf
user default off                          # 关掉默认用户（禁用旧密码体系）
user app on >AppPass2026 ~app:* +@read +@write -@dangerous
user monitor on >MonPass2026 ~* +@read +info
```

含义：`app` 用户只能访问 `app:*` 的 key、可读写、禁危险类；`monitor` 用户全局只读（给 redis_exporter 用）。管理命令：

```bash
ACL LIST                    # 当前用户清单
ACL CAT dangerous           # 危险命令类别（FLUSHALL/KEYS/SORT…）
ACL GETUSER app             # 用户详情
ACL SETUSER app -@dangerous # 运行时禁用危险类
```

迁移注意：老应用用 `requirepass` 的密码仍映射到 default 用户——升级时保留 default 密码，逐步切到 ACL 用户。

## 4. 历史攻击面：为什么绝不裸奔

未授权 Redis + `CONFIG SET dir/webshell` 写文件的利用链曾是挖矿与勒索的重灾区。**裸奔公网的 Redis 平均几分钟内就会被扫描发现**。防线清单：bind 内网 ✓ 保护模式 ✓ 密码/ACL ✓ 防火墙 ✓ 低权限运行（不用 root 跑 Redis，防提权写文件）✓ 定期升级补 CVE ✓。

## 5. 监控衔接：指标映射与告警阈值

redis_exporter（「监控」007 §7）从 `INFO` 抓指标，运维侧要给的映射与阈值：

| INFO 指标 | Prometheus 指标（redis_exporter） | 告警建议 |
|---|---|---|
| used_memory/maxmemory | redis_memory_used_bytes / redis_memory_max_bytes | 比值 >90% 告警 |
| mem_fragmentation_ratio | redis_memory_fragmentation_ratio | >1.5 警告，<1 告急（swap） |
| connected_clients | redis_connected_clients | 打满前 80% 告警 |
| keyspace hit/miss | redis_keyspace_hits_total / misses_total | **命中率骤降告警**（雪崩前兆） |
| evicted_keys | redis_evicted_keys_total | 增长即告警（容量不足） |
| master_link_status（从库） | redis_master_link_up | down 即告警（HA 前兆） |
| blocked_clients | redis_blocked_clients | 持续增长告警（阻塞命令嫌疑） |
| rdb_last_bgsave_status | redis_rdb_last_bgsave_status | 非 ok 告警 |

**主存储业务的告警档位与「SRE」001 的 SLO 对齐**：命中率是 SLI 的候选。

## 6. 客户端注意事项

| 项 | 要点 |
|---|---|
| 连接池必配 | maxActive/maxIdle/maxWait——泄漏会让 connected_clients 打满 |
| 超时必设 | connect/so timeout 缺省值过大，故障时雪崩式挂起 |
| 密码入库 | 用配置中心/环境变量，不硬编码 |
| 协议升级 | 6.0+ RESP3 与 ACL 的客户端兼容性，升级前验证 |

## 7. 坑表

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | bind 0.0.0.0 上公网 | 几分钟内被扫描、植入挖矿 | bind 内网 + 保护模式 + 防火墙 |
| 2 | 只设了 requirepass 没限命令 | FLUSHALL 误删全库 | ACL 禁 @dangerous |
| 3 | redis_exporter 用管理员账号 | 采集账号权限过大 | 专用只读 monitor 用户 |
| 4 | root 跑 redis-server | CONFIG 写文件提权风险 | 专用低权限用户运行 |
| 5 | 客户端无超时 | Redis 故障时应用线程雪崩式挂起 | 超时必设（006 §7） |
