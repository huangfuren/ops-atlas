## 1. 两种机制总览

| | RDB | AOF |
|---|---|---|
| 本质 | 某时刻全量**二进制快照** | 每条写命令**追加日志** |
| 恢复速度 | 快（直接载入） | 慢（逐条重放） |
| 丢数据窗口 | 上次快照之后的全丢 | 最多 1 秒（everysec） |
| 文件体积 | 小（压缩二进制） | 大（文本命令），需重写压缩 |
| 运行影响 | bgsave 需 fork | fsync 占 IO |

7.x 默认**混合持久化**（`aof-use-rdb-preamble yes`）：AOF 重写时文件头是 RDB 全量、尾部是增量命令——恢复快且丢得少。

## 2. RDB：快照

**机制**：`save` 同步阻塞（生产禁用）；`bgsave` fork 子进程落盘。自动触发靠配置规则：

```conf
save 3600 1    # 1 小时内 1 次写入就触发
save 300 100   # 5 分钟内 100 次写入
save 60 10000  # 1 分钟内 1 万次写入
```

优点：文件紧凑、恢复快、可传输异地。缺点：两次快照之间的数据全丢（窗口取决于触发频率）。

## 3. AOF：命令日志

**机制**：写命令追加到 aof 文件，`appendfsync` 三档控制刷盘：

| 档 | 行为 | 代价 |
|---|---|---|
| `always` | 每条命令都 fsync | 丢得最少，吞吐掉一个量级 |
| **`everysec`** | 每秒 fsync（默认） | 最多丢 1 秒——生产默认 |
| `no` | 交给操作系统 | 最快，断电丢多 |

**重写（AOF Rewrite）**：日志越写越大，`bgrewriteaof` fork 子进程按当前数据生成等价最小命令集。7.x 支持增量重写，减少一次性的大 fork。**恢复顺序**：同时开启 RDB 与 AOF 时，重启优先载入 AOF（数据更全）。

## 4. fork 与写时复制：卡顿元凶

`bgsave`/重写都靠 fork 子进程：fork 瞬间父子**共享内存页**，之后谁改谁复制（写时复制）。

三个运维要点：

1. **fork 本身的耗时与实例内存成正比**——10GB 实例在 200ms~1s 级（看页表大小），期间主进程停顿。
2. **写时复制可能让内存翻倍**——快照期间写入越猛，复制出去的页越多；内存余量要留 30%~50%。
3. **host 内核参数**：`vm.overcommit_memory=1`（否则 fork 可能失败）；大页（THP）建议关闭——放大复制粒度。

观察手段：`INFO stats` 的 `latest_fork_usec`（最近一次 fork 耗时）——持续走高就要控制实例大小或错峰。

## 5. 持久化 ≠ 备份

**RDB/AOF 都在本机磁盘上**——机器没了数据就没了。持久化解决"进程重启恢复"，备份解决"磁盘/机器级灾难"：

| 手段 | 防什么 | 频率 |
|---|---|---|
| RDB/AOF | 进程重启、断电 | 自动持续 |
| 定时拷贝 RDB 到异地/对象存储 | 磁盘损坏、误删 | cron 每小时/每天 |
| 恢复演练 | 验证备份可用 | 定期（方法见「Linux」010 · 「数据库」005） |

**误删（FLUSHALL）防护**：持久化救不了已执行的删除——靠 ACL 禁命令（007）与备份回滚。

## 6. 选型决策

| 业务定性 | 推荐配置 |
|---|---|
| 纯缓存（可丢，库里有全量） | RDB 或 AOF everysec 均可；甚至接受重启丢——但**主存储 Redis 绝不允许** |
| 会话/状态（少量可丢） | AOF everysec + RDB 兜底 + 混合 |
| 计数/资金相关（不可丢） | AOF always 或 everysec + 主从双写（003）+ 异地备份 |

**先回答"可丢不可丢"再选配置**——这是 000 §3 那个判定的落地。

## 7. 坑表

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 生产用 `save ""` 关掉全部持久化 | 重启全丢，主存储业务崩盘 | 主存储必须 AOF everysec 起 |
| 2 | `appendfsync always` 当默认 | 吞吐掉一个量级 | 用 everysec；真不可丢靠主从+双写 |
| 3 | 大实例不控制大小就开 bgsave | fork 秒级停顿 + 内存翻倍 | 单实例 ≤10GB，大了上 Cluster |
| 4 | 重写期间内存无余量 | 写时复制 OOM | 内存预留 30~50%，监控 rss |
| 5 | AOF 文件损坏直接重启 | 启动失败 | `redis-check-aof --fix` 修复后再启 |
| 6 | 只在本机持久化 | 磁盘坏 = 数据没 | 定时异地备份 + 演练 |
