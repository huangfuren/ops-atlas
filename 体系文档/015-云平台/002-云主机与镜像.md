## 1. 实例选型：规格族与场景

选型就是三问：**CPU 内存配比、是否突发、要不要本地盘**：

| 规格族 | 特点 | 场景 |
|---|---|---|
| 共享型（t6 等） | CPU 有性能基线限制，超基线计费 | 测试机——**生产不要用** |
| 通用型（g7 等） | 1:4 内存配比 | 大多数应用 |
| 计算型（c7 等） | 1:2 | 计算密集（编译/转码） |
| 内存型（r7 等） | 1:8 | 内存密集（Redis/缓存中间件） |
| 本地盘型（i 系列） | 带 NVMe 本地盘，性能高 | 数据库/日志——**本地盘不支持快照迁移，释放即丢** |

运维纪律：**生产实例跨 AZ 部署**（001 §1），规格族同代对齐（避免不同代实例的性能与网络差异）。

## 2. 镜像体系：三种来源

| 来源 | 场景 | 运维要点 |
|---|---|---|
| 公共镜像 | 官方 OS（Alibaba Cloud Linux/Ubuntu/CentOS） | 干净底座——装什么你自己决定 |
| **自定义镜像** | 从已有实例/快照制作——预装应用与配置 | 团队的"黄金镜像"：新机从镜像起，不是从裸机装起 |
| 云市场镜像 | 第三方预装产品 | 付费与安全自查 |

**黄金镜像工作流**：装好一台标准机 → 制作自定义镜像 → 之后的实例全部从镜像起 → 应用变更通过"重做镜像 + 替换实例"发布——与「容器」002 的镜像思想一致（不可变交付），只是粒度是整机。镜像要与快照区分：**镜像用于创建实例，快照用于保存/回滚云盘**（00-术语表易混）。

## 3. 生命周期与计费：什么状态会丢数据

| 状态 | 数据后果 | 计费 |
|---|---|---|
| **停机**（不释放） | 数据保留 | 包月不变；按量可选"节省停机模式"（计算费停收、磁盘照收） |
| **释放**（销毁） | **系统盘默认随释放删除**；数据盘看"随实例释放"开关 | 停止计费 |

⚠️ **两条铁律**：① 重要数据盘把"随实例释放"关掉，或先做快照再释放；② **释放前先打快照**——释放不可逆，回收站（如有）保留期有限。按量 vs 包月：测试与突发按量，**长期稳态负载包年包月便宜数倍**（00-术语表易混）。

## 4. 登录与密钥

| 方式 | 要点 |
|---|---|
| SSH 密钥对 | 创建密钥对 → 绑定实例 → 私钥妥善保管——**生产首选**（密码可被暴力破解） |
| 密码 | 初始密码一次性的多；改密后重启生效 |
| 会话管理/Workbench | 网页登录——应急用，不替代 SSH 纪律 |

SSH 加固全套（禁 root/改端口/AllowUsers）见「安全运维」001——云上实例同样适用，别因为"在云上"就放松（001 §4 的事实：公网裸奔的 Redis 几分钟沦陷，裸奔 SSH 同理）。

## 5. 磁盘体系：系统盘与数据盘

| 盘 | 用途 | 要点 |
|---|---|---|
| 系统盘 | OS 所在，实例释放默认删除 | 重要数据不放系统盘 |
| 数据盘 | 独立云盘，可挂/卸/扩容 | "随实例释放"开关决定生死；**云盘可在线扩容**（分区+文件系统还要手动扩） |

云盘性能与规格族绑定（ESSD 各等级 IOPS 不同）——数据库类应用选高 IOPS 盘。扩容流程：控制台扩云盘 → 实例内 `growpart` + `resize2fs/xfs_growfs` 扩文件系统——**只扩云盘不扩文件系统 = 白扩**。

## 6. 坑表

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 重要数据盘开着"随实例释放" | 释放实例 = 数据消失 | 关开关或先快照 |
| 2 | 释放前没打快照 | 不可逆销毁 | 释放 SOP 第一步永远是快照 |
| 3 | 只扩云盘没扩文件系统 | df 看到的还是旧大小 | growpart + resize2fs 两步 |
| 4 | 生产用共享型实例 | 基线限制导致性能抖动 | 生产用企业级规格族 |
| 5 | 密码登录生产机 | 暴力破解风险 | 密钥对 + 禁密码（安全运维 001） |
| 6 | 单 AZ 部署高可用 | AZ 故障全挂 | 跨 AZ + SLB |
