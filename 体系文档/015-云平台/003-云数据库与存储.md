## 1. RDS：托管数据库的责任边界

RDS 不是"新的数据库"，是**托管的 MySQL/PG**——选型与 SQL 优化仍看「数据库」010/007。责任边界（000 §主线）落到 RDS 上：

| 事项 | RDS 接管 | 你仍负责 |
|---|---|---|
| 主机/OS/打补丁 | 是 | 否（小版本可能要你确认） |
| 备份执行 | 是（自动备份） | **保留天数、跨地域备份、恢复演练** |
| 高可用与切换 | 是（主备架构） | **切换后应用重连、只读实例延迟** |
| 参数配置 | 部分（很多锁定） | **可改参数的设置** |
| 慢 SQL 与索引 | 否 | **全部是你的** |
| 容量与规格 | 否（扩容你操作） | **全部是你的** |
| 数据正确性 | 否 | **全部是你的**（误删、误更新） |

一句话（呼应「数据库」000 全貌）：**RDS 接管机器，不接管 SQL 与数据**——线上 80% 的数据库问题责任仍在运维侧。

## 2. RDS 的高可用与只读实例

| 形态 | 解决什么 | 运维要点 |
|---|---|---|
| **主备版**（高可用系列） | 主备自动切换，故障秒级 | 切换后应用连接会断——**驱动要有重连**；白名单与连接串走代理地址 |
| **只读实例** | 读写分离分担读压力 | 有复制延迟——写后立即读走主库；只读实例数量按读 QPS 扩 |
| 数据库代理 | 读写分离与连接复用 | 应用连代理地址，免改代码 |

对比自建（「数据库」006 主从复制）：RDS 把复制与切换做成了产品——**你的职责从"维护复制"变成"配置备份策略 + 监控延迟 + 演练恢复"**。

## 3. OSS：对象存储

OSS 是**按 key 存取的对象存储**（AWS 对照 S3）——适合日志归档、备份文件、静态资源；不是文件系统（随机写不行，挂载用 NAS）。

运维四件事：

1. **存储类型与生命周期**：标准（热）→ 低频 → 归档 → 冷归档；配**生命周期规则**按前缀自动转换——日志类数据不配生命周期就是成本的定时炸弹。
2. **内网端点**：同 Region 的 ECS 走内网端点——**公网流出是流量费大头**（00-术语表症状）。
3. **访问权限**：Bucket 默认私有；跨账号/公开读用 STS 或 ACL，**绝不 Bucket 全公开**（历史泄露事件的高发原因）。
4. **版本控制**：开启后覆盖写保留历史版本——误删误覆盖的保险。

## 4. 快照与备份策略

| 对象 | 机制 | 纪律 |
|---|---|---|
| ECS 云盘快照 | 时间点副本，增量存储 | 生产盘每日快照 + 保留期策略；释放实例前必打 |
| RDS 自动备份 | 全量+binlog，默认保留 7 天 | **延长到业务可接受的天数**（默认 7 天常不够）+ 开跨地域备份 |
| RDS 手动备份 | 大变更前必做 | 变更 SOP 的第一步 |
| 恢复演练 | 用备份真的恢复一次 | 没演练过的备份不算备份（「数据库」005 同口径） |

## 5. 坑表

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | RDS 备份保留天数用默认 7 天 | 误操作第 10 天才发现，备份已过期 | 按业务延长 + 跨地域 |
| 2 | OSS Bucket 公开读 | 数据泄露的高发原因 | 私有 + STS/签名 URL |
| 3 | OSS 公网直连传输 | 流量费暴涨 | 内网端点 + 生命周期治理 |
| 4 | 只读实例当强一致用 | 写后读不到 | 写后读走主库 |
| 5 | 云盘扩容只做了一半 | df 还是旧容量 | 控制台扩 + 实例内扩文件系统（002 §5） |
| 6 | 恢复只在故障时第一次做 | 真恢复时发现备份不可用 | 定期演练（005 同口径） |
