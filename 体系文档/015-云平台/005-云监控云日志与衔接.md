## 1. 云监控：自带指标的边界

每个云产品自带基础指标（ECS 的 CPU/网络、RDS 的连接数与 IOPS、SLB 的流量），在云监控控制台可见、可配告警。

**边界**：云监控只覆盖**产品级指标**——主机内部（进程/磁盘内文件/自定义业务指标）它看不见。所以：

| 层 | 采什么 | 谁 |
|---|---|---|
| 云监控 | 产品级：实例 CPU、RDS 连接数、SLB 流量 | 云厂商自动采，告警在云控制台配 |
| 自建 Prometheus | 主机内部 + 应用指标 + 中间件深度指标 | node_exporter 等采集（「监控」007） |

两层互补而非替代——**产品级告警放云监控（断电断网它最准），业务与主机深度指标放自建**。

## 2. 操作审计：云上的"谁改了什么"

操作审计（ActionTrail，AWS 对照 CloudTrail）记录控制台与 API 的**全部操作**：谁、何时、从哪个 IP、改了什么资源。

三个运维场景：

1. **追溯误操作**：资源被改/被删，审计里搜资源 ID 定位操作人与时间。
2. **安全合规**：异常时间、异常 IP 的操作告警——「安全运维」005 的云上延伸。
3. **配置漂移溯源**：004 §3 的漂移检测发现资源不符，审计告诉你谁在控制台改的。

纪律：**审计日志开全球地域事件 + 推送到 OSS 长期留存**（默认只留 90 天，合规场景要长存——「安全运维」005 §4）。

## 3. 与自建体系的衔接：两层观测

| 数据 | 云监控 | 自建体系 |
|---|---|---|
| 产品级指标 | 自动采集 + 控制台告警 | 可经 exporter/export 落入 Prometheus 统一 |
| 主机内部指标 | 看不见 | node_exporter（「监控」007） |
| 应用指标 | 看不见 | 业务埋点（「Go」016 三支柱） |
| 日志 | 云日志产品 | Filebeat/Loki 自建（「日志」板块） |
| 审计 | ActionTrail 原生 | 推 OSS 长存 |

**衔接方式**（按投入从小到大）：① 云监控告警走 webhook 进 IM（最少改动）；② 云监控指标导出进自建 Prometheus（统一看板）；③ 全量自建，云监控只留产品级兜底。**选型判断**：资源在云上占多数 → 以云监控为主自建为辅；混合云/强 Prometheus 体系 → 自建为主云监控兜底。

## 4. 账单与标签：成本的运维纪律

云账单是运维的"第五维观测"——**账单异常往往是资源泄漏的第一信号**（没人管的按量实例、遗忘的 EIP、打满的公网流量）。

| 纪律 | 做法 |
|---|---|
| **资源标签** | 所有资源打 `env/app/owner` 标签——分账与定位的基础；IaC 里标签随代码统一（004） |
| **分账单** | 按标签拆分月账单，环比异常即排查 |
| **泄漏清单** | 空跑的按量实例、未绑定的 EIP、孤儿磁盘快照——每月巡一遍 |
| **预算告警** | 成本超过阈值告警——像监控内存一样监控账单 |

## 5. 坑表

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 只靠云监控不看主机内部 | 进程级/业务级问题全盲 | 两层观测互补 |
| 2 | 操作审计默认 90 天 | 追溯窗口不够，合规不过 | 推送 OSS 长存 |
| 3 | 没有资源标签 | 账单拆不了、泄漏找不到主 | 标签规范 + IaC 统一打 |
| 4 | OSS 公网流出放任 | 流量费成倍 | 内网端点 + CDN |
| 5 | 云产品告警配了没人看 | 告警疲劳重演（「监控」006 同病） | 告警也走分级与分组 |
