## 1. 账号生命周期

账号从建到删的四个动作与核查命令：

| 阶段 | 动作 | 核查 |
|---|---|---|
| 创建 | 人人独立账号（禁共享），指定 Shell | `grep ops /etc/passwd` |
| 授权 | 按角色加组，sudo 白名单 | `sudo -l -U 用户名` |
| 休眠 | 长期不用 → `usermod -L 锁定` 而非删除（保留证据） | `passwd -S 用户名` |
| 离职/清退 | 当天锁定 + 移出 sudo + 撤销密钥（`authorized_keys` 清理） | `find / -name authorized_keys` 逐机清 |

⚠️ **离职清退是最容易漏的**：密钥散在几十台机器的 `authorized_keys` 里——用配置管理批量清，或定期审计比对。

## 2. sudo 最小授权

**纪律：不给 ALL，按需白名单**。`visudo` 编辑（语法检查防错）：

```sudoers
# 运维组：允许重启指定服务与看日志，不给全部
Cmnd_Alias SVC = /bin/systemctl restart nginx, /bin/systemctl restart php-fpm, /bin/journalctl
%ops ALL=(root) NOPASSWD: SVC

# 应急账号：全量但每次留记录
emergency ALL=(root) /usr/bin/sudoedit /etc/*
Defaults logfile="/var/log/sudo.log"
```

验证：`sudo -l` 看自己实际可用的命令清单；`/var/log/sudo.log` 留痕。**`su -` 直接切 root 绕过 sudo 审计**——生产禁用 root 密码登录，逼所有人走 sudo 留痕。

## 3. SSH 加固清单

`/etc/ssh/sshd_config` 逐项加固（改完 `sshd -t` 校验语法再 reload；**改前开一个已登录的会话做回滚保险**）：

| # | 加固项 | 配置 | 验证 |
|---|---|---|---|
| 1 | 禁 root 密码登录 | `PermitRootLogin prohibit-password` | 远程 `ssh root@` 被拒 |
| 2 | 禁密码登录（仅密钥） | `PasswordAuthentication no` | `ssh -o PreferredAuthentications=password` 失败 |
| 3 | 白名单用户/组 | `AllowGroups ops` | 白名单外用户被拒 |
| 4 | 改端口（可选，防扫描噪音） | `Port 22222` | `ss -tlnp` 确认监听 |
| 5 | 限制重试与超时 | `MaxAuthTries 3` + `LoginGraceTime 30` | 观察日志频率 |
| 6 | 关 X11/空转发 | `X11Forwarding no` | — |

配套：`fail2ban`（多次失败自动封禁 IP）；密钥格式用 ed25519（`ssh-keygen -t ed25519`）；私钥自持、加 passphrase。

## 4. 堡垒机与登录审计

生产 SSH 的标准形态：**人 → 堡垒机（账号托管+录屏审计）→ 目标机（只信任堡垒机来源）**。没有堡垒机时的替代：

| 手段 | 覆盖 |
|---|---|
| 目标机 `auth.log`/`secure` 集中采集 | 登录事件留痕（005 §1） |
| sudo.log 集中采集 | 提权行为留痕 |
| 命令审计（auditd execve 规则） | 全命令底账（成本高，高危机才开） |

登录审计的观察命令：`last`（历史登录）、`lastb`（失败尝试）、`grep 'Accepted' /var/log/auth.log`（成功登录明细）——出现陌生 IP 即告警。

**向第三方开通临时堡垒机账号（四步）**：① 先查既有 guest 账号（命名带专用后缀）——有则只延期激活时间；② 没有则新建：邮箱可占位、绑定用户组角色、**强制启用 MFA**、激活时间设**当日 23:59:59**（到期自动失效，不留暗门）；③ 用该账号登录一遍验证资源可见性，MFA 绑到交付人手上；④ 交付三样：入口地址、临时账号、动态码获取方式（每次登录现要，短时有效）。

**耗时复盘**：首次全流程实测 2 小时——响应慢 15 分钟 + 处理 10 分钟，标准化后 25~30 分钟可达；流程效率本身是记录对象（011 §四）。

## 5. 坑表

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 共享账号多人使用 | 出事无法追责 | 人人独立账号 |
| 2 | sudo 给了 ALL | 提权无边界，误操作无审计 | 命令白名单 |
| 3 | 只改了配置没重启 sshd | 加固"看起来"生效了 | `sshd -t` + reload + 远程验证 |
| 4 | 密钥无 passphrase | 私钥泄露即沦陷 | 私钥加 passphrase + 存放管控 |
| 5 | 改防火墙/SSH 后没有回滚会话 | 把自己锁在门外 | ⚠️ 改前留已登录会话，验证成功才退出 |
| 6 | 清退只删账号不删密钥 | 密钥仍在 authorized_keys 里可登录 | 批量清 authorized_keys |
| 7 | 第三方临时账号无失效时间 | 长期滞留成暗门 | 激活时间当日 23:59:59 自动失效（§4） |
