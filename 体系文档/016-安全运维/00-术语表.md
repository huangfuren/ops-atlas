# 00 术语表

> **这一文档回答**：安全运维领域的词是什么意思、两个混用词的分界、「只知道现象不知道翻哪册」往哪走。  
> **怎么用**：按名字（按主题分组）、按缩写（缩写速查）、按现象（症状反查）。  
> **只有一句话**：要加固操作回对应册；这里只保证你「认得出、分得清、找得到」。

## 01 概念与模型

| 术语 | 英文 | 一句话 |
|---|---|---|
| 纵深防御 | defense in depth | 多层防线叠加：边界→主机→应用→数据→审计，单层失守不失全局 |
| 最小权限 | least privilege | 只授予完成任务所必需的最小权限——一切加固的总原则 |
| 攻击面 | attack surface | 可被访问与利用的全部入口总和——加固就是收窄攻击面 |
| 纵向 privileging | privilege escalation | 提权：从低权限获得高权限——加固的防守目标 |
| 堡垒机 | bastion host | 统一运维入口：审计录屏、账号托管——生产 SSH 不直连 |
| 双因素认证 | 2FA/MFA | 密码之外再加一道（令牌/短信）——防密码泄露 |
| 横向移动 | lateral movement | 攻入一台后向内网其他机器扩散——纵深防御防的就是它 |

## 02 主机与加固

| 术语 | 英文 | 一句话 |
|---|---|---|
| 加固 | hardening | 按基线收窄系统默认配置的过程 |
| 基线 | baseline | 一组"最低安全配置标准"——加固的验收依据 |
| CIS 基准 | CIS Benchmark | 业界广泛使用的基线标准集（Linux/云产品都有分册） |
| sudo | superuser do | 受控提权：最小授权 + 命令白名单 |
| 密钥对 | key pair | SSH 首选认证：公钥放服务器、私钥自持 |
| SELinux / AppArmor | — | 强制访问控制（MAC）：进程级权限天花板 |
| auditd | Linux Audit Daemon | 内核级系统调用审计——"谁干了什么"的底账 |
| chattr | change attribute | 文件级不可修改位（+i）——防篡改的最后一道 |

## 03 网络与边界

| 术语 | 英文 | 一句话 |
|---|---|---|
| 默认拒绝 | default deny | 未明确允许的一律拒绝——防火墙策略的总原则 |
| nftables | — | iptables 的后继：内核包过滤统一框架 |
| conntrack | connection tracking | 连接跟踪表：有状态防火墙的底账，打满即拒绝新建 |
| WAF | Web Application Firewall | Web 应用层防火墙：挡 SQLi/XSS 等应用攻击 |
| IDS / IPS | Intrusion Detection / Prevention | 入侵检测（旁路告警）/ 防御（串联阻断） |

## 04 漏洞与合规

| 术语 | 英文 | 一句话 |
|---|---|---|
| CVE | Common Vulnerabilities and Exposures | 公开漏洞的全球编号——漏洞情报的索引 |
| CVSS | Common Vulnerability Scoring System | 漏洞严重度评分（0~10）——修复优先级的输入之一 |
| 漏洞扫描 | vulnerability scanning | 自动化发现已知漏洞与弱配置——基线的机器检查 |
| 补丁管理 | patch management | 漏洞修复的流程化：评估→测试→灰度→全量 |
| 等保 2.0 | 网络安全等级保护 2.0 | 国内合规框架：定级→备案→建设整改→测评→监督 |
| 应急响应 | incident response | 入侵事件的组织化处置：准备→遏制→根除→恢复→复盘 |

## 最容易混的 10 对

| 容易混 | 一句话差别 | 去哪 |
|---|---|---|
| 认证 vs 授权 | 你是谁 vs 你能干什么——SSH 是认证，sudo 是授权 | 001 §1 |
| 漏洞 vs 威胁 vs 风险 | 漏洞是缺陷，威胁是主体，风险=漏洞×威胁×影响 | 003 §1 |
| IDS vs IPS | 旁路告警 / 串联阻断 | 003 §3 |
| 基堡机 vs 跳板机 | 堡垒机强在审计与账号托管；跳板机只是中转 | 001 §4 |
| 基线 vs 加固 | 基线是"标准"，加固是"达标的过程" | 003 §1 |
| 安全组 vs 主机防火墙 | 云平台实例级白名单 / 系统级规则——双层都要管（衔接 015 001） | 002 §2 |
| SUID vs SGID | 执行者获得文件属主 / 属组权限 | 「Linux」003 |
| 对称 vs 非对称加密 | 一把钥匙 / 公私钥对——SSH 两把都用 | 「网络」005 |
| 漏扫 vs 基线核查 | 查已知漏洞 / 查配置合规——互补不互替 | 003 §2 |
| 应急 vs 复盘 | 应急是处置当时；复盘是沉淀机制（衔接 SRE 003） | 005 §4 |

## 按症状反查

| 现象 | 大概率病根 | 去哪 |
|---|---|---|
| SSH 被大量尝试登录 | 公网暴露 + 密码认证 | 001 §3 |
| `last` 里有陌生 IP 登录成功 | 账号泄露或弱口令 | 001 §4 · 005 §3 |
| 测评发现"未开启审计" | auditd 未配置 | 005 §1 |
| 漏扫报告一堆"中危配置" | 基线未做 | 003 §2 |
| 防火墙改规则后把自己锁外 | 无回滚路径 | 002 §3 |
| 一台机器沦陷后内网扩散 | 横向移动无阻隔 | 000 §1 |
| 服务器被植入挖矿程序 | 未授权服务暴露或弱口令 | 005 §3 |
| 误删日志无法追责 | 日志未集中留存/权限过大 | 005 §1 |
| 新机器上线忘了加固 | 无基线清单 SOP | 003 §2 |
| sudo 配置过于宽松 | ALL=(ALL) 满天飞 | 001 §2 |
