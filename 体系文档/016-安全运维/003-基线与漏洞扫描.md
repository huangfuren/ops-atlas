## 1. 基线：加固的验收标准

基线 = 一组"最低安全配置标准"——**加固是过程，基线是验收依据**。来源三选一：CIS 基准（业界标准，条目最全）、等保测评项（合规驱动，见 004）、团队自定基线（从前三者裁剪）。

基线的价值在**可机器核查**：每条都能用一条命令判定通过/不通过——这也是它与"安全意识文档"的区别。

## 2. 手工核查清单（Linux 基线核心 15 条）

每条：核查命令 → 期望 → 不达标处理。完整版按 CIS 分册扩展，这里是运维高频子集：

| # | 核查项 | 命令 | 期望 |
|---|---|---|---|
| 1 | 密码复杂度与有效期 | `grep PASS /etc/login.defs` | PASS_MAX_DAYS ≤90，minlen ≥8 |
| 2 | 空口令账号 | `awk -F: '($2==""){print $1}' /etc/shadow` | 无输出 |
| 3 | 非 root 的 UID=0 | `awk -F: '($3==0){print $1}' /etc/passwd` | 只有 root |
| 4 | SSH 加固 | `sshd -T \| grep -E 'permitroot\|password'` | 001 §3 清单 |
| 5 | 关闭无用服务 | `systemctl list-unit-files --state=enabled` | 最小化服务集 |
| 6 | 关键文件权限 | `ls -l /etc/passwd /etc/shadow` | 644 / 640 或更严，属主 root |
| 7 | umask 全局值 | `grep -i umask /etc/profile /etc/bashrc` | 022 或更严 |
| 8 | core dump 关闭 | `ulimit -c` / `cat /proc/sys/fs/suid_dumpable` | 0 |
| 9 | 时间同步 | `timedatectl status` | NTP active（日志时间线的前提） |
| 10 | 日志服务在跑 | `systemctl status rsyslog/journald` | active |
| 11 | auditd 在跑 | `systemctl status auditd` | active（005 §1） |
| 12 | 防火墙默认拒绝 | `nft list ruleset` | policy drop + 白名单（002） |
| 13 | 危险命令处理 | `which KEYS/FLUSHALL 类比` | 见「Redis」007 §2 同思路 |
| 14 | 内核风险参数 | `sysctl kernel.randomize_va_space` | ≥2（ASLR 开） |
| 15 | 补丁水平 | `包管理器检查可升级安全补丁` | 无高危未修 |

**落地形态**：清单脚本化（一条 bash 输出 PASS/FAIL 表）——新机上线跑一遍，月度巡检跑一遍；结果与 003 §3 的漏扫互为补充。

## 3. 漏洞扫描：工具形态

| 工具 | 形态 | 场景 |
|---|---|---|
| **OpenVAS/Greenbone** | 开源漏扫，自建部署 | 内网周期扫描，成本零 |
| Nessus / 商用漏扫 | 商业产品 | 企业有预算与合规要求 |
| 云厂商基线检查 | 云平台自带（安全中心） | 云主机一键核查（衔接 015） |
| `lynis` | 轻量命令行审计 | 单机快速基线审计（`lynis audit system`） |

扫描纪律：**生产机扫描选低峰与只读模式**；扫描报告 ≠ 威胁——要按 §4 修复优先级排序后再排期。

## 4. 修复优先级：CVSS 不是唯一

修复排序 = **可利用性 × 暴露面 × 业务影响**，CVSS 分数只是输入之一：

| 优先级 | 特征 | 动作 |
|---|---|---|
| P0 立即 | 可远程利用 + 已有公开利用代码 + 服务暴露公网 | 当天修复或临时缓解（下线/限源） |
| P1 本周 | 可远程利用，暴露在内网但可达 | 本周窗口修复 |
| P2 本月 | 需本地权限 / 影响有限 | 纳入月度补丁窗口 |
| P3 观察 | 无缓解措施可用 / 升级风险大于收益 | 记录风险，制定长期方案 |

补丁流程：**评估（兼容性）→ 测试环境 → 灰度 → 全量**（与「CICD」007 发布纪律同构）——⚠️ 安全补丁也要走灰度，"因为安全就直接全量"是另一种事故。

## 5. 坑表

| # | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 基线核查纯人工逐条看 | 覆盖不全且不可持续 | 脚本化 PASS/FAIL |
| 2 | 漏扫报告直接转发不排序 | 团队被几百条"中危"淹没 | 按 §4 排序输出行动清单 |
| 3 | 只扫不修 | 报告越攒越厚，风险不变 | 修复排期与验收闭环 |
| 4 | 新机不做基线 | 每台新机都在重复历史漏洞 | 新机上线 SOP 第一步跑基线 |
| 5 | 安全补丁不走灰度 | 补丁引入兼容性事故 | 补丁也走灰度流程 |
