# 安全方法论

> **这一册回答**：纵深防御为什么立得住——「最小权限、默认拒绝、可验证、可回滚」四条方法论，以及怎么用它们判断一套加固方案够不够格。
> **给谁读**：负责主机安全的运维/SRE；也用于评审一份加固清单「是不是真的在降低风险」。
> **工具无关**：ssh_config 参数、nftables 语法在正文册；本册给的是它们要服务的原则。

## 最小权限是一切的总原则

账号、sudo、防火墙、ACL——每一层都只给「完成所必需」的权限：

1. **人最小化**：账号按需开通、按期回收，sudo 按命令白名单授权而不是 ALL（011）。
2. **服务最小化**：进程用专用低权用户跑，能不给 shell 就不给——`nologin` 是大多数服务账号的归宿。
3. **网络最小化**：端口只对需要的源开放，默认拒绝、按需放行（012）。
4. **权限会腐化**：人员流动、业务变更会让「临时权限」变永久——定期复核（013 的基线核查）就是给权限保鲜。

## 默认拒绝

- **白名单思维**：防火墙规则从「全拒绝 + 按需放行」开始，而不是「全放行 + 事后补堵」——补堵永远慢于攻击（012）。
- **变更走流程**：安全组/防火墙的每次变更都是变更管理事件——可追溯、可回滚（012 的策略变更流程）。
- **锁门之前先留钥匙**：改 SSH 端口、禁 root、改防火墙默认策略，都是可能把自己锁在门外的操作——**回滚路径先写下来再动手**（011/012 的 ⚠️ 注记）。

## 可验证

- **没有验证的加固等于没做**：每条加固措施给验证命令——「禁止 root 登录」要 `ssh root@host` 实测被拒才算数（011）。
- **基线是验收依据**：加固是过程，基线是标准——CIS 基准裁剪出团队基线，周期复核（013）。
- **漏扫收尾**：加固完扫一遍，高危漏洞按「可利用性 × 暴露面」排优先级，不为 CVSS 分数跳舞（013）。

## 审计与应急是兜底

- **日志留痕**：登录、sudo、关键操作进审计日志，留存期满足合规（015 的留存口径）。
- **应急五步**：发现 → 遏制 → 根除 → 恢复 → 复盘，先遏制再根除——别在攻击还在进行时忙着找根因（015）。
- **复盘接「SRE」013**：入侵后的技术复盘按无指责流程走，防线的补强靠系统改进不靠处分（015 与 SRE 板块的握手）。

## 反模式

- ❌ sudo 全体 ALL——一次凭据泄露就是整机沦陷。
- ❌ 加固做完不复核——半年后基线漂移，加固成果清零。
- ❌ 应急预案只在文档里——第一次跑应急剧本不应该在被入侵当晚。
- ❌ 防火墙规则注释缺失——三个月后没人知道那条放行为什么存在，全变成不敢删的规则。

## 自测

1. 最小权限在哪四层落地？（人、服务、网络、定期复核）
2. 默认拒绝和白名单思维是什么关系？（从全拒绝开始按需放行，不事后补堵）
3. 为什么每条加固要给验证方法？（没有验证的加固等于没做）
4. 被入侵后先做什么？（遏制，再根除——顺序错了影响面会扩大）
