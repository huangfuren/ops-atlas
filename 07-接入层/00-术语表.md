# 00 术语表

> **这一文档回答**：某个词是什么意思、两个长得像的概念差在哪、「只知道现象、不知道该翻哪一册」时往哪走。  
> **怎么用**：三种查法——按名字（下面按册分组）、按英文或缩写（缩写速查）、按现象（症状反查）。  
> **只有一句话**：要原理和命令回对应册；这里只保证你「认得出、分得清、找得到」。

## 000 接入层全貌

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 接入层 | edge / ingress layer | 流量进入系统的第一跳：DNS、CDN、负载均衡、网关都在这一层 |
| 反向代理 | reverse proxy | 替后端接请求的中间人。客户端不知道后面有几台服务器 |
| 正向代理 | forward proxy | 替客户端出门的中间人。方向相反：一个藏服务器，一个藏客户端 |
| 南北向 / 东西向流量 | north-south / east-west | 进出系统的流量 / 系统内部的流量。接入层管南北向 |
| 七层网关 | L7 gateway | 能看懂 HTTP 并按内容路由的入口。Nginx/HAProxy 都能做 |
| 云负载均衡 | cloud LB | 云厂商托管的 LB（SLB/CLB、ELB）。省心但配置项与自建有差异 |
| WAF | Web Application Firewall | 应用层防火墙，拦注入与扫描。通常串在接入层旁或前面 |

## 001 Nginx 配置体系

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 指令 | directive | 配置文件里的最小语句：`listen 80;`。分号结尾，花括号成块 |
| 配置块 / 上下文 | context | main → events → http → server → location 的层级。**内层继承外层，内层可覆盖** |
| server 块 | server | 一个虚拟主机：靠 listen + server_name 区分同一台机器上的多个站点 |
| location | location | URI 的匹配规则：`=` 精确、`^~` 前缀、`~` 正则。**顺序决定谁生效** |
| include | include | 拆分配置文件的引入指令。Ubuntu 的 sites-enabled 就是它实现的 |
| `nginx -t` | — | 语法检查。**reload 之前必跑**，过了才谈生效 |
| 平滑重载 | reload (`SIGHUP`) | 新 worker 接管、旧 worker 处理完存量再退，不断连接。**失败旧配置继续服务** |
| worker 进程 | worker process | 干活的进程数，通常 `auto` = 核数。连接都是它处理的 |
| 事件驱动 | event-driven | 单 worker 异步处理成千上万连接，与 Apache 每连接一线程的分界 |

## 002 反向代理

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| proxy_pass | — | 转发指令。**末尾带不带 URI 决定后端收到什么路径**，全册最易错的一条 |
| 转发头 | forwarded headers | X-Real-IP、X-Forwarded-For、X-Forwarded-Proto：把客户端真实信息告诉后端 |
| Host 头 | proxy_set_header Host | 不设的话后端收到的 Host 是 upstream 名字，多站点路由会乱 |
| 连接超时 | proxy_connect_timeout | 与后端建连的超时。**连不上是 502 的第一来源** |
| 读写超时 | proxy_read/send_timeout | 两次成功读写之间的间隔超时。**不是总时长**，长连接业务要单独调 |
| 缓冲 | proxy_buffering | 后端响应先攒到 Nginx 再给客户端。关掉它，慢客户端会拖住后端 |
| WebSocket 升级 | Upgrade / Connection | WS 需要显式转发 Upgrade 头，否则握手必失败 |
| 内网穿透 | internal | `internal` 指令限定的 location 只允许内部转发，不能被外部直接命中 |

## 003 负载均衡与 upstream

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| upstream | upstream | 后端服务器组的定义。server 指令逐台登记 |
| 轮询 / 加权轮询 | round-robin / weight | 默认依次分发；weight 按 5:2:1 之类分流量 |
| ip_hash | — | 按客户端 IP 固定到同一后端。**会破坏负载均匀度**，是最粗暴的会话保持 |
| least_conn | least connections | 发给当前连接数最少的后端。处理时长差异大时比轮询公平 |
| 备份服务器 | backup | 标记 `backup` 的机器平时不接活，全员挂了才顶上 |
| 失败判定 | max_fails / fail_timeout | N 秒内失败 N 次就摘除一段时间。**被动健康检查**，摘除窗口内无人探测 |
| 会话保持 | session persistence | 同一用户固定到同一后端：ip_hash 或 cookie 插入 |
| 主动健康检查 | active health check | 定期探测后端。**开源版 Nginx 没有**，商业版/三方模块/HAProxy 才有 |
| keepalive 连接池 | upstream keepalive | 到后端的长连接复用，省每次握手。数量要配 |

## 004 HTTPS 与证书运维

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| TLS 终止 | TLS termination | 在 Nginx 解密，后端走 HTTP。**排障先确认自己在终止点的哪一侧** |
| 证书链完整性 | chain completeness | 服务器要发「自己的证书 + 中间证书」。**缺中间证书是部署第一翻车** |
| SNI | Server Name Indication | 握手时带域名，一个 IP 挂多张证书的前提 |
| HTTP/2 | — | `listen 443 ssl http2;` 开启。多路复用省连接，但队头问题转移到 TCP |
| 强制跳转 | http→https | 80 端口 301 到 https。配合 HSTS 防降级 |
| HSTS | Strict-Transport-Security | 告诉浏览器一段时间内强制 https。**开了以后回 http 会很久改不回来** |
| 证书续期 | renewal | certbot 自动续（Let's Encrypt）或人工轮换；续完必须 reload |
| 到期监控 | expiry monitoring | 监控面板盯到期天数。**35 天告警、7 天升级告警**是常见阈值 |
| OCSP 装订 | OCSP stapling | Nginx 代查证书吊销状态并缓存，加快握手、保隐私 |

## 005 日志与访问控制

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| log_format | — | 自定义日志字段。**把 upstream 响应时间记进去**，502 取证全靠它 |
| 访问日志 / 错误日志 | access log / error log | 谁来了 / 出了什么事。排障先看 error log 的级别与时间 |
| 日志切分 | log rotation | logrotate 或 USR1 信号切换文件。不切就是磁盘杀手 |
| limit_req | — | 请求速率限制（漏桶）：`rate=10r/s` + burst 突发容量，超了返回 503/429 |
| limit_conn | — | 并发连接数限制。一个 IP 开 500 个连接刷流量就靠它拦 |
| 限流键 | key | `$binary_remote_addr` 等，按什么维度限。**上 CDN 后要用真实 IP 键** |
| auth_basic | — | HTTP 基本认证。内部系统快速加门的姿势 |
| allow / deny | — | IP 白名单黑名单，满足即停。封扫描器与只放办公网都靠它 |
| 429 / 503 | — | 限流被触发的两种回法：429 更语义化，Nginx 默认 503 |

## 006 性能调优

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| worker_processes | — | `auto` 起步，等于 CPU 核数。不是越大越好 |
| worker_connections | — | 单 worker 的连接上限。**总容量 ≈ worker × connections，还要除以 4**（每个请求占多个连接） |
| ulimit 联动 | nofile | worker_connections 再大也过不去系统 `nofile` 限制，两者要一起看 |
| sendfile | sendfile(2) | 静态文件零拷贝直发。开静态加速的标配 |
| gzip | — | 文本压缩传输。**图片视频别压**，白费 CPU |
| 客户端长连接 | keepalive_timeout | 浏览器复用连接省握手。太长占连接，太短费握手 |
| upstream 长连接 | keepalive (upstream) | 到后端复用连接。**配了数量还要配 `proxy_set_header Connection "";`** |
| 压测 | load testing | wrk / ab 打流量验证调优效果。**先压测试环境，带监控看瓶颈在哪层** |

## 007 故障排查手册

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 502 | Bad Gateway | 后端连不上 / 进程不在 / 回了非法响应。**先 ping 端口再看应用日志** |
| 504 | Gateway Timeout | 后端接了但超时没回。慢查询、慢接口居多 |
| 413 | Payload Too Large | `client_max_body_size` 太小，上传必踩 |
| 499 | Client Closed Request | 客户端等不及先挂断——**慢的后端 + 急的用户** |
| upstream timed out | — | error log 里的原话，对应 504，去查后端为什么慢 |
| connect() failed | — | error log 里的原话，对应 502，去查后端起没起 |
| 取证顺序 | triage order | error log → access log（upstream 字段）→ 后端日志 → 抓包。**别一上来改配置** |
| 循环重定向 | redirect loop | http→https 跳转与代理头打架，浏览器报「重定向次数过多」 |

## 008 高可用接入

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| HAProxy | HAProxy | 专业四层/七层负载均衡器。**主动健康检查是它对开源 Nginx 的最大优势** |
| frontend / backend | — | HAProxy 的两半：接流量的入口定义 + 分流的后端定义 |
| ACL | Access Control List | HAProxy 的条件语法：按域名、路径、头分流与拦截 |
| Keepalived | Keepalived | VRRP 高可用套件：主挂了 VIP 漂到备机 |
| VIP | Virtual IP | 对外服务的浮动 IP，永远跟着主节点走 |
| 脑裂 | split-brain | 主备失联都抢 VIP，流量一分为二。**预防靠仲裁线路/防火墙策略** |
| 主动健康检查 | active check | Keepalived/HAProxy 定期探测后端，坏的先摘除。被动式（Nginx 开源版）做不到 |
| 双机热备演练 | failover drill | 人工 kill 主机验证 VIP 漂移时长。**没演练的高可用不算高可用** |

## 缩写速查

| 缩写 | 全称 | 意思与出处 |
| --- | --- | --- |
| ACL | Access Control List | 访问控制列表：Nginx 的 allow/deny、HAProxy 的条件语法（005 / 008） |
| CDN | Content Delivery Network | 内容分发网络，接入层的前一跳（000） |
| HSTS | HTTP Strict-Transport-Security | 强制浏览走 https 的响应头（004） |
| HTTP/2 | — | 应用层多路复用协议（004） |
| LB | Load Balancer | 负载均衡器（003 / 008） |
| OCSP | Online Certificate Status Protocol | 证书吊销状态在线查询，装订到握手省一次外查（004） |
| SNI | Server Name Indication | 握手带域名，一 IP 多证书的前提（004） |
| TLS | Transport Layer Security | 传输层加密（004） |
| VIP | Virtual IP | 浮动服务 IP，Keepalived 漂移的目标（008） |
| VRRP | Virtual Router Redundancy Protocol | 网关/入口主备选举协议（008） |
| WAF | Web Application Firewall | 应用层防火墙（000） |
| WS | WebSocket | 全双工长连接协议，需要代理转发 Upgrade 头（002） |

## 最容易混的 14 对

| 容器易混 | 一句话差别 | 怎么确认 | 册 |
| --- | --- | --- | --- |
| 正向 vs 反向代理 | 藏客户端 / 藏服务器 | 服务端日志里看到的是谁的 IP | 000 |
| reload vs restart | 平滑交接 / 断连重来 | `nginx -s reload` 失败旧配置还在服务 | 001 |
| proxy_pass 带 URI vs 不带 | 替换路径 / 原样拼接 | 后端 access log 里看真实收到的路径 | 002 |
| X-Real-IP vs X-Forwarded-For | 单值真实 IP / 逐跳追加的链 | 多层代理时 XFF 是逗号串 | 002 / 005 |
| limit_req vs limit_conn | 限速率 / 限并发 | 一个管「每秒几个」，一个管「同时几个」 | 005 |
| Nginx vs HAProxy | 万能 web 服务器兼 LB / 专业 LB | 要主动健康检查优先 HAProxy | 000 / 008 |
| 四层 vs 七层 | 只看 IP 端口 / 能看 HTTP 内容 | 能按 URL 分流就是七层 | 000 / 008 |
| 被动 vs 主动健康检查 | 失败了才摘 / 定期探测先摘 | 后端死了多久被发现 | 003 / 008 |
| ip_hash vs cookie 保持 | 按 IP / 按会话 | 手机换网掉会话的是前者 | 003 |
| client keepalive vs upstream keepalive | 浏览器到 Nginx / Nginx 到后端 | 两段各配各的，漏一段握手翻倍 | 006 |
| 502 vs 504 | 连不上 / 连上了但超时 | error log 原话 connect failed vs timed out | 007 |
| 499 vs 504 | 客户端先挂 / 服务端超时 | 谁先放弃连接 | 007 |
| HSTS vs 强制跳转 | 浏览器记住强转 / 服务器下发跳转 | 关掉跳转后仍走 https 的是 HSTS 在起作用 | 004 |
| Keepalived vs 双 Nginx 轮询 | 主备漂移 / 两台都接流量 | VIP 在几台机器上同时存在 | 008 |

## 按症状反查

| 现象 | 大概是 | 去哪 |
| --- | --- | --- |
| 全站 502 | 后端挂了 / 端口错 / 上游全被摘除 | 007 §7.x / 003 |
| 个别接口 504 | 后端慢查询或超时阈值太小 | 007 / 002 超时三兄弟 |
| 上传大文件 413 | client_max_body_size 太小 | 007 |
| 改了配置不生效 | 忘 `nginx -t` + reload / 改错 include 文件 / 另一实例在跑 | 001 |
| reload 后行为没变 | 旧 worker 还在处理存量 / reload 失败回退旧配置 | 001 |
| 后端拿到的都是 Nginx 的 IP | 没配 X-Real-IP / X-Forwarded-For | 002 |
| 部分用户报证书错误，多数正常 | 证书链缺中间证书 | 004 |
| 一张证书要挂多个域名 | SAN 证书 + SNI 多 server | 004 |
| 证书到期没人发现 | 没接到期监控 | 004 |
| WebSocket 握手失败 | Upgrade 头没转发 | 002 |
| 负载严重不均 | ip_hash 破坏均匀 / weight 没配 | 003 |
| 限流把正常用户也拦了 | 键选错（CDN 后用了 CDN IP）/ burst 太小 | 005 |
| 流量高峰 CPU 打满 | gzip 大文件 / SSL 全在本机 / 日志同步刷盘 | 006 |
| 静态文件 403 | 目录权限 / index 不存在 / autoindex 未开 | 001 / 007 |
| 主机挂了入口全断 | 没做高可用，上 Keepalived 双机 | 008 |
| 演练杀主后 VIP 没漂 | VRRP 通信被防火墙拦 / 优先级配错 | 008 |
