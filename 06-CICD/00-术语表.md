# 00 术语表

> **这一文档回答**：某个词是什么意思、两个长得像的概念差在哪、「只知道现象、不知道该翻哪一册」时往哪走。  
> **怎么用**：三种查法——按名字（下面按册分组）、按英文或缩写（缩写速查）、按现象（症状反查）。  
> **只有一句话**：要原理和命令回对应册；这里只保证你「认得出、分得清、找得到」。

## 000 自动化全貌

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 持续集成 | Continuous Integration, CI | 提交就自动构建 + 测试，问题当天暴露而不是上线当天暴露 |
| 持续交付 | Continuous Delivery, CD | 每次构建产出「随时可上线」的制品，上线是点一下按钮的事 |
| 持续部署 | Continuous Deployment | 连按钮都不点：过完全部门禁自动上线。胆子和自动化水平的双重考验 |
| 流水线 | pipeline | 从提交到上线的一串自动化阶段，红了哪段看哪段 |
| 制品 | artifact | 构建的产物：jar/wheel 包、tar 包、镜像。**上线上的就是它，不是代码** |
| 环境 | environment | dev / test / staging / prod 的统称。同一制品逐环境晋级，配置随环境变 |
| 环境漂移 | configuration drift | 手工改过的机器和定义的状态不一致。Ansible 的天敌也是它存在的理由 |
| 门禁 | quality gate | 流水线里「不过就停」的检查点：测试、扫描、审批 |

## 001 Git 与协作

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 三区模型 | working / staging / repository | 工作区、暂存区、本地仓库。`add` 进暂存、`commit` 进历史、`push` 上远端 |
| commit | commit | 一次带说明的快照，哈希唯一标识。回滚的一切都建立在它上面 |
| 分支 | branch | 指向某条提交线的可移动指针。建分支零成本，别在 main 上直接改 |
| merge / rebase | — | merge 造一个合并提交保留分叉史；rebase 把提交搬到新基底改写历史——**公共分支禁 rebase** |
| 冲突 | conflict | 两个人改了同一处，Git 拒绝自动合并。手改 `<<<<<<<` 区块再 add |
| tag | tag | 指向某个 commit 的固定标记，发布版本用它。**tag 不会随分支移动** |
| PR / MR | Pull / Merge Request | 代码评审与合入的入口，CI 的天然触发点 |
| 分支模型 | branching model | Git Flow（分支多流程重）vs trunk-based（主干短分支）。团队节奏决定选哪个 |
| HEAD / detached HEAD | — | 当前位置的指针。detached 是「站在历史提交上」，改东西前先建分支 |
| .gitignore | — | 不进版本库的清单。密钥和构建产物必须在第一次提交前就写进去 |
| 回退三兄弟 | reset / revert / checkout | revert 造反向提交（公共分支用）、reset 搬指针（私有分支用）、checkout/restore 恢复文件 |

## 002 Jenkins 与流水线

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| controller / agent | — | Jenkins 的调度中心与执行节点。构建任务派给 agent 跑，controller 别干重活 |
| node | node | 一台注册进 Jenkins 的机器（含 controller 自身） |
| job / 构建 | job / build | 一个自动化任务的定义与一次执行。构建号是排查时的第一索引 |
| Jenkinsfile | Jenkinsfile | 流水线即代码：随仓库走、可评审、可回滚 |
| 声明式流水线 | declarative pipeline | `pipeline { stages { … } }` 的结构化写法。**新项目一律用它**，脚本式只做读旧代码 |
| stage / step | — | stage 是逻辑阶段（构建/测试/部署），step 是具体一步。失败定位到 stage |
| agent 段 | — | 这条流水线/阶段在哪跑：`any`、`label`、`docker{}` 容器内执行 |
| 凭据 | credentials | Jenkins 托管的密钥与密码，`withCredentials` 注入。**日志里要掩码，明文是事故** |
| webhook | — | Git 服务在 push/merge 时主动通知 Jenkins 触发构建。比轮询快且省 |
| 环境隔离 | workspace 隔离 | 每个 job 独立工作空间；容器化构建是更强的隔离方式 |

## 003 GitLab CI 对照

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| .gitlab-ci.yml | — | 仓库根目录的流水线定义。GitLab 自带 CI，不用额外搭构建服务器 |
| Runner | runner | 执行 job 的进程。shared / specific / 自建，executor 决定在什么环境跑 |
| executor | — | shell（直接跑）/ docker（容器里跑）/ kubernetes。**生产建议 docker**，环境干净 |
| stages / jobs | — | 全局阶段顺序 + 各阶段的并发任务。同 stage 并行、跨 stage 串行 |
| cache | cache | 给下一次构建提速的目录缓存（依赖包），**不保证存在**，丢了要能重建 |
| artifacts | artifacts | job 的产物，传回 GitLab 供下载或传给下游 job，**这是交付物** |
| rules / only / except | — | 什么分支、什么事件触发什么 job。新语法用 `rules` |
| include | include | 复用流水线模板，多项目统一门禁的抓手 |

## 004 Ansible 批量配置

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| Ansible | Ansible | 无 agent 的批量配置工具：SSH 过去执行模块，完事不留痕 |
| 控制节点 / 被管节点 | control / managed node | 跑 ansible 的机器 / 被管的机器。被管端只要 Python 和 SSH |
| inventory | inventory | 主机清单：IP、分组、连接变量。INI 或 YAML，生产按业务分 group |
| ad-hoc | ad-hoc | `ansible all -m ping` 一条命令直接跑模块，适合临时取证与小操作 |
| playbook | playbook | YAML 写的多任务剧本，幂等可重复执行 |
| module | module | 幂等的最小执行单元：copy / systemd / apt / lineinfile。能用模块就别 shell |
| 幂等 | idempotent | 跑一次和跑十次结果一样。模块天然幂等，`shell` 模块要自己保证 |
| become | become | 提权执行（默认 sudo）。生产账号按最小权限走 |
| facts | facts | 执行前采集的机器信息（IP、内存、系统版本），模板里直接引用 |

## 005 Ansible 工程化

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| role | role | playbook 的组件化封装：tasks/vars/templates/handlers 按目录约定组装 |
| 变量优先级 | variable precedence | extra vars > play vars > host_vars > group_vars > role defaults……**同名的坑全在这** |
| Jinja2 模板 | template | `.j2` 模板 + 变量渲染出配置文件，`template` 模块下发 |
| handler | handler | 被通知才执行的任务：改了配置才 reload。**没被 notify 就不跑** |
| tag | tag | 给 task 贴标签，`--tags` 只跑一部分 |
| check mode | `--check` | 演练模式：只报告会改什么，不真改。**生产变更前必跑** |
| Ansible Vault | vault | 加密变量文件，密码进 Git 的唯一合规姿势 |
| 收敛 | convergence | 反复执行到稳定态。playbook 是否幂等，连跑两遍 diff 为空才算合格 |

## 006 制品与镜像仓库

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 制品库 | artifact repository | 构建产物的统一存放与分发点。没有它，制品散落在各构建机的 workspace 里 |
| Nexus | Sonatype Nexus | 通用制品库：jar / tar / rpm / npm 一个库管全 |
| Harbor | Harbor | 容器镜像专用库：带扫描、签名、复制。镜像制品的首选 |
| tag 策略 | tagging | 版本怎么打：语义化版本 + 构建号。**latest 是漂移指针，生产禁用** |
| 不可变 tag | immutable tag | 同一个 tag 内容永不覆盖。可追溯回滚的前提 |
| 保留策略 | retention | 旧制品自动清理的规则。不配它，存储迟早被构建历史吃满 |
| 晋级 | promotion | 同一制品从 dev 库晋级到 prod 库，而不是重新构建一遍 |

## 007 发布策略与回滚

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 滚动发布 | rolling update | 一台一台替换，省资源。新旧版本短暂共存，要兼容同一套接口 |
| 蓝绿发布 | blue-green | 两套环境整切，回滚=切回。资源翻倍，数据库要双向兼容 |
| 灰度 / 金丝雀 | canary | 小比例流量先上新版，观察指标再放量。接「接入层」的权重路由 |
| 回滚 | rollback | 退回上一版制品 + 退配置。**预案没演练过等于没有** |
| 停机窗口 | maintenance window | 允许中断的时间段。有它才能做不兼容变更 |
| 数据库先行 | expand-contract | 先加字段兼容旧代码，后删旧字段——发布顺序错=线上事故 |
| 配置与代码分离 | — | 制品在各环境不变，变的只有配置。改环境=改配置不是重新构建 |

## 008 流水线实战

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 触发链 | trigger chain | push → webhook → 构建 → 镜像 → 部署 → 通知，全自动或分段审批 |
| 参数化构建 | parameterized build | 发布到哪个环境、用哪个版本，构建时人选括号里填 |
| 并行阶段 | parallel stages | 测试与扫描并行跑，缩短总时长 |
| 人工审批 | manual approval | `input` 步骤卡住流水线等人点确认，上线前最后一道门 |
| 发布通知 | notification | 成败都发到 IM 群。**静默的成功比失败更可怕** |
| 全链路版本号 | versioning | 从 commit 到镜像 tag 到部署记录用同一版本号，出事一查到底 |

## 009 排错与自测

| 术语 | 英文 | 一句话 |
| --- | --- | --- |
| 构建可重现 | reproducible build | 同一 commit 在任何时候构建出等价制品。依赖锁版本是前提 |
| 凭据泄漏 | credential leak | 密钥出现在日志、镜像层、Git 历史里。事后轮换是唯一解 |
| 幂等破坏 | — | playbook 连跑结果不同：shell 里写了时间戳、curl 覆盖文件 |
| 环境不一致 | env drift | staging 过了 prod 挂了：先 diff 配置与版本，别急着看代码 |
| 流水线自我监控 | — | 构建成功率、时长趋势也进监控——流水线是生产系统的一部分 |

## 缩写速查

| 缩写 | 全称 | 意思与出处 |
| --- | --- | --- |
| CI / CD | Continuous Integration / Delivery(Deployment) | 持续集成 / 持续交付（部署）（000） |
| LTS | Long Term Support | 长期支持版本，Jenkins 与 GitLab 都按它选型（002） |
| MR / PR | Merge / Pull Request | 评审合入入口（001） |
| RBAC | Role-Based Access Control | 基于角色的权限，GitLab/Jenkins/Harbor 都用它（002 / 006） |
| SCM | Source Code Management | 源码管理，Jenkins 里的 Git 配置段就叫它（002） |
| SSO | Single Sign-On | 单点登录，内部工具统一认证（002 注记） |
| VAULT | HashiCorp Vault | 密钥管理系统，Ansible Vault 是其简化同名词（005） |
| YAML | YAML Ain't Markup Language | 一切流水线与清单的格式（全册） |

## 最容易混的 14 对

| 容器易混 | 一句话差别 | 怎么确认 | 册 |
| --- | --- | --- | --- |
| merge vs rebase | 保留分叉史 / 改写线性史 | 公共分支上有没有别人的提交：有就禁 rebase | 001 |
| reset vs revert | 搬走历史 / 追加反向提交 | 分支推过远端就只能 revert | 001 |
| tag vs branch | 固定标记 / 可移动指针 | `git log --oneline --decorate` 看指向 | 001 |
| 持续交付 vs 持续部署 | 到可上线为止 / 自动上到底 | 有没有人工上线按钮 | 000 |
| 声明式 vs 脚本式 Jenkinsfile | 结构化 pipeline 块 / Groovy 随手写 | 文件开头是不是 `pipeline {` | 002 |
| artifacts vs cache | 交付物 / 提速缓存 | cache 丢了要能重建，artifacts 丢了是事故 | 003 |
| webhook vs 轮询 | 事件通知 / 定时去问 | 构建是不是 push 后秒触发 | 002 |
| playbook vs role | 一场戏 / 一个可复用的剧组 | 目录里有没有 tasks/ 和 defaults/ | 005 |
| host_vars vs group_vars | 单机变量 / 分组变量 | 同名时 host 覆盖 group | 005 |
| check mode vs dry-run | Ansible 官方演练 / 各工具口语 | `--check` 输出 changed 但没真改 | 005 |
| Nexus vs Harbor | 万能制品库 / 镜像专用库 | 放不放 OCI 镜像、要不要扫描签名 | 006 |
| 滚动 vs 蓝绿 | 一台台换 / 两套整切 | 回滚是 undo 还是切回旧环境 | 007 |
| 蓝绿 vs 灰度 | 全量切 / 按比例放量 | 流量能不能只给 5% | 007 |
| 持续集成 vs 自动化测试 | 提交触发的流水线 / 流水线里的一段 | 测试红了流水线红不红 | 000 / 008 |

## 按症状反查

| 现象 | 大概是 | 去哪 |
| --- | --- | --- |
| 流水线绿了，线上没更新 | 部署阶段发错环境 / tag 不是刚构建的 | 008 §8.x / 006 |
| `git push` 被拒 | 保护分支 / 落后远端要先 pull | 001 |
| merge 后历史一团乱 | 在公共分支上 rebase 过 | 001 |
| Jenkins 构建日志里出现明文密码 | echo 了凭据变量 | 002 §2.x，事后立即轮换 |
| webhook 不触发构建 | Git 服务到 Jenkins 网络不通 / token 失效 | 002 |
| Runner 一直不接活 | token 失效 / 并发上限 / tag 不匹配 | 003 |
| 构建忽快忽慢 | cache 命中不稳定 / agent 排队 | 003 |
| Ansible 跑了但配置没变 | 变量被更高优先级覆盖 / 条件跳过 | 005 |
| playbook 二次执行就失败 | shell 模块里写了非幂等命令 | 004 / 005 |
| Vault 文件拉下来是密文 | 没 `--ask-vault-pass` | 005 |
| 镜像 tag 一样的两份内容 | 用了 latest / 可变 tag 被覆盖 | 006 |
| 制品库磁盘暴涨 | 没配保留策略 | 006 |
| 回滚后数据库报错 | 回滚了代码没考虑数据库兼容 | 007 |
| 灰度 5% 后指标劣化 | 别急着全量，先看是版本问题还是比例问题 | 007 / 接入层 |
| staging 过了 prod 挂了 | 环境漂移：diff 配置与制品版本 | 009 |
| 构建机磁盘满 | workspace 没清 / 旧构建堆积 | 009 |
